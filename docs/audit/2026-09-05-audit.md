**P1-2 · `hook-shared.mjs` is a hook-layer module that two `lib/` cores and the MCP server depend on (carried from 2026-09-02 P2-9)**
- Evidence: `lib/lesson-bridge.mjs:5` imports `callLLM`; `lib/startup-dashboard.mjs:11` imports `isAdoptedHere, HANDOFF_EXPIRY_EXIT`; `server.mjs` imports it too (dependency section, `docs/ARCHITECTURE.md §3`). `hook-shared.mjs:4-23` itself imports `haiku-client`, `schema`, `memdir`, `claudemd`, `adopt-content` — so a `lib/` module pulling one constant loads the whole hook constellation. - Impact: the “lib/ does not depend on the hook layer” rule is true only by exception; `lib/startup-dashboard.mjs` cannot be unit-tested without the hook-layer import graph.

- Size: ~40-60 LOC across `hook-shared.mjs`, 2 new lib files, 2 lib importers, 1 test, plus `source-files.mjs` + `package.json#files` registration (the twice-shipped-broken-tarball rule). Risk: low-medium — import surface; the existing 5,831-case suite covers the callers.

**P2-2 · `db.prepare()` inside loops on two hot paths**
- Evidence: `search-engine.mjs:510` and `:530` prepare `SELECT … FROM observations WHERE id = ?` once per vector hit, inside `for (const vr of vecResults)`; `vecResults` is bounded by `VECTOR_SCAN_LIMIT` = 500 (`tfidf.mjs:21`). `scripts/user-prompt-search.js:421` prepares the file-recall query once per file named in the prompt. `hook-llm.mjs:490,497` (≤5 iterations) and 24 more sites are in one-shot migrations/maintenance and do not matter. `better-sqlite3` does not cache statements — each `prepare` recompiles.
- Impact: up to 500 compilations per hybrid search; measurable only on vector-heavy corpora, but it is the retrieval path.
- Proposal: hoist the statement above the loop (`const byId = db.prepare(...)`) at the three sites; optionally one `WHERE id IN (…)` for `search-engine.mjs`.
- Size: ≤10 LOC per site. Risk: low. Verify with `node benchmark/denoise-ab.mjs --save/--compare` (must read NEUTRAL) — results are order-identical by construction.

> **执行记录 (2026-09-05, 分支 `audit/2026-09-05-round2`, 第 2 项)**
> - 改动文件：`search-engine.mjs`（两个分支的 `db.prepare(SELECT ${VEC_HIT_OBS_COLS} …)` 上提为分支前的一条 `vecHitObs`——两个分支互斥，一条语句同时服务两边，因此是 −1 条语句而非 +1 个变量）；`scripts/user-prompt-search.js`（`searchByFile` 的整条 SQL 上提到 `for` 之外，`fileMatchParams(file)` 是绑定值不是 SQL，故循环不变）；`tests/vector-fieldset-r3.test.mjs`（原守卫断言“两条相同 SELECT”= `toBe(2)`，上提后只剩一条，改为断言“恰好一条共享语句 + 两个分支都经由它 + 循环内无 `db.prepare`”）。
> - 验证方式：守卫做了变异验证（doctrine rule 5）——把 `prepare` 放回循环 → 第 35 行失败（expected 2 to be 1）；把一个分支换成字面列清单 → 第 38 行失败（expected 1 to be 2）+ 行为孪生用例同时失败；还原后 5 passed。`node benchmark/denoise-ab.mjs --save`（**在 `git stash` 后的改动前树上**）→ `--compare`（改动后树），两臂背靠背同一语料（doctrine rule 2）。`npx vitest run`；`npx eslint .`；`npx vitest run tests/user-prompt-search.test.mjs`。
> - 结果：denoise-ab **VERDICT: NEUTRAL**，三个 suite 的 ΔR@10 / ΔP@10 / ΔnDCG / ΔMRR 全为 0.000，行为探针 cross-source 11/11、deferred 10/10、events-pipeline 9/9 全过；测试 351 文件 / 5831 passed | 1 skipped；eslint exit 0；`user-prompt-search.test.mjs` 131 passed。
> - 说明（doctrine rule 9）：denoise-ab 只驱动 `search-engine.mjs`，**看不到** `scripts/user-prompt-search.js` 那一处；该处的证据是 131 例的 `user-prompt-search.test.mjs` 与“SQL 文本循环不变”这一结构事实，不是 denoise-ab 的 Δ=0。

## 明确不建议做

- **Splitting `install.mjs:doctor` (547) or `schema.mjs:initSchema` (475).** Both are linear, once-per-run scripts; `doctor` deliberately shadows `ok/warn/fail/log` to make `--json` work (`eslint.config.mjs` comment) and `initSchema` is the migration ledger. Splitting buys files, not guarantees.
- **Bulk-annotating the 127 empty catches** — declined once with reasoning that still holds; rubber-stamp comments are not error handling.
- **Merging the two UserPromptSubmit processes without telemetry numbers** (P1-4).
- **Re-layering `lib/` under `engine`.** The 11 `lib → engine` edges are shared cores fronting their engines (`docs/ARCHITECTURE.md §2`); “fixing” them means inverting a design `CLAUDE.md` states on purpose.
- **Bumping `better-sqlite3` or `vitest` majors inside an audit-fix release.**
- **Adding `install.mjs` / `server.mjs` / `hook.mjs` to the coverage gate.** Measured 2026-09-03 at 11.67% / 25.89% statements in-process; they are exercised by subprocess E2E that v8 cannot see (`vitest.config.mjs` comment). Including them measures the harness.
- **Cleaning the 51 knip exports as a batch.** The intentional category (`utils.mjs` v2.21 re-exports, test-only exports) is documented in `CLAUDE.md`; treat NEW names as review signal only.
- **Reformatting the tree as part of any other change** (P1-3 option (a) must be its own commit).
