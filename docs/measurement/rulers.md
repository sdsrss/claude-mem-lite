## Denoising A/B

- **Denoising A/B** (evaluate any precision/recall lever BEFORE shipping): `node benchmark/denoise-ab.mjs --save before.json` (control) → apply the change → `node benchmark/denoise-ab.mjs --compare before.json` (verdict). Runs the precision hard-negative, vocab-mismatch paraphrase, AND cjk_mixed suites so a lever's precision gain and recall cost are weighed on one screen — the split that let an OR-BM25 floor ship-then-revert (2026-06-29). Behavioral probes ride the same screen (multiscript guard + cross-source direction + deferred reachability + events end-to-end pipeline); any probe failure overrides the verdict to PROBE-FAIL and exits 1 — "A/B NEUTRAL ≠ safe" on faces the metric suites can't see. Verdict: REJECT / TRADEOFF / NET-POSITIVE / NEUTRAL / PROBE-FAIL.


## error-recall LIVE replay

- **error-recall LIVE replay** (`node benchmark/error-recall-live-replay.mjs [--dump f.json] [--shapes f.json]`): the ruler that closed D#167, and the one to reach for FIRST on this face. No fixture at all — inputs are real failing commands with their real stderr read out of `~/.claude/projects/**/*.jsonl` and filtered through the surface's own `detectBashSignificance().isHardError`; corpus is the live DB, every project with ≥20 rows. Reports the share of injected rows that match NO error term (i.e. admitted on command vocabulary alone) and the share of cases where such a row is TOP-1. **A/B it by flipping `CLAUDE_MEM_ERROR_RECALL_RERANK=off`, not by editing it**, and pass the same `--shapes` file to both arms — the transcript sample grows every session, so a re-extraction between arms silently changes the denominator. It carries a self-check that the membership predicate can return FALSE, because the first version of it could not (see the FTS5 note below) and reported the defect as 0.0%.

## episode-flush LIVE replay

- **episode-flush LIVE replay** (`node benchmark/episode-flush-replay.mjs [--since ISO] [--project p] [--json]`): the ruler for D#178 and the only thing that can price a change to the episode flush path. No fixture: it replays every real tool call in `~/.claude/projects/**.jsonl` through the **shipped** batcher (`isRelatedToEpisode` / `EPISODE_BUFFER_SIZE` / `EPISODE_TIME_GAP_MS` / `planEpisodeFlush` / `explainSignificance` / `buildImmediateObservation` / the two write-side noise gates), so the flush decisions cannot drift from production. **Its middle self-check is the one that matters**: the live `episode_significance` metric rows measure the same share the replay models, and the two must agree within 15pp or the run exits 1 (measured 2026-08-25: meter 40.7% insignificant over n=938, replay 37.1% over n=1305, gap 3.6pp). It reports SKIP — not PASS — on a machine that never set `CLAUDE_MEM_METRICS=1`, because there the flush model is unchecked. Known under-count, in one direction: `<session>/subagents/*.jsonl` is one level below the walk, so tool calls made inside a dispatched agent — which do fire PostToolUse and do append to the same reads file — are missing. **Correct a premise before quoting it**: D#178 was filed saying ~92–96% of flushes are insignificant; the meter says **40.7%** (n=938 over 3 active days). Standing result (2026-08-25, 1122 transcripts, 3819 flushes, 1627 distinct reads consumed): **42.2% of the Read paths a flush consumed are destroyed by an insignificant flush**, 72.7% of significant flushes carry no reads at all, and the fix delivers ×1.68 more (72.7% → 66.1% empty). Staleness is **per delivering flush and of the OLDEST read in each** — median 1.7m, p90 10.1m — so it overstates the typical read's wait and understates nothing. Observation-level, past the two write-side gates and NOT modelling DB dedup (so an upper bound): 10 → 17 of 47 landed rows carry a read. **The delivery multiple is a UNION, not a sum**: production collects with `new Set(...)`, so a path read in two carried-over windows is delivered once; summing per-flush counts published a figure 2.9% high until both pre-tag reviews caught it independently.

## error-recall calibration

- **error-recall calibration** (`node benchmark/error-recall-suite.mjs [--scores|--sweep|--compare]`): denoise-ab **structurally cannot see the error-recall face** — its suites are query→document, while that face's input is a failed command plus its stderr, so a lever there reads NEUTRAL Δ=0 no matter what it does. This is its ruler. `--sweep` is the one to calibrate against: a floor only affects rows that reach the injection cap, so the `--scores` distribution overstates the achievable gain. **Four invariants the suite enforces on itself, each one earned:** (1) every case must pass the real `detectBashSignificance().isHardError` — a case that cannot fire measures a path that does not exist (#10731); (2) the fixture must carry enough filler to keep FTS5's IDF non-degenerate (a small all-one-topic corpus scores every row 0.00, and any floor then removes everything); (3) `--scores` must probe at `floor: 0` and self-checks that it can see below the calibrated value — it once inherited the shipped default and reported the post-gate remnant as the population, making the calibration table unreproducible from its own tool; (4) cases are split into **servable** (the corpus can explain the failure → judged on hit-rate) and **unservable** (it cannot → judged on staying quiet), because with only servable cases present a set-level gate scores identically at every threshold and reads as a no-op. **Standing result (v3.78.0): the |bm25| floor is built, calibrated at 10.5, and OFF by default.** Measured on the live DB at that threshold (8 projects × 9 shapes, 69 firing cases): floor off = 201 injected rows; **set-level = 126 (−37%), 39% of firings silenced**; per-row = 97 (−52%), 38% silenced. Loss concentrates in projects under ~500 observations, which `corpusFloorScale` is documented not to see (it normalises over the whole table, correct for IDF, deliberately project-blind). **The fixture reports the set-level form as a no-op and is wrong** — its hard negatives are constructed to score above 10.5, so it cannot see this cost; two review rounds each caught one level of this same "fixture number standing in for a live one" error. Command words dominating BM25 is a semantic defect and no magnitude gate reaches it → D#167. **D#167 is now closed, and it was filed against the wrong culprit.** Measured over 52 real failing commands (real stderr, pulled from 1110 transcripts, filtered through the real `isHardError`) replayed across 15 live projects: 28 of the 52 name their failure (`ModuleNotFoundError`/`ENOENT`/`JSONDecodeError`) and **25 of those 28 (89.3%) never got that name into the query** — the six-term budget went to the Python banner `traceback,most,recent` and to path fragments (`mnt,data_ssd,dev`). Downstream, 39.2% of injected rows and **42.3% of TOP-1 rows** (the row inlined verbatim into context) matched no error term at all. Two independent defects, and **fixing terms alone does not touch injection**: naming the failure moved cmd-only rows 39.2% → 40.2% (more specific terms match fewer rows, leaving the flat OR *more* room to fill slots with command vocabulary). Shipped: `ERROR_NAMER_RE` (positive pattern for the signal, never a boilerplate stop-list — that enumerates forever) + an error-first rerank that **reorders and never removes** → 22.4% rows / 21.5% top-1, row count unchanged; suite precision 23.1%→34.6%, hit-rate 85.7%→100%. The mandatory-error-term form was rejected on the same sample (−22.4% rows, 21.5% of cases injecting nothing, concentrated in small projects — the floor's failure mode relocated). **Two ruler defects worth remembering:** (1) `SELECT 1 FROM observations_fts WHERE rowid = ? AND fts MATCH ?` **silently drops the rowid constraint** on SQLite 3.53.1 — it is an always-true membership test, and it reported the defect as 0.0%; pull each term's rowid set instead. (2) `ERROR_NAMER_MAX` shipped at 2 on an argument (chained tracebacks) and swept to 1 on data. Residual: the cap evicts the *last* term, which is often the most specific one (a filename lost to a class name) — **that was D#169, and it was built, measured and rejected**: an identifier-first cap (`[._-]`) moved cmd-only rows 22.6% → 35.8% and top-1 21.3% → 33.4% on the live DB, because `[._-]` conflates "discriminative" with "unique to this invocation" — it promotes this run's own filenames (IDF so high they match nothing) and evicts `enoent`/`syscall`, which are exactly what the explaining memories contain. Any retry needs real document frequencies, and `planErrorRecall` is pure with no corpus to count. The negative result lives in the cap's docblock in `bash-utils.mjs`.

Standing verdict: mechanism confirmed, cite-rate benefit **not demonstrated and not refuted**.


## rerank-pool LIVE replay

Now: arm B runs FIRST with `{ counterfactual: true }` (skips both the bump and the metric emission), so both arms see one state by ordering rather than isolation, and arm B carries its OWN imperative pick instead of arm A's. `tests/patha-meter-counterfactual.test.mjs` pins the behaviour AND the wiring — including source-position ordering, because the flag with the wrong order leaves the delta defect intact; six mutations, six kills. **`suppressed` is exact, not estimated** — arm A's exclude is inert, so its result IS the unexcluded search, and intersecting it with the coerced marker names precisely the rows a working exclude would drop. **The column that decides D#216 is `refilled`, not `suppressed`**: the ledger's open question is whether a freed slot gets refilled from the pool or is simply lost, and a suppression count alone cannot answer it. `net` is reported beside `setChanged` because a one-for-one replacement is net zero while the delivered SET moved — a net-only reading would call that "no change". **Isolation:** coerced ids are ADDED to `contextExclude` rather than replacing it, so the Key Context half (a different mechanism with its own history) is byte-identical in both arms. **`inert` is per PROMPT and keyed on the right predicate** — a prompt's exclude is inert when an id it COULD have matched arrives as a string, not merely when some string is present. The looser rule shipped in a draft on the premise that only a PreToolUse emission turns the union into strings; **that premise is false and the counterexample is the writer itself** — `scripts/user-prompt-search.js` emits `P<id>` (prompt corpus) and `D<id>` (deferred) on its own legs, and the deferred leg merges `prevIds.map(String)`, stringifying whatever was already in the file with no tool call involved. Under the loose rule a marker of nothing but those namespaces read as `inert: true` with `markerCoercible: 0` — a prompt with nothing excludable, counted into the inert population, which is the denominator inflation the column exists to prevent, running backwards. Caught by the v3.90.0 pre-tag claims review; `inertMarkerIds` is now the predicate and `markerCoercibleStrings` is reported beside it. `task_imperative` records `imperativeArm: 'off'` on a stock install rather than being omitted, since it is behind `CLAUDE_MEM_TASK_IMPERATIVE`. **Cost is gated twice**: `recordPathAExclude` re-checks the env, but the check at the call site is load-bearing because arm B of the imperative face is an eagerly-evaluated argument. `tests/patha-exclude-meter.test.mjs` drives every guarantee to fail; **one mutation SURVIVED that round and it was the code that was wrong** — an explicit `/^E/` skip for namespaced event ids was unreachable behind the `Number.isInteger` gate that follows it, so it was deleted rather than given a test (the D#197 precedent). No corpus yet: this ships with the meter built and the decision still open.

## hook entry-point latency

- **hook entry-point latency** (`node benchmark/hook-latency.mjs [-n 15] [--db <path>] [--json] [--keep]`): the only ruler here for what the product COSTS rather than what it RETURNS. Every other entry measures retrieval quality; none of them can see the per-tool-call price, which is paid whether or not a single memory comes back, because Claude Code spawns a fresh Node process per hook fire. **It is a latency ruler and says nothing about quality** — a change that halves the hook and destroys recall reads as a win here, so pair it with `denoise-ab` for anything touching retrieval. Two arms make the rest readable: `node -e ''` is the FLOOR (Node's own boot, which no change to this repo can move — quoting the raw column credits ~17ms of V8 start to the code under test), and `hook.mjs` with **no event argument** loads the entire top-level import graph and then matches no `case`, giving the import cost with the work subtracted. That second arm depends on the dispatcher's switch falling through; a future `default:` that does work silently turns it into something else. **Standing read (2026-09-14, `converge/20260914-setup-sh-runtime-dir` @ `06386ed`, Node v26.8.1, empty sandbox DB, n=15, min column, ms): floor 16.4 · hook.mjs imports-only 73.6 (+57.2) · post-tool-use Edit 83.6 (+67.2, of which the work is 10.0) · post-tool-use.sh Read 5.1 and Glob 4.2 (never start Node, so the Node floor is not theirs and the report refuses to print them a delta) · pre-tool-recall.js 32.8 (+16.4) · user-prompt-search.js 46.5 (+30.1) · session-start 99.1 (+82.8).** The shape: on the hottest path **~85% of this repo's own per-tool-call cost is loading modules, not doing the work**. The largest single item is the DB graph (`hook-shared.mjs` → `schema.mjs` → better-sqlite3's native addon; ~30ms marginal inside hook.mjs's graph, ~38ms in isolation), which a typical PostToolUse never uses — it appends to a JSON buffer and opens no database. **Deferring it is not a small change and was not attempted**: `openDb` is synchronous by contract at 15 call sites including a signal handler, and a dynamic import makes it async. The rest of the graph is ~16ms spread over ~30 modules, so there is no third option that is both large and small-diff. **Three self-checks, and the second one fired on this file's own first run.** (1) Every arm must exit 0 — a hook that crashes on bad input is FAST, and a crash would otherwise be published as an improvement. (2) The post-tool-use arm must leave an `ep-*.json` behind in the sandbox: without that premise a no-op (disabled plugin, mis-set env, changed stdin shape) reports the bare import cost wearing a "did the work" label, which is the one error this ruler could make that looks exactly like a win. (3) The floor must come in measurably under the hook arm, or the run is timing spawn noise. **The failure that check caught was in the RULER, not the product, and the fix is a caliber rule worth keeping: the premise must be sampled where it is true.** The buffer was read after all arms had run, and the `session-start` arm is a real SessionStart — its first spawn finds the leftover buffer, flushes it and unlinks it. A correctly-buffering hook therefore reported "never buffered". It is now sampled immediately after the arm that writes it, and the same ordering is why `session-start`'s `min` is its steady-state (no-leftover) cost. **Pollution (rule 6):** HOME and `CLAUDE_MEM_DIR` are a fresh `mkdtemp` tree, every `CLAUDE_MEM_SKIP_*` flag is set so no detached worker outlives the run, `MEM_NO_AUTO_ADOPT=1` so it cannot rewrite a CLAUDE.md, and the tree is removed on exit behind a path check that re-validates the temp root and this ruler's own prefix. `--db` COPIES a database in rather than opening one in place; say which corpus a number came from, since empty and seeded are different populations.
