## Report: v6.33.0 pre-release defect review (0d9c9912 against v6.32.0)

HEAD was 0d9c9912. Line numbers refer to the 0d9c9912 tree. Probe scripts are under /home/ai/.cache/tmp/rv-6330-defects/probes/. They read `$D/cand` and `$D/base`, which are deleted now; rebuild them with the brief's `git archive` + `cp -a node_modules` lines before rerunning.

### Findings
**F1 (P2, regression). After `/compact`, the previous session's summary can carry the next session's reply.**
- What happens: `previousTranscriptPath` (hook.mjs:2442) returns the same transcript after `/compact`. The worker is spawned with no epoch, so nothing supersedes it (hook.mjs:2512). It waits for every young flush file (hook-llm.mjs:1850), then takes the last assistant text in the whole file (hook-llm.mjs:1890).
- Why the wait is normal: SessionStart flushes the leftover episode before it spawns the worker.
- Repro: `PENDING_FLUSH=1 FLUSH_TIMEOUT=12 probes/summary/clear-compact.sh {cand,base} compact 5`. A post-compact reply is appended 5 s after SessionStart.
- Output, cand: `Final reply:\nPOST-COMPACT INTERIM TEXT: let me now delete the old migration files`. Output, base: no Final reply section. The system prompt tells the model this reply's outcome wins.
- How often: this machine's 150 newest transcripts (2026-11-11, `probes/summary/compact-delay.mjs`) hold 27 compactions. 2 of the 22 manual ones had a reply within 25 s (3.9 s and 23.4 s). Auto compactions took 89 s or more.

**F2 (P2, regression). The word-form tier adds rows to a search that already had results, and ranks them first.**
- Cause: the gate at search-engine.mjs:687 looks at observations only. lib/search-core.mjs:826 then merges them with the other sources.
- Repro: save two observations containing "crash", and `activity save` an event containing "crashes". Then run `search crashes`.
- Output: base returns `Found 1 result` (E#1). Cand returns `Found 3 results`, with obs #2 ("crash") above E#1, the exact match.
- Prose this contradicts: CHANGELOG.md:45 ("A search that finds nothing…") and the comment at search-engine.mjs:681-686 ("cannot reorder one that had any").

**F3 (P3, regression). On a re-run, purge prints "Done!" while `runtime/` is still there.**
- Repro: a relocated directory holding only product files plus `.DS_Store` (`probes/purge/s10-dsstore.sh`). The first run exits 1 with `Left runtime … Remove it yourself`, and has already removed the store. The second run says `has no claude-mem-lite.db — left untouched`, prints `Done!`, exits 0, and `runtime/sub/x` is still there.
- Cause: install.mjs:2231-2234 removes the store even when `left` is non-empty. That is the shape of R33 M2, which the code comment says was closed for failed entries only.
- Base: removes the whole directory.

**F4 (P3). From a fresh subdirectory, `save --project .` and plain `save` file into different projects.**
- With `--project .` the row goes to the git root's project, because mem-cli.mjs:4376 resolves it with `cliProject` (lib/cli-project.mjs:101). Plain `save` uses `inferProject` (mem-cli.mjs:1346).
- Output: `#4 … (project: projdot--repo)` and `#5 … (project: pkg--third)`. Base files `--project .` under a new project named ".".
- I found no case of a non-project argument being rewritten. `save -- "text mentions" --project . "as words"` was stored verbatim.

**F5 (P3, constructed). The summary worker hangs on a FIFO transcript and ignores SIGTERM.**
- Cause: `readFileSync` in lib/transcript-scan.mjs:104 blocks in `open()`, and the SIGTERM handler at hook.mjs:346 never gets to run.
- Repro: `TMO=25 probes/summary/worker-direct.sh cand fifo fifo`. The node process was still in `wait_for_partner` 188 s after `timeout 25`; I killed it with SIGKILL.
- Base: its Stop hook already reads the same path synchronously (hook.mjs:1417). The host always passes a regular file.
- Other inputs were fine: a 207 MB transcript took 634 ms; a directory or a missing path gives no reply and exit 0.

**F6 (P3, scrubber gap that predates the release; new channel).** Five token shapes pass `scrubSecrets` (secret-scrub.mjs:1743) unchanged: `hf_`, `dop_v1_`, `pypi-`, `shpat_` and `gsk_`. Base's scrubber leaks the same five. They now reach the summary model through `summaryReplyExcerpt` (hook-llm.mjs:1749). The other 16 shapes tested, and a secret that straddles the head/tail cut, were masked. Repro: `probes/summary/secret-scrub{,2}.mjs`.

**F7 (P3, regression). The word-form fallback costs time on long queries in which no word matches.**
- Scope: CLI and MCP search only; no hook calls `searchObservationsHybrid`. The MCP query has no length bound (tool-schemas.mjs:175).
- Timing on a 20k-row synthetic corpus, 4 interleaved runs per tree in ABBA order (CLI end to end, cand vs base): 3 words 92 vs 89 ms; 300 words 199 vs 98 ms; 2000 words 920 vs 144 ms.
- Nothing threw. The builder is linear: 100k-character words took 5 ms or less.

**F8 (P3, predates the release).** A row in a DST zone's repeated last hour of the day is shown as day D, but neither `--from D --to D` nor day D+1 finds it.
- Cause: lib/search-core.mjs:108 resolves that hour to its first occurrence.
- Where it shows: America/Santiago 2026-04-05T03:00–04:00Z, Africa/Cairo 2026-10-29T21–22Z and Asia/Beirut 2026-10-24T21–22Z, 12 of 105,694 instants each.
- Clean: 13 other zones, including +05:30, -09:30, +05:45, Lord_Howe and Chatham, had 0 misses. Pasting `localIsoTime` back as a date bound missed 0 everywhere. Exact local midnight and 23:59:59.999 missed 0.
- Base misses 11,076 to 32,376 instants per zone. Repro: `TZ=<zone> node probes/dates/display-vs-filter.mjs <tree>`.

**F9 (P2, predates the release; default purge, unchanged).** When `~/.claude-mem-lite` is a symlink to the real data directory, `rmSync` removes only the link (install.mjs:1978). The run prints `Data purged` and `Done!`, exits 0, and the store stays at the link target. Both trees behave the same (`s9-default-symlink.sh`).

**F10 (P3, constructed, predates the release).** In a relocated directory two things go that may not be claude-mem-lite's:
- `claude-mem.db` and its `-wal` are removed by name (install.mjs:2101). That is the pre-rename store name, and possibly the original claude-mem's store name; I did not verify the latter.
- A user's own `managed/` (or `runtime/`) goes whole when it is the only foreign entry (s11: `managed/infra/terraform.tfstate` deleted, `Done!`).

Base deleted the whole directory in both cases.

### No defect found
- **Q1, default purge:** identical in both trees (s8).
- **Q1, relocated purge (cand):**
  - User files and look-alikes were kept (s2, s3).
  - Symlinks were never followed (s4, s4b, s4c).
  - An unremovable entry gave exit 1 with the store kept (s6).
  - An unreadable directory gave exit 1 with nothing removed (s7).
  - With `CLAUDE_MEM_DIR=$HOME`, only product files went (s5; base deleted the whole of `$HOME`).
  - A store held open by a live MCP server behaved as base does.
  - Everything a full hook and CLI session wrote was recognised.
  - Base crashed on EACCES in s6 and s7.
- **Q3, `mem_defer_drop` / `defer drop`:** 27 input shapes. A duplicate or unknown id drops nothing (CLI `1,9` and `2,D#2` left 3 items open; `3,1` dropped D#3 and D#1).
- **Q4, schema:** cand adds the column when it opens a v6.32.0 store. v6.32.0 then writes observations and events into that store, and its doctor reports `DB schema: v49 — readable by all 1 install(s)`.

### Q7: mutation testing (run by a forked agent)
- Method: 37 single-line mutations, 22 on purge and 15 on the summary worker. Each was asserted applied, then restored and confirmed with `cmp`.
- Baselines: purge test set 113/113 passed; summary test set 301 passed, 1 skipped.
- Result: 34 killed, 3 survived:
  - **P04, install.mjs:2015:** `rmdirSync` changed to a recursive `rmSync`. This only matters in a race, but the line that protects a file written between the scan and the `rmdir` is not covered by any test.
  - **S13, hook.mjs:2448:** `ORDER BY prompt_number DESC` changed to `ASC`. This needs one session with two host ids, for example when `CLAUDE_PID` is missing.
  - **S14, hook.mjs:2454:** the `existsSync` guard removed. The behaviour is the same without it.
- No test appends to the transcript after `/compact` (F1).
