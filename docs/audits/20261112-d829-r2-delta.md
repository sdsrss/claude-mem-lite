## Pre-existing, not introduced or worsened by the delta (outside the counting rule; for the ledger)

### X1 · P1 shape · introduced: no (same at c79bd41e and v6.34.0 0103af50)
**When another process deletes or renames a file under ~/.claude-mem-lite during the purge, rmSync stops
partway and returns normally. The run prints "Data purged (~/.claude-mem-lite/)" and "Done!" and exits 0
with the store left. The new failure line is never reached.**
- Where: install.mjs:2006-2007 (`rmSync(DATA_DIR, {recursive, force})` then `ok('Data purged …')`).
- Mechanism, observed on Node 24.22.0 and 26.8.1: removal stops at the first entry that fails. When that
  entry's failure is ENOENT (it vanished between listing and unlink), rmSync treats it as "already gone"
  and returns without throwing. The rest of the tree stays: the store, plus 1.5k-2.6k entries in my
  fixture.
- Reproduce: `probes/churn.sh probes/h-churn-26 26 6`. A second process loops writeFileSync+unlinkSync of
  a temp file in ~/.claude-mem-lite/runtime/, a stand-in for atomic-write churn.
  ```
  == cd9e7c0f node 24
  run 1: Data purged (~/.claude-mem-lite/) Done! EXIT=0 | left=2556 db-left      (6/6 runs like this)
  == cd9e7c0f node 26
  run 1: Data purged (~/.claude-mem-lite/) Done! EXIT=0 | left=2173 db-left      (5/6; run 4 threw ENOTEMPTY → the new line, EXIT=1)
  == c79bd41e node 26: 2/3 runs "Data purged … Done! EXIT=0" with db left
  == v6.34.0  node 26: 1/3 runs "Data purged … Done! EXIT=0" with db left
  ```
  Direct rmSync probe (`probes/race2.mjs`, 20 runs per arm, tmpfile mode): NOTHROW with the directory and
  store left in 15/20 runs on Node 24 and 13/20 on Node 26. Control: a writer that only creates files, no
  deletes, left nothing and printed a true "Data purged … Done!" in 10/10 runs.
- How common: rare, and judged from the mechanism, not measured on real sessions. It needs a live
  claude-mem-lite process to delete or rename a file under ~/.claude-mem-lite inside the sub-second
  rmSync window. Candidates: the MCP server, which lives until Claude Code restarts; a spawnBackground
  child; a hook; SQLite removing a -wal/-journal on close. I did not check whether this is already a
  deferred item: a search would write telemetry to the real store.
