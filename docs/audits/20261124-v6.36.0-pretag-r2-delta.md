## Answers to the brief's questions

**Q1a: Does any spelling of `.` / `current` on the six commands still write under a `<config home>/projects/…` project?**
No, for every spelling I ran. Full-run differential, v6.35.6 vs candidate: 6 commands × 4 spellings
(`--project .`, `--project current`, `--project=.`, `--project=current`) × 20 directory/env scenarios
= 480 cases. In every state scenario the candidate exited 1 with the "per-project state" message
and left the DB at the seed's project set. The state scenarios were: the state dir, the
`projects/` root, `CLAUDE_PROJECT_DIR` pointing at the state dir, an empty `CLAUDE_PROJECT_DIR`,
`CLAUDE_CONFIG_DIR` pointing at an alternate config, a config home kept in git, and a stale `PWD`
naming the state dir. The probe arm also ran flag-first, after `--`, and repeated
(`--project . --project current`) forms. All of them are refused in state dirs; after `--` the
words stay literal text.
Paths around the refusal, none caused by this delta (see PE-2, PE-3): a symlinked config home
reached by its real path, and `--project <cwd's short name>`.

**Q1b: Does any `.` outside that state resolve differently from v6.35.6?**
No. Probe arm: an `RV_PROBE` early return logs the dispatcher's rewritten argv right after
`currentProjectSpelled`, in both trees. 22 command shapes (the 6 writes plus `search recent`,
`defer list/drop/update`, `activity recent/promote`, `compress optimize export stats timeline`,
plus 4 position variants) × 4 spellings × 20 scenarios = 1520 cases. Resolved argv was identical
in 1520/1520, and `refused` was true exactly for (six writes × state scenarios).
The scenarios include: work-tree root; subdirectory with no rows (→ `work--invoice-app`);
subdirectory with its own rows (→ `invoice-app--pkg`); non-git dir; `CLAUDE_PROJECT_DIR` unset,
set to the root, set to the subdirectory, or empty; stale `PWD` either way; the config home itself;
and the default state path with `CLAUDE_CONFIG_DIR` elsewhere.
The ruler can say no: the resolved names differ across scenarios as listed.
`lib/cli-project.mjs`, `project-utils.mjs`, `utils.mjs` and `lib/data-paths.mjs` are unchanged
since v6.35.6.
Full arm outside state: exit code and per-table project counts were identical to v6.35.6 in every case.

## Pre-existing (identical in v6.35.6; not introduced by this delta)

### PE-1 (P3, constructed): `.` resolving to a `-`-leading project name is re-read as a bare flag
- Where: mem-cli.mjs:4098-4108 together with cli/common.mjs:128-130.
- Cause: Claude Code state dirs name projects like `-tmp-work-invoice-app--memory`. The space form
  `--project .` is rewritten to `--project -tmp-…`, and parseArgs then treats `--project` as
  value-less.
- What happens in the state dir, on the candidate:
  - `recent --project .` → `Invalid count "-tmp-work-invoice-app--memory" … using default 10`, then
    `Recent (all):`, listing every project unfiltered.
  - `defer list --project .` → `No open deferred items in project "null".`
  - `search pnpm --project .` → exit 1 `--project requires a value`.
  - The `=` form works.
- v6.35.6 writes with the space form failed this same way. That is why only `--project=current`
  filed rows, which matches the CHANGELOG's example.
- The probe shows identical argv in both versions.

### PE-2 (P3, constructed): `--project <short name of the cwd>` from a state dir writes under the state project

### PE-3 (P3, constructed): a symlinked config home reached by its real path is not recognised
