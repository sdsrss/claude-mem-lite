### F2 (P2, security regression vs v6.30.14 in the class this release fixes; constructed shape) — a word joined to a token by an escaped `/` or `+`

CHANGELOG.md:5 (title) "values in JSON that two different encoders nested are erased again"; CHANGELOG.md:22 "**Still stored**:
the shapes 6.30.14 lists, and … (D#703)". The candidate stores values that both v6.30.14 and v6.30.13 erased. The value is a word
joined by PHP's `\/` (or .NET's `+`) to a token-shaped credential that a specific pattern erases (JWT, `ghp_`, `sk-`,
`xoxb-`). It sits on a line after credential lines, in PHP's JSON inside a JSON or .NET string. This is the same kind of value
D#701 counts (a value under a non-credential label that 6.30.13's run-on erased).

The cause is the new joined reading. At the inner level the token pattern erases only the token, leaving `***/<W>`. The decoded
body read `\/` as `/`, so the word there was `LABEL=<token>/<W>`. The rewritten literal's word `/<W>` is in neither set and is
kept. v6.30.14 split the body's word at the escape, so `<W>` was in its erase set.

Minimal repro probes/b701c.mjs (values assembled at run time; `o`/`p`/`c` = v6.30.13 / v6.30.14 / candidate; `W!` = W in output):

```

two colon labels, ghp in a URL path | php in JSON    J([php({content: env})])        o---- p---- cW!--
two colon labels, ghp in a URL path | php in .NET    dotnet({c: php({content: env})}) o--V! p---- cW!--
env = 'API_KEY: <V>\nCLIENT_SECRET: <V2>\nLOG_LEVEL=<JWT>/<W>\n'
two colon labels | php in JSON                                                       o---- p---- cW!--
two colon labels | php in .NET                                                       o--V! p---- cW!--
(Node 22: identical)
masked output, php in JSON:  cand ["{\"content\":\"API_KEY: *** ***\\nLOG_LEVEL=***/<W>\\***\"}"]
                             prev ["{\"content\":\"API_KEY: *** ***\\nLOG_LEVEL=******\\***\"}"]
```

On every capture path (probes/b701-import.mjs, probes/b701-hook.mjs):

### F8 (P3, comment wording) — "every escape that decodes to one character"

secret-scrub.mjs:1584-1585 "…are read with every escape that decodes to one character, at any depth, read as that character."
Only a backslash run followed by `/` or by `u` and four hex digits is read that way. `\n`, `\t`, `\"` and `\\` also decode to one
character and are read as written, as the block's own later "Every other escape is read as written" says. joinedReading's doc
comment and the 12b1bd30 message carry the defining parenthetical; the block comment does not. Also
tests/secret-scrub-escaped-literals.test.mjs:187 "An escape that decodes to one character joins words …: PHP's `\/`, and the
`\uXXXX` that .NET writes for `"`, `'` and `+` and Gson for `=` and `'`". `"` and `'` are not value-token characters and join
nothing; the code comment states the `"` effect correctly ("no longer sticks `u0022` onto the next word").
