### F1 [P2] Known limit（D#633）把触发条件写宽了：只满足所写的形状时，6.30.9 一行密钥也不存

句子（CHANGELOG.md:25-27）：
> **Known limit** (D#633): in an added diff line (`+`), a cut key under a BEGIN with text before it, whose next line is a header holding a second BEGIN (`+Comment: -----BEGIN …`), keeps key lines that 6.30.8 erased.

1. **光凭所写形状不漏**（probeD.mjs、probeD2.mjs）。输入是 `+KEY = '''<BEGIN>` / `+Comment: <BEGIN>`（第二个 BEGIN 在行尾）/ 正常密钥体逐行加 `+` / `Thanks.`，真实密钥 330 例（带或不带 `+Proc-Type`/`+DEK-Info` 头，3 种包装）：
   - "rc 存、base 擦"：0 例
   - "base 存、rc 擦"：165 例
   - 正常体 r1 风格单例：BASE `"+KEY = '''-----BEGIN RSA PRIVATE KEY-----\n+Comment: ***PEM_KEY***"`，RC `"+KEY = '''***PEM_KEY***"`，两边都存 0 行
2. **头行里的第二个 BEGIN 后面还有文字时，方向反过来**（`+Comment: -----BEGIN RSA PRIVATE KEY----- was here`）。
   - 正常体：6.30.8 存 330/330，6.30.9 存 0/330
   - r1 输入：base 存 3 行，rc 存 2 行（probeD3.mjs）
   - 也就是说，"a header holding a second BEGIN"里有一部分情况，6.30.9 反而比 6.30.8 存得少
3. **真正的回归还要两个句子没写的条件**：
   - (a) 第二个 BEGIN 位于头行行尾；
   - (b) 密钥行中间有一行去掉 `+` 后不是整行 key 行，比如 `+QWERTYUIOPasdfg`（`+` 后 15 位），或只有前缀的 `+Comment: `，而且它后面还有 key 行。
4. **在 r1 输入上复现成立**（probeD2.mjs）：
   ```
   IN   "+KEY = '''-----BEGIN RSA PRIVATE KEY-----\n+Comment: -----BEGIN RSA PRIVATE KEY-----\n+MIIEowIBAAKCAQEAu1SU1LfVLPHCozMxH2Mo4lgOEePzNm0tRgeLezV6ffAt0gun\n+QWERTYUIOPasdfg\n+VfLLGRHm…\n+hgsZH+ZH+…"
   BASE "+KEY = '''-----BEGIN RSA PRIVATE KEY-----\n+Comment: ***PEM_KEY***"            (存 0 行)
   RC   "+KEY = '''***PEM_KEY***\n+VfLLGRHm…\n+hgsZH+ZH+…"                            (存 2 行)
   ```
   把 `+QWERTYUIOPasdfg` 换成 `+Comment: `，结果同样是 base 0 行、rc 2 行。

**影响**：读者会以为：只要加行 diff 里，代码 BEGIN 下面有一行装着 BEGIN 的头行，6.30.9 就会漏出 6.30.8 不漏的密钥。而升级说明恰好告诉读者"Going back is pinning 6.30.8"。实际上，在正常密钥体上 6.30.9 不漏；第二个 BEGIN 后面有文字时，退回 6.30.8 漏得更多。

**建议修改**（把缺的条件补进去，不加限定词）：
> **Known limit** (D#633): in an added diff line (`+`), under a BEGIN with text before it whose next line is a header ending in a second BEGIN (`+Comment: -----BEGIN …`), a short or header line between the key's lines (`+QWERTYUIOPasdfg`, `+Comment: `) stops the reading, and the key lines after it are stored; 6.30.8 erased them.

### F2 [P2] D#615 把丢失写窄了：丢的不止"那一行的开头"，触发也不止"≥40"

句子（CHANGELOG.md:17-20）：
> **Below a BEGIN with text before it on a diff, Read, grep, quoted or list line, a line that starts with 40 or more letters, digits, `+`, `/` or `=` (a hex hash, a long path or identifier) loses that start even when it is not a key** (D#615), as 6.30.8 already did below a BEGIN with nothing before it.

所写方向成立：base 保留，rc 丢失（见"核对为真"T3）。但 rc 实际丢的范围比句子大（probeB2.mjs、probeB4.mjs）：

| # | 输入（`\n` 分行） | BASE（6.30.8） | RC（6.30.9） |
|---|---|---|---|
| 1 | `-KEY = '''<BEGIN>` / `-e83c…f290` / `-0a1b…4567` / `-95aa…cdef` / `-done` / `end of text`（`git rev-list` 式整行 hash 加一个短词） | 原样保留 | `"-KEY = '''***PEM_KEY***\nend of text"`：三行 hash 和 `-done` 整行丢失 |
| 2 | `-KEY = '''<BEGIN>` / `-loadPrivateKeyFromDiskAndValidateItsSignature` / `-TokenStore` / `-and the rest of the prose` / `end` | 原样保留 | `"-KEY = '''***PEM_KEY***\n-and the rest of the prose\nend"`：10 位标识符行也丢了 |
| 3 | `-KEY = '''<BEGIN>` / `-` / `-Version: 2` / `-e83c…f290 Fix` / `end` | 原样保留 | `"-KEY = '''***PEM_KEY*** Fix\nend"`：空行和像头的行一起丢 |
| 4 | `-KEY = '''<BEGIN>` / `-MIGRATIONSTATUSCHECKER` / `-and prose` / `end` | 原样保留 | `"-KEY = '''***PEM_KEY***\n-and prose\nend"`：22 位整行，以 key magic `MIG` 开头，不到 40 也丢 |
| 5 | `-KEY = '''<BEGIN>` / `-SessionManagerImplementation` / `-e83c…f290` / `-and prose` / `end` | 原样保留 | `"-KEY = '''***PEM_KEY***\n-and prose\nend"`：28 位整行，因为下面跟着 40 位行也丢 |

- "as 6.30.8 already did below a BEGIN with nothing before it"仍然成立：在裸 BEGIN 下，base 对第 1 行输入同样输出 `***PEM_KEY***\nend of text`。
- 句子写"a line … loses that start"，实际会丢一整段：其上的空行/头样行、该行之下连续的整行 base64 字母表行，再加一个短词行。阈值也不只是 40：整行以 key magic 开头的、或者跟在 ≥40 行上面的 16–39 位整行，也会丢。

**建议修改**：删掉具体的字符和阈值，改为陈述机制：
> **Below a BEGIN with text before it on a diff, Read, grep or quoted line, 6.30.9 reads the lines under it as key lines the way 6.30.8 read them under a bare BEGIN** (D#615): a hash, long path or identifier there, and the hash or word lines right under it, can be erased as key text.

### F4 [P3] Still as in 6.30.8（D#614）的 grep 路径清单不全

句子（CHANGELOG.md:22-23）"when a grep path holds a backslash, a space or a drive letter (`keys\conf.py:5:`, `My Keys/conf.py:5:`, `C:/src/conf.py:5:`)"。
