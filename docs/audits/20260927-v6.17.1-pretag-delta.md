### P3-1: the comment and CHANGELOG name the unclosed-tag span as the only remaining booking gap. The block pass's fail-closed branch is a second one.
- Where: hook-context.mjs:715-718 ("Matches the block-level pass for any tag closed on its own line…") and the CHANGELOG v6.17.1 Key Context bullet ("An unclosed tag … still leaves the rows it spans unrecorded, as before").
- Mechanism:
  - defangToFixpoint fails closed by stripping EVERY `<`/`>` in its input (format-utils.mjs:153).
  - The block pass runs on the whole body (hook-context.mjs:937), and that body includes the untruncated, un-defanged `Lessons:` / `Decisions:` lines from buildSummaryLines (:960, :966). hook-context.mjs:849-850 already calls that trigger "still open".
  - When it fires, every Key Context or File Lessons row with a `<` or `>` (for example `=>`) is shown with the bracket stripped. Its booked line keeps the bracket, so the row is rendered but not booked, even though it has no tag at all.
  - Live population: 34 of 178 importance>=2 rows carry `<` or `>` (readonly count, 2026-09-27).
- Reproduction (scratch probe, now deleted): insert a Key Context row with the lesson 'use x => y', plus a session_summaries row with lessons = ['<'×40 + 'system-reminder' + '>'×40].
  - Without the summary row: rendered [2,1], booked [2,1].
  - With it: rendered [2,1], booked [1]. The row renders as "use x = y".
- Trigger: needs 32 or more nested forged layers, so it is adversarial only.
- Fix: word the comment and CHANGELOG as "a block-level pass that fails closed, or an unclosed tag", or book against the block pass's output.

### P3-2: "the rows it spans then go unbooked" overstates the damage. Only the span's two endpoint rows diverge.
- Where: hook-context.mjs:718, and the same phrase in the CHANGELOG bullet ("leaves the rows it spans unrecorded").
- Mechanism: the replacement is `m.slice(1,-1)` (format-utils.mjs:151). It removes only the match's first `<` and last `>`, so rows strictly inside the span keep their text and match their booked line.
- Reproduction (scratch probe): three Key Context rows.

  - Result: rendered [3,2,1], booked [2]. The middle row IS booked.
- Fix: say "the row holding the tag and the row whose `>` closes it".
