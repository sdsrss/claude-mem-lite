## P2

### P2-1 "A worker now exits, or skips the write, when its data directory is gone" is false for two writers a worker reaches after dispatch

Claims:
- CHANGELOG.md:48-51 (Unreleased): "Detached workers (episode and session summaries, enrichment,
  maintenance, the update check) can run for up to a minute, and each one created its directories
  with a recursive `mkdir`. ... A worker now exits, or skips the write, when its data directory is gone".
- 57581aab title: "a background worker no longer re-creates a data dir removed while it ran", and its
  list of guarded sites (dispatch exit, hook-shared module mkdir, ensureDb, metrics, sampled-error,
  hook-error, record-once, plus the two spawners).

Two recursive mkdirs under the data dir that a marked worker (CLAUDE_MEM_BG_WORKER=1) still reaches
after the dispatch check are not guarded:
1. hook-update.mjs:1516-1524 `saveState()` -> `mkdirSync(join(STATE_DIR, 'runtime'), { recursive: true })`
   (STATE_DIR = DB_DIR). The update-check worker calls it after the release lookup (fetch timeout 3 s).
   Repro (sandbox HOME + CLAUDE_MEM_DIR, worker env, fetch stub that removes the data dir and rejects):
   `before check: exists = true` / `after check: exists = true [ 'runtime', 'runtime/update-state.json' ]`.
2. haiku-client.mjs:41-48 `cliSpawnCwd()` -> `mkdirSync(join(resolveRuntimeDir(DB_DIR), 'cli-cwd'), { recursive: true, mode: 0o700 })`,
   run on every `claude -p` spawn (execClaudeCliSync :810, callModelCLIAsync :891). Reached by the
   keyed-provider fallback after a failed API call (BG_LLM_TIMEOUT_MS = 45000) and by enrich-save,
   which takes no LLM slot. Repro on the HEAD copy, ANTHROPIC_API_KEY set, fetch stub removes the dir
   and throws, CLAUDE_CODE_PATH=/bin/true: `before: exists = true` /
   `after: exists = true [ 'runtime', 'runtime/cli-cwd' ]`. Direct call with the dir removed first
   gives the same `[ 'runtime', 'runtime/cli-cwd' ]`.
   (Slot-gated LLM calls are protected by accident: acquireLLMSlot's openSync fails ENOENT in a removed
   RUNTIME_DIR and gives up after LLM_SEM_TIMEOUT.)

The commit's end-to-end evidence ("sandbox removed at once: HEAD re-created it 0.25 s later, this tree
not within 75 s") removes the dir before the worker reaches dispatch, so it exercises the dispatch
exit, not a removal "while it ran". The update check is named in the CHANGELOG list, so that sentence
is false as written. Fix: guard both sites with workerDirGone(DB_DIR), or narrow the claim.
