## P2-1 — D#179: passing node:test runs whose test name ends in a count read as errors; NEW for "N error(s)", unfixed for "N failed"

`bash-utils.mjs:687`. The summary-position lookahead `(?=[ \t]*(?:$|[,;|(]|in[ \t]+\d))` accepts
`(` and end-of-line. node:test's spec reporter (Node 26 non-TTY) ends every test line with
` (<ms>)`, and its TAP reporter (Node 20.20.2 non-TTY) ends `ok N - <name>` at end of line. So a
test name ending in a count sits in a "summary position" by construction. Adding `errors?` turned a
class that was green into red.

Real output, captured with `node --test` (Node 26.8.1 spec, Node 20.20.2 TAP), classified by
`detectBashSignificance` at `539e9ae9~1` (old) and HEAD (new):

| Passing run (green `ℹ fail 0` / `# fail 0` summary) | old | new |
|---|---|---|
| `✔ handles 2 errors (0.072192ms)` | ok | **ERR** |
| `✔ returns 1 error (0.3ms)` | ok | **ERR** |
| `✔ counts 1 error, then retries (0.05ms)` | ok | **ERR** |
| TAP `ok 1 - handles 2 errors` | ok | **ERR** |
| `✔ reports 3 failed (0.374817ms)` | ERR | ERR |
| TAP `ok 1 - reports 3 failed` | ERR | ERR |
| `✔ reports 3 failed retries in the summary (0.3ms)` (the shape the new test uses) | ERR | ok |
| bun 1.4.2 pass logging `retried: 2 failed` (end of line) | ERR | ERR |
| bun pass logging `processed 3 errors (expected)` | ok | **ERR** |

- Mutation: removing `(` from the lookahead leaves `tests/bash-utils-signif.test.mjs` at 75/75
  green — the `(` that causes the spec-reporter case is pinned by no test (deno's `1 failed (3ms)`
  line also starts with the `FAILED |` banner, and vitest's red lines carry the ` FAIL ` banner).
- The CHANGELOG headline (working tree `CHANGELOG.md:43`) "a passing test run whose output
  mentions "3 failed" is no longer stored as an error" is false for the node:test spec and TAP
  shapes above, and the issue text names exactly "passing node:test/deno runs whose test NAME
  contains '3 failed'".
- Consequence: `isError` drives the episode's error marking and the error-recall gate
  (`lib/error-recall-gate.mjs`), so these passing runs get error treatment.
- Fix direction: exclude lines a runner prints for a PASSED test (`^\s*✔ `, `^\s*ok \d+ - `,
  `^# Subtest: `) from the count-first scan, rather than narrowing the lookahead.
- Repro: `node --test` on a file holding `test('handles 2 errors', () => {})`, then
  `detectBashSignificance({command:'node --test'}, output).isError` → `true` (was `false`).

## Answers to the brief's questions

- **hasGreenTestSummary misclassification** (real outputs captured for node:test 26/20, bun 1.4.2,
  pytest 9.0.2, cargo; documented formats for jest, vitest, mocha, go, deno, tap, gtest, rspec,
  phpunit, playwright, ava, tsc): green→red P2-1, P3-3; red→green P3-1, P3-2, P3-4, P3-10.
  Correct in both trees: bun pass/fail, pytest `-q`/`-v`, cargo pass/fail (incl. a test named
  `reports_3_failed`), jest / vitest / mocha / playwright red beside a green summary, deno pass
  with a `3 failed` name (fixed by this commit), go `-v` red (fixed by this commit), node:test red
  in a second run, `XFAIL` lines, eslint `0 errors`. Mutation of the D#179 regex: dropping
  `errors?`, the whole lookahead, `$`, `;`, `|`, `in <n>`, `(?:ED)?` or the whole banner each reds
  1-3 cases; `(` and `--- ` survive.
- **Other doctor/status checks grading an inaccessible dir**: Update state and Hook self-heal
  (P2-2). Stale temp files says "check failed" (honest). status reads nothing else under the data
  dir. `codeDirDenied`: correct under plain relocation (one ✗ "Entry points", Managed files / Hook
  scripts "not checked"), correct under a symlinked HOME without relocation, double-counts when
  the same dir is spelled two ways (P3-6), and ENOENT returns null so a missing code dir still says
  "server.mjs: missing" (correct).
- **mergeDuplicates**: no pair is dropped without a reason. Walked: self-merge, verbatim repeat
  (quiet, merged once), second keeper, 2- and 3-cycles, chain into a cycle (transitive keeper, by
  design, not reported), non-live keeper, missing remove row, cross-project, already-hidden remove
  row. Reasons are right; for a cycle whose canonical member is itself not live, both pairs are
  reported (`no live row #1` and `cycle: #1 survives`) and nothing merges. Mutation: removing
  either new skip, or the `!==` guard on the verbatim repeat, reds one case each.
- **rollbackInstall marker**: cannot clear another live swap's marker while install.lock holds
  (shared path, same marker path in all three writers); cannot leave hooks muted (finally + the
  launcher's dead-pid / 2-minute rule). The test observes the marker on every restore rename via
  a `node:fs` wrap (dropping `markSwapStart` reds 2/2, dropping the clear reds 2/2), but not on
  the deletes (P3-8).
- **recall-framing default**: no caller or test assumes the A/B default. Callers
  (`scripts/pre-tool-recall.js`, `scripts/post-tool-recall.js`) pass process.env; the spawned-hook
  tests match either arm; `classifyRecallFraming` is arm-agnostic. Restoring `'ab'` as the default
  reds 1 case; restoring the old unknown-value path reds 3.
- **Node 22**: see the top; no binary on the machine.
