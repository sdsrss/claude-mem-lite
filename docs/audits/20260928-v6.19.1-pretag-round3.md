## Q2 超线性

**没有发现。**
- 三个新计时形态在 tip 上 200k 时的耗时：`pemHeaderSpacesBackslash` 0.7 ms、`pemHeaderSpacesLoneCr` 2.5 ms、`pemEscapedHeaderTabs` 0.8 ms，倍增比约 2。
- 另外构造了 35 种形态（`node probes/timing.mjs probes tip`），涵盖：
  - 头部值里的引号 / 反斜杠 / 空白串，后接单独的 CR；
  - 大量 header 各带空白值；
  - 非整行的长行后接空白；
  - 空白行 / 转义空行串；
  - 以引号开头的 tail 行（新 lookbehind）；
  - long+short+short 重复；
  - `\n` + n 串；
  - END 长 label；
  - 大量没有 END 的 BEGIN。

  每档倍增（50k→100k→200k）都在 1.5–2.6 之间。只有 200k 档有几个在 3.1–3.8，但绝对值 ≤ 5 ms。把这些放大到 1.6M 复测（`timing-big.mjs`），倍增是 1.88–2.52（1.6M 时 6.7–27 ms）。
- 最慢的几个形态（200k，带 CHAIN，即跑满 32 遍）：

  | 形态 | tip | parent | v6.19.0 | benign（tip） |
  |---|---|---|---|---|
  | `tailQuoteLinesChain` | 302.6 ms | 294.4 ms | 263.3 ms | 95.4 ms |
  | `blankSpaceLinesChain` | 200.5 ms | 210.0 ms | 60.4 ms | — |

  都是线性的，与 benign 的比值 ≤ 3.2，在测试的 10× 门限之内。
- 结构化 fuzz（`probes/fuzz-time2.mjs`）：用重复单元构造形态，20k 时超过 2 ms 的再跑 40k 求倍增。
  - tip：两个 seed 各 30,000 例，**0 例**超过 2 ms。
  - parent 作为 NO 组：6,000 例中 28 例，倍增 4.07–4.15（20k 时约 450 ms，40k 时约 1,850 ms）。
  - 注意：第一版 fuzz 用的 LCG 低位周期太短，parent 也报 0，已改用 mulberry32。
- 结构上：
  - 头部值 `(?:[^\r\n\\]|\\(?![rn]))*` 的两个分支首字符互斥，后面紧跟 lookahead，不再有第二个空白量词。
  - 首行一旦匹配成功，后面的部分全是可选的，所以不会回溯进已经完成的迭代。
  - tail 模式新增的 `(?<=["'])` 起点落在 b64 串之外（b64 类不含引号和反斜杠），一次失败的扫描只会覆盖它自己那一段。

## P3

### P3-A `'` 可以结束短行后，cut-off key 下一行开头的缩写词首词被擦（相对 parent 和 v6.19.0 都是回归）
- 位置：`secret-scrub.mjs:220`，结尾可选短行的 lookahead `(?=\r?\n|\\[rn]|["']|$)`。
- 复现：`prose.mjs` 的 `contractionAfterBody` 与 `contractionAfterBodyJson`：
```
in    "$ head -3 id_rsa\n-----BEGIN RSA PRIVATE KEY-----\n<64>\n<64>\nDon't paste keys into chat."
v619  原样保留（key 也保留）
parent "$ head -3 id_rsa\n***PEM_KEY***\nDon't paste keys into chat."
tip    "$ head -3 id_rsa\n***PEM_KEY***'t paste keys into chat."
JSON: "...\\nIt's cut here" → tip "***PEM_KEY***'s cut here"
```
- 触发条件：cut-off body 的下一行以 ≤15 字符的单词加 `'` 开头（Don't / It's / That's / Let's）。每处最多损失一个词。
- 真实性：低到中。模型或用户在粘贴的 key 片段下面紧接着写英文句子，就会出现这种形态。

### P3-B 「长行不必整行」使 header 或 body 下一行开头的 16 字符以上 `[A-Za-z0-9+/=]` 串被擦（相对 parent 和 v6.19.0 都是回归）
- 位置：`secret-scrub.mjs:220`，两处 `[A-Za-z0-9+/=]{16,}` 后面都不再带行尾断言（P3-2 的改动）。
- 复现：`prose.mjs`：
  - `pathLineAfterHeader`：`HDR\n/usr/local/etc/ssh/keys/host.key: permission denied` → tip `***PEM_KEY***.key: permission denied`；parent 和 v6.19.0 保留。
  - `longWordAfterHeader`：`HDR\nInternationalization errors follow` → `***PEM_KEY*** errors follow`。
  - `setextAfterBody`：`HDR\n<64>\n================ end of key ...` → `***PEM_KEY*** end of key ...`；parent 保留整条分隔线。
  - `nextLineIdentifier`：`HDR\n<64>\nexportedArmoredPrivateKey = armor + body;` → `***PEM_KEY*** = armor + body;`。
- 仓库内实例：tip 扫描本提交自己的 `tests/secret-scrub-linear.test.mjs:58-59` 时，把下一行开头的标识符 `pemHeaderSpacesLoneCr` 一起擦掉了（与 P3-C 叠加），parent 保留。复现：`node probes/erased-spans.mjs probes tests/secret-scrub-linear.test.mjs`：
```
tip erases 280 chars parent keeps:
  "-----BEGIN PGP PRIVATE KEY BLOCK-----\\nComment:' + ' '.repeat(N) + '\\\\x',\n    pemHeaderSpacesLoneCr"
```
- 与 delta 轮 P3-5 是同一类，现在从「整行」扩大到了「行首前缀」。
- 真实性：低。要求紧贴一个私钥 BEGIN，而且紧接着的下一行以长 token 开头。

### P3-C 头部值能跨过 `\\`、`\"`、`\t` 等转义后，单行 JSON 中被擦的范围会延伸到后面的字段（相对 parent 和 v6.19.0 都是回归）
- 位置：`secret-scrub.mjs:220`，`(?:[^\r\n\\]|\\(?![rn]))*`。
- 机制：值会一直吃到下一个 `\n` / `\r` 转义、真实换行或文本末尾。parent 在第一个反斜杠处停止，然后回退到上一个 `"`。
- 复现：`prose.mjs`：
  - `jsonOneLineHeaderCutTab`：
    - 输入：`{"preview": "HDR\nComment: x", "table": "a\tb\tc", "keep": "yes"}`
    - parent：`{"preview": "***PEM_KEY***"a\tb\tc", "keep": "yes"}`
    - tip：`{"preview": "***PEM_KEY***`，后面的字段全部被擦
  - `codeCommentEscapedQuote`：`const armor = "HDR\nComment: \"" + comment + "\"";\nexportedArmoredPrivateKey = armor + body;` → tip `const armor = "***PEM_KEY*** = armor + body;`。代码跨越真实换行被擦（与 P3-B 叠加）；parent 和 v6.19.0 原样保留。
- 如果后面的字段里没有任何转义，parent 和 tip 都会擦到行尾（`jsonOneLineHeaderCutNoEsc`）。这一点是 a5af889 / 6b4dab2 已有的行为，不属于本提交。
- 真实性：低。要求 key 恰好截断在 armor 头部行，并且位于单行 JSON 或拼接代码中。

### P3-D tail 模式 `{0,2}` 与引号起点会擦掉 END 上方的两行短词（相对 parent 和 v6.19.0 都是回归）
- 位置：`secret-scrub.mjs:228`。
- 复现（`prose.mjs`）：
  - `tailTwoShortWords`：`intro\n<64>\nOK\nyes\n-----END RSA PRIVATE KEY-----\nafter` → `intro\n***PEM_KEY***\nafter`；parent 和 v6.19.0 原样保留。
  - `tailQuotePrefixProse`：`She wrote 'SomethingVeryLongHere\nok\nyes\n-----END RSA PRIVATE KEY-----` → `She wrote '***PEM_KEY***`。
- 真实性：很低。必须存在私钥 END，且那两行位于长行和 END 之间。

### P3-E Windows 路径中以 n/r 开头的段仍然会截断头部行，整段 body 被存储（不是回归；delta 轮 P3-1 例 B 未修）
- 位置：`secret-scrub.mjs:220`，`\\(?![rn])`。
- 复现（`shapes.mjs`）：`winPathN`（`Comment: C:\Users\nick\key.asc`）、`winPathR`（`D:\repos\keys\a.asc`）、`winPathJsonNick`（JSON 里的 `C:\\Users\\nick`）。四个版本都泄露。
  - 「+later」变体里 v6.19.0 能擦除，所以在这个配置下相对 v6.19.0 是回归，归入 P3-F。
- 对照：`Comment: C:\Users\me\...` 和 JSON 里的 `\"alice\"` 现在能擦除，这两处 parent 都泄露。
- 注：纯文本里 `\n` 这两个字符本来就可能是转义换行，这个歧义在正则层面没法消除；可以考虑按整段文本是否含真实换行来选解析方式。

### P3-F 非裸行形态的 cut-off key 后面再跟一个私钥 header 时，v6.19.0 擦到后一个 header，tip 存下 body（相对 v6.19.0 是回归；parent 已存在，源自 a5af889 的设计，不是 e046796 引入的）
- 复现：`shapes.mjs` 的「+later」行，v619 列为 ok，parent 和 tip 列为 LEAK：
  - readToolNumbered / readToolArrow（`     2\t`、`     2→`）
  - diffMinus（`-` 前缀）
  - quoteMd（`> `）
  - doubleEscaped（`\\n`）
  - loneCrBreaks
  - headerSameLine
  - cutQuotedLines（`"...\\n" +` 拼接）
  - headerUnknownField（`MessageID:`，这是 RFC 4880 合法的 armor 头）
  - headerCommentSpacedColon
  - winPathN/R/JsonNick
- delta 前一轮的 defect F2 把其中带行号、仅 CR、同一行这几种判为「非回归」，但它只比较了「后面没有 key」的变体。加上后一个 key header 后，v6.19.0 是能擦掉的。
- 仓库内实例：`tests/secret-scrub-linear.test.mjs:193,198` 的 fixture 在源码文本里是双重转义（`\\n`）。v6.19.0 把其中的 body 擦掉了，tip 保留（见 M1）。
- 真实性：低。要求同一字段里有两个私钥，前一个被截断，并且行带前缀或是双重转义。
