## Where the summarizer lives
- Capture: `hook.mjs` handlePostToolUse builds one episode entry per call; `desc` is a 40-60-char prefix. Flush: `flushEpisodeWithDb` → `flushEpisodeGroup` (immediate rule-based observation + detached `llm-episode`).
- Summarizer: `hook-llm.mjs` `handleLLMEpisode` → Haiku sees ONLY the entries' `desc` lines → `persistHaikuSummary` → `saveEvent` (lib/activity.mjs), `body = lesson_learned || narrative`. Every LLM type except `change` goes to `events`. It is the only automatic events writer.
- Root cause behind shape 6 (invented mechanisms): the model never saw the line naming a cause, and the prompt said "Look hard before giving up — most coding episodes contain at least one micro-lesson". Removed.

## What changed
1. `lib/episode-input-filter.mjs` (new leaf; registered in source-files.mjs + package.json#files):
   - `entryInputTags` (capture time, full command/output): probe / opens-probe / closes-probe / slip / test-run. Probe = vocabulary AND mechanism: printed marker ("mutation landed/applied", "mutant", "RED ARM", "sha before") with a checksum/in-place write/restore/test run; or "mutat*" in the command's own words (heredoc bodies stripped) with checksum/restore/test run; or "mutat*" in a heredoc script whose output reports a restore. Commits, `save`, and `>> *.md` appends are narration, never probes.
   - `filterSummaryInput` (flush): drops probes, the TEST RUNS inside an open mutate→restore span (≤4; any other call ends the span and is kept), and slips.
   - Slip = the agent's own inline script failing: python traceback whose LAST frame is `<stdin>`/`<string>`, node error located at `[eval1]`/`[stdin]`, a patch's `anchor not found`. Line-anchored (a doc quoting these is not a slip).
   - `extractDiagnosisLines`: failing output lines (named exception > FAIL/× > "failed"; count lines skipped; viewer commands' output never read), comment BLOCKS an Edit/Write adds, comment blocks inside heredocs of Bash commands the hook resolved as WRITES (python patches, `cat > f <<EOF` — most edits now), commit message lines. Scrubbed before clipping (300 chars).
   - `isLessonGrounded`: shared 4-word run (≥1 word ≥5 chars) with one diagnosis line, or an 8-char CJK run.
2. `hook.mjs`: calls with `agent_id` (host field, present only inside a subagent — read from the 2.1.283 bundle schema) skip the episode buffer; error recall still runs. Entries carry `inputTags` + `diag`. `summaryInputSubs` filters every sub before significance / immediate save / LLM; an emptied sub is not flushed; `episode_input_filter` metric row when anything is dropped.
3. `hook-llm.mjs`: DIAGNOSIS block (≤12 distinct lines) in both prompts and the retry; lesson must quote ≥4 consecutive words. Post-check for event types: ungrounded → lesson dropped, row KEPT, importance capped at 1 (SessionStart / UserPromptSubmit / PreToolUse all read importance ≥ 2), `decision` included (its body falls back to the equally unanchored narrative). No diagnosis → the retry is skipped.
4. Off switches `CLAUDE_MEM_EPISODE_INPUT_FILTER=off`, `CLAUDE_MEM_LESSON_GROUNDING=off`, documented in README.md + README.zh-CN.md (authorized by team-lead).

### Least-destructive choice, justified
Drop the lesson, keep the row, demote below the injection floor. Deleting would lose the searchable record of real work (title/files are rule-derived and usually right); keeping the lesson at full importance is what put 16 wrong lessons into SessionStart. Grounding is scoped to event types: `change` rows go to `observations`, were not audited, and a lesson-less `change` is DELETED by `isLowYieldChangeObs`, so applying it there would be deletion, not demotion.

## CHANGELOG-ready paragraph
### change: the episode summarizer learns only from the main thread's own work, and keeps a lesson only when it quotes the window (D#69)
An audit of 30 auto-captured events read 16 wrong. Subagent tool calls no longer enter the episode buffer. Mutation probes (mutate → RED run → restore) and the agent's own failing inline scripts are dropped before a window is saved or summarized. The summarizer now sees the window's diagnosis lines (failing output, comments an edit adds, commit messages). An event lesson that quotes none of them is dropped and its row demoted to importance 1, below every injection face; the row stays searchable. Replayed over the 30 audited events, none of the 16 wrong lessons would still be injected. Both accurate ones would lose their lessons too until the new prompt's quoting is measured. `CLAUDE_MEM_EPISODE_INPUT_FILTER=off` / `CLAUDE_MEM_LESSON_GROUNDING=off` restore the old behaviour. Key Events stays off at SessionStart.
