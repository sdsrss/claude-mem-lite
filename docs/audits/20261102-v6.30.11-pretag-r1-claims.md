## Findings

### F1 (P1) Python repr (and Node util.inspect) of a hunk whose code before the BEGIN holds a double quote: removed and added key lines stored
Where: CHANGELOG.md:12-15 ("...the removed and added key lines are erased now: ... or a Python repr"); not in the "Still stored" list (23-27).
Real tool: `python3 -c 'print(repr(patch))'` (or any REPL/`print(list_of_patches)`) on the `git diff` of a Python file with `KEY = """-----BEGIN ...`. Real keys, all 14 types, cut after every escaped line: 6.30.11 kept 1,713,122 of 1,952,794 windows, same as 6.30.10. Same file with `'''`: 0 kept. Also in this shape the added/deleted key (BEGIN on a `+`/`-` line) keeps 224,946 / 686,826 windows in both versions.
Repro (fake base64, no key): `node bin/repro-pyrepr.mjs /home/ai/.cache/tmp/rv-6311-claims` prints
`""" 6.30.11: >>> f.patch | '@@ -2,9 +2,9 @@\n \n DEBUG = False\n KEY = """***PEM_KEY***\n-AAAx9Q2AmZ7...\n-BBBx9Q2BmZ7...\n+CCCx9Q2CmZ7...\n+DDDx9Q2DmZ7...'`
`''' 6.30.11: >>> f.patch | "@@ -2,9 +2,9 @@\n \n DEBUG = False\n KEY = '''***PEM_KEY***"`
and Node `console.log({ patch })` stores the same lines for `"""`.
Mechanism: in single-quoted escaped text an unescaped `"` counts as a string end, so the BEGIN's line start is taken right after `"""`; `lineStartPastQuotes` only looks past single quotes, so `isDiffContextLine` is false and no diff reading runs. The tests' Python repr case is a bare key file (cutoff-shapes test, `const repr = ...`), so the shape is untested. Not a regression.
