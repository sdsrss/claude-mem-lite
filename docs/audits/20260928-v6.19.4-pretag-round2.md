### F1 (P1): cross-pass leak with no code before the BEGIN
- Mechanism: on pass 1 the cut-off reader erases the key's first lines and writes `***PEM_KEY***` over the BEGIN.
  The block pattern (secret-scrub.mjs:214) never crosses `***PEM_KEY***`. A later pattern in pass 1
  (Authorization :232, DSN) removes a partial `-----BEGIN RSA PRIVATE KEY` blocker. On pass 2, 26dcd49's block match
  BEGIN..END erases every key line; 5981f88 has no BEGIN left, so the lines after the first non-key line stay.
- The commit files this as D#166 and accepts it as parity because "26dcd49 stores the same lines when the key has no
  code before its BEGIN". That does not hold for two new pass-1 erasure sources that need no code:
  1. a trimmed blank prefixed line (`//`, `>`, `#`), which the reread (:739, :750-762) takes as BLANK. This has
     been present since c112ef3.
  2. a BEGIN at the start of a JSON string value, where leftContexts (:586-604) reaches `:"` and `:` shares with `-`.
     This is new in 5981f88.
- Repro (raw text, no code, no opener, synthetic key): `node probe3.mjs`
  ```
  prefix "// " blocker Authorization:: key lines kept old 0/5 new 3/5
  prefix "// " blocker postgres://u:-: key lines kept old 0/5 new 3/5
  prefix "> "  ... old 0/5 new 3/5      prefix "# " ... old 0/5 new 3/5   (both blockers)
  NEW: "// ***PEM_KEY***\n// Some prose line here.\n// <b64:64>\n// <b64:64>\n// <b64:20>\n// Authorization: Bearer *** RSA PRIVATE KEY\n// -----END PGP PRIVATE KEY BLOCK-----\nthe end"
  ```
  Input shape: `// -----BEGIN PGP PRIVATE KEY BLOCK-----`, `//`, two key lines, a prose line, three key lines,
  `// Authorization: Bearer -----BEGIN RSA PRIVATE KEY`, `// -----END PGP PRIVATE KEY BLOCK-----`. The `>` form is
  a gpg export quoted in mail or markdown with the blank quote line trimmed.
- Repro (JSON, no code): `node probe2.mjs`. The BEGIN starts the JSON string value, and the key lines carry a `-`:
  `bearer pre='-' json: windows kept old 0/10 new 6/10` (json2 the same). At 2e5e266 the result is 0/10, so this path
  is new in 5981f88. probe3 gives the same 3/5 at 2e5e266.
- Rate: 100,000 cross-arm cases (`node crosscount.mjs 100000 15`). 535 store key windows 26dcd49 erased. All 535
  are cross-pass: old's single pass stores them too. 505 are D#166-parity. 30 are not: 26dcd49 erases the no-code
  variant too. Of those 30, 8 have no code or opener at all (7 escaped, 1 raw/fence).
- It is crafted: it needs a partial-BEGIN blocker that a later pattern scrubs, an END, and a non-key line inside the
  key. It falsifies the parity basis of D#166 as the commit states it, not the per-call claim.

### F2 (P2): new prose-loss class with no key and no code
- Where: the reread condition `!shape?.test(lineText)` (:755) fires for any first line that does not start with the
  whole left context, not only for code or openers. sharedShape (:565) then takes the shorter shared prefix.
  - A trimmed blank line (`//`, `#`, `>`, ` *`, `-`, `web-1  |`) becomes BLANK, and the reading continues.
  - A shallower prefix (`> > BEGIN` over `> ...`, `#  BEGIN` over `# ...`) makes the next line LONG.
  - Either way, whole-line 16+ base64-shaped words below are taken: identifiers, paths, 40-hex SHAs, and a line starting
    with a 40+ run as a CUT line.
- Repro (raw, no key anywhere): `node probe4.mjs`, section Q3.
  ```
  P-A. // comment, trimmed blank line   words kept: old 2/2 new 0/2   NEW: "// ***PEM_KEY***\nthe end"
  P-A. # comment / > quote              old 2/2 new 0/2
  P-A. control: blank line keeps its trailing space   old 0/2 new 0/2
  P-B. quote depth 2 over depth 1       old 2/2 new 0/2      P-B. "#  " over "# "   old 2/2 new 0/2
  ```
  The input is `// -----BEGIN RSA PRIVATE KEY-----`, `//`, `// SessionManagerImpl`, `// TokenRefresherImpl`,
  `the end`. 26dcd49 erases the same words only when the blank line keeps its trailing blank. The contract's test
  (the same text with code or opener removed) is the same text here, and 26dcd49 keeps the words.
- Rate:
  - No-key arm (a BEGIN over base64-shaped prose), `classify.mjs nokey 100000 16`: 233 per 100k lose words 26dcd49
    keeps on the no-code variant. In every one, the first line turned BLANK after the reread.
  - The same arm with random edits: 166 per 100k, including LONG after the reread.
  - Lines arm (keys, no random edits): 7 and 4 per 100k.
- Realism: local transcripts show 0. Across 1,076 files and 2,948 strings naming PRIVATE KEY, the outputs differ in 26,
  all in this repo's own scrubber-review transcripts, and in all 26 the new code erases key-shaped content. The 32
  strings from other projects are unchanged.
- It is the same mechanism that now erases quoted gpg exports (`> ... \n>\n> lQ...`), which 26dcd49 stored whole.

### F3 (P2): the reread makes a bare `>` BLANK, so 17 BEGINs re-read one run
- Shape `quoteArmorInterleaved` (shapes.mjs):
  - `CHAIN\n> BEGIN\n`
  - 16 × (`>\n> X-h<letter>: BEGIN\n`)
  - `>\n` × N/2
  - Each inner BEGIN's first line is a bare `>`. 26dcd49 stops each BEGIN there. 5981f88 rereads it as BLANK, then reads
    up to 16 ARMOR lines and the whole `>` run, on each of the 32 passes.
- Under coverage (`zz-perf.test.mjs`, suite method, 200k): new 168-170x benign, 26dcd49 0.70-0.72x.
- A single BEGIN over a `>` run (`quoteBlank`) is new 10.3-10.6x benign (over the 10x budget), 26dcd49 0.67-0.83x.
- Without coverage: 3,250 ms at 200k and 12,722 ms at 800k (26dcd49 43 ms / 172 ms). Growth is 1.93-2.03x per
  doubling, so it is linear. At 400k it is 6.6 s, over Stop's 5 s.
- The same cost is at 2e5e266 (3,264 ms), so it came in with c112ef3. The linear suite has no blank-quote shape.

### F4 (P3): leftContexts walks into JSON syntax
- Where: :589-602. At u > 0, a BEGIN at a JSON string start has an own context of ''. The first reach-back passes the
  string's opening `"` and stops at the key's closing quote, giving `:"`; later ones give `content":"` and similar.
- sharedPrefixLength treats `:` and `-` as the same, so a `-`/`:` line under the BEGIN is read with prefix `:`.
- `node probe1.mjs`: `{"type":"tool_result","content":"-----BEGIN RSA PRIVATE KEY-----\n- SessionManagerImpl\n- TokenRefresherImpl\n- the end of the list"}`
  - old keeps both names; new outputs `"***PEM_KEY***\n- the end of the list"`.
  - The same text raw is kept by both. Paths (`- src/components/HeaderBar`) and `:` lists are also lost, as is a short
    last word (`done`, SHORT).
- The comment (:580-585) says the contexts reach back "toward the line's start". They also reach past the string
  start. This is also F1's JSON source.

### F5 (P3): union of spans takes lines after the key
- Where: :816-822. A BEGIN in an armor header line of a taken key (`Comment: -----BEGIN ...-----`) is now read with
  its own prefix `Comment: `, and takes `Comment: <16+ base64-shaped word>` lines after the key's end.
- `probe4.mjs` P-D: `[B, 'Comment: '+B, <key 64>, <key 64>, 'Comment: SessionManagerImpl', 'Comment: TokenRefresherImpl', 'the end']`
  gives old 2/2 kept, new 0/2 (`"***PEM_KEY***\nthe end"`). 2e5e266 keeps them. Contrived; the commit meant this
  change to take key lines only.
- Cost: inner BEGINs in header lines re-read the key body (armorAlphaLongBody 5 → 33 ms at 200k, still 0.5x benign).

### F7 (P3, not regressions): what the D#160 fix still misses
`node probe4.mjs` (Q2 section) and `node residual.mjs 100000 21`:
- `a.` More than 4 quote runs in escaped text: `-print('a' + 'b' + '''BEGIN` stores 3/3 in JSON and erases raw.
- `c.` A shared prefix over 64: a 75-character logback stamp plus `KEY = """` stores 3/3; a 53-character one erases.
- `d.` A BLANK first line spends the reread: `\tKEY = '''` over a gpg key (blank line) in JSON stores 3/3; without the
  code it erases.
- A blank before an escaped opener (` \"\t-----BEGIN` in JSON): sharedShape returns null at :574 when the shared part is
  only a blank, without trying the opener or later contexts (the M19 input).
- Residual rate: 116 of 40,214 code/opener head-or-mid cases store windows the no-code variant erases (26dcd49:
  19,487). The rest are D#167 (`+` over a 16-39 first line).

### F8 (P3): pre-existing budget breaches, about 2x worse since e59daed
The regex exec per nextLine call costs more than the old per-character loop on 1-character lines.
- `armorAlphaBlank` (one BEGIN, 16 `X-h<letter>: BEGIN` header lines, N blank lines):
  - Under coverage at 200k: 26dcd49 238.6-239.8x benign, 5981f88 299.6-316.3x.
  - Without coverage: 2.4 s → 4.9 s at 200k, 9.6 s → 21.1 s at 800k.
- `blankLines` (one BEGIN, N blank lines): 13.6-14.6x → 17.5-17.7x under coverage.
- Neither shape is in the suite. The e59daed tree alone already reads 5,003 ms and 261 ms, so the 2x is e59daed's.
- Linear: 1.97-2.02x per doubling.

## Answers

**Q1, security.**
- Single-pass leaks: none found. That is 0 in each of:
  - lines ×2 seeds, edits ×2, cross, nokey and nokey+edits (100k each);
  - 400k token-soup cases (`chaos.mjs`).
- Per call the reread is monotone by construction:
  - SHORT stays SHORT or turns BLANK, only on a prefix-only line.
  - OTHER, where 26dcd49 ended the key, can only extend the span.
  - The span union never shrinks `last`.
- Cross-pass leaks: F1.
- Crashes: 0 in every arm.
- Keys stored overall: lines arm 31,354 → 8,088 per 100k (26dcd49 → 5981f88).

**Q2, the new paths.**
- leftContexts:
  - over-reach: F4 (JSON syntax), F1 source 2.
  - under-reach: F7a. The 512 cap only bounds the second and later reach-backs; a 520-character context is taken on
    the first.
- Union of spans: F5, plus the per-BEGIN re-read cost (F3 does not depend on it).
- MAX_SHARED_PREFIX: under-reach F7c. Nothing pins it (M01-M07, F6). The alt60 cost it was meant to bound is below it:
  17.0-17.6x benign under coverage vs 26dcd49 8.9-9.4x.
- Backslash back-off: no misbehaviour found. The F3 test catches its removal (M08).
- OPENER_RE with escaped quotes: works on the fuzz; the escaped repeat is unpinned (M13).
- Reread with no prefix shape: F4 and F1. The reread with key material on the BEGIN line: F2's `restOnBegin` rows
  (5 + 1 + 5 + 2 in the no-key arm).

**Q3, prose.** F2 (P2), F4 and F5 (P3). All three are losses 26dcd49 does not show on the same text with code and
opener removed. F2 and F4 need no code at all.

**Q4, performance.**
- Nothing superlinear: 1.83-2.15x per doubling from 100k to 800k, over 8 shapes and both trees (`growth.mjs`).
- Much slower than 26dcd49 under coverage: F3 (0.7x → 170x), `quoteBlank` (0.7x → 10.5x), F8 (1.2-2x).
- Suite shapes on 5981f88: `pemEscapedQuotesBeforeBegin` 8.34-8.78x (26dcd49 3.87-4.06x), 12-17% under the 10x budget;
  `pemOpenerBeforeBegin` 7.79-8.03x.

**Q5, tests.** F6.
