# v6.35.6 pre-tag review, round 2 (delta, defects lens): report

Commit under review: `764d69a2` (parent `52665d0e`), `lib/summary-extractor.mjs` + its tests.
Trees built with `git archive` under `~/.cache/tmp/rv-6.35.6-r2/`: `tree-v6.35.5`, `tree-52665d0e`,
`tree-764d69a2` (the last with a copied `node_modules`, 280 MB, a real copy, not a link). Every
process ran with the LLM keys and proxies unset, `MEM_NO_AUTO_ADOPT=1`, and `HOME` / `CLAUDE_MEM_DIR`
(plus `TMPDIR` for vitest) under the work dir. Nothing was written to the repository:
`git status --short` printed nothing at the end. Scripts are in `scripts/`. `corpus.json` and
`corpus-r4.json` hold transcript text and stay in the work dir.

## Answers

1. **Contract violated?** Yes, in one place: clause 2 (text with no report heading must extract
   exactly as v6.35.5 does). A multi-name header whose second or later name is a part name
   (`**Done / Changes**: x`) is read differently (R2-A). I built this input. It never occurs in the
   7133 real messages that have no report heading. I found no other no-heading divergence. Inside
   reports, the real corpus matches a contract-literal segmentation line for line. The divergences
   I found there are built inputs (R2-B to R2-D). No input threw. Time is linear.
2. **Is the report-heading test too wide or too narrow?** Neither, on this machine's real reports.
   298 of 298 report headings match, I found 0 near-misses, 0 sit inside a code fence, and every
   matched heading is followed by at least one part. The narrow cases (R2-F) and the one wide case
   (R2-D, a fenced example) are built inputs.
3. **Would a 6.35.5 user notice something the contract does not allow?** Only R2-A, and only if they
   write that header shape. R2-E is a visible change for 6 of 298 real reports. It comes from
   `5576d377` (already in the parent), not from this delta, and it sits where two contract
   clauses conflict.

## Findings

### R2-A (P3, constructed): the clause-2 parity claim fails for multi-name headers with a part name after the first

- **Where:** `lib/summary-extractor.mjs:45` builds `MORE_SECTIONS_RE` from the widened `SECTION`
  (line 36), and `:77-78` applies it whatever `inReport` is. The delta gates only the FIRST name
  (`:71-72`, `if (part && !inReport) return null`).
- **Repro:**
  ```
  cd ~/.cache/tmp/rv-6.35.6-r2 && node --input-type=module -e "
  const o=(await import('./tree-v6.35.5/lib/summary-extractor.mjs')).extractStructuredSummary;
  const n=(await import('./tree-764d69a2/lib/summary-extractor.mjs')).extractStructuredSummary;
  for (const t of ['**Done / Changes**: shipped X','**Uncertain / 验证**\n- flaky on CI\n- needs a rerun'])
    console.log(JSON.stringify(o(t)), JSON.stringify(n(t)));"
  ```
  - v6.35.5: `{"done":"",…}` and `{"uncertain":"",…}`.
  - 764d69a2: `done:"shipped X"`, and `uncertain:"- flaky on CI\n- needs a rerun"`.
  - The other forms that diverge: `Failed / Verification: …`, `**Not done / Open items**: …`,
    `**Done、变更**：…`, `- Done, Changes: x`.
- **Effect:** `done` becomes non-empty while `notDone` is `''`. Through `writeStopSummary`
  (`lib/fast-summary.mjs:304` / `:367-369`, `if (hasReport) remaining = notDone`), that sets
  Remaining to `''`. This is the mechanism F2 was fixed for.
- **Measurement:**
  - Random no-heading differential (`scripts/fuzz-noreport.mjs 1 200000`): 1548 of 199612
    inputs diverge, 0 throw.
  - The same generator with the four multi-name separators removed
    (`fuzz-noreport-nomore.mjs`, seeds 2/3/4 × 300k): 0 of 894777 diverge.
  - Real corpus: 0 of 7133 no-heading messages diverge.
- **Fix:** I checked one candidate (`tree-m7`): build `MORE_SECTIONS_RE` from the four non-part
  names only. No-heading divergence drops to 0 (2 seeds × 300k), and the extractor tests stay
  75/75. Gating the part names on `inReport` would also work.
- **Test gap:** that same mutation passes the whole extractor test file (75/75), so no test pins
  multi-name headers that contain part names, in either direction.
- **Why P3:** never seen in real text. But it falsifies the commit message's "a reply without one
  extracts as in 6.35.5", and the contract's "for every input".

### R2-B (P3, constructed): a bullet whose first word is a part name switches the part mid-part

- **Where:** `HEAD_RE` (`:42`) accepts a `- ` / `* ` / `●` / `>` prefix, and inside a report any
  such line opens a part (`:250-256`).
- **Repro (`scripts/fb.mjs`):**
  - `## 汇报\n\n**变更**\n- 改了解析\n- **验证**：补了一条测试\n- 改了缓存\n\n**遗留**\n- 无`
    gives `done:"- 改了解析"`. `- 改了缓存` is lost: it went to the 验证 part, which has no field.
  - `…**变更**\n- 改了解析\n- 遗留：无\n- 改了缓存` gives `notDone:"无\n- 改了缓存"`, which is 变更
    content in Not done.
  - `- Verification: …` and `- 变更：…` behave the same way (`scripts/table.mjs`).
- **Real:** 0 bullet-form part headers in the 298 reports. But 3 messages without a report heading
  in the same corpus use exactly the `- **验证**：…` sub-bullet shape, so this user does write it.
- **Note:** requiring a part header to be non-bullet would not change any real report. My
  non-bullet oracle agrees with the shipped code on all 298 reports.

### R2-C (P3, constructed): a Done / Not done / Failed / Uncertain header inside a part ends the part, and 验证 content can land in a field

- **Where:** `:250-256`. A non-part EN header sets `part=false`, and an inline one also sets
  `block=false`.
- **Repro (`scripts/fb.mjs`, `scripts/table.mjs`):**
  - `## Report\n\n### Changes\n- a\n\n### Verification\n- Done: ran the suite\n- \`npm test\` → passed (47/47)\n\n### Open items\n- b`
    gives `done:"- a\nran the suite\n- \`npm test\` → passed (47/47)"`. That breaks
    "验证 → no returned field".
  - `- Failed (pre-existing): lint rule X` inside Verification sends the next 验证 line to
    `failed`.
  - `**Uncertain.**` inside 变更 sends the rest of 变更 to `uncertain`.
- **Real:** 0 of 298 reports have any Done / Not done / Failed / Uncertain header after the
  report heading. `failed` and `uncertain` are empty for all 298.
- **Root:** the contract's own clauses 1 and 3 conflict here ("a part runs to the next part
  header" against "Done/Failed behaviour unchanged"). This needs a decision, not necessarily a
  code change.

### R2-D (P3, constructed): part boundaries and the report heading ignore Markdown code blocks

- **Where:** `BLOCK_END` (`:111`) and `REPORT_HEADING` (`:135`, tested at `:249`).
- **Repro (`scripts/fb.mjs`):**
  - In a part, a fenced block holding `# run`, a fenced `---`, or a 4-space-indented `# x` ends the
    part. `### 变更\n- a\n\`\`\`bash\n# run\nnpm test\n\`\`\`\n- b` gives
    ``done:"- a\n```bash"``: `- b` is lost and the fence opener is kept.
  - A fenced example containing `## 汇报`, followed by a `### Changes` list, gives
    `done:"- Moved the parser"`. v6.35.5 gives `''`, so this is the F2 shape reached through a
    fenced example.
- **Real:** 0 fenced report headings, and 0 part lines lost to fences, in 298 reports. The
  `BLOCK_END` half predates this delta; the fenced-heading half is new.

### R2-E (P3, real, not introduced by this delta): 剩下… lines inside a 变更 / 验证 part leave Not done

- **Where:** block mode `continue`s (`:258-274`) before the `ZH_HEADER` check (`:275-281`), and
  parts are always block mode.
- **Real corpus:** in 6 of 298 reports, content that v6.35.5 put in Not done now lands elsewhere.
  That is 54 lines: 50 moved to Done, 4 dropped because they were inside 验证. My ids are
  1355, 1534, 2630, 3497, 4693, 5325 in `corpus.json` order (`scripts/oldlost3.mjs`).
  - In 2 of these, v6.35.5's Not done was noise: prose that starts with 剩下的 but describes work
    that was done.
  - In at least 2, the line is a real open item that the writer filed under 变更: a
    `- **剩余工作**：D#…` bullet, and a "还剩 N 条…没测" bullet.
- **Parent:** `52665d0e` gives the same output on all 6 (`scripts/par6.mjs`).
- **Decision needed:** the contract's "剩下… behaviour must be unchanged" and "a part runs to the
  next part header" cannot both hold for these lines.

### R2-F (P3, constructed): heading forms the report test rejects

- **Where:** `REPORT_HEADING` (`:135`) has no `/i` flag and anchors with `$` on a `\n` split.
- **Rejected forms:** `## report`, `## REPORT`, `## Report:`, `## 汇报：`, `## 汇报 — x`,
  `**汇报**`, and any CRLF line (`## 汇报\r`). `HEAD_RE` itself tolerates a trailing `\r`.
- **Effect:** these extract as in v6.35.5, which is the contract-safe direction.
- **Real:** 0 near-miss headings, and 0 `\r` characters, in 7431 messages.
