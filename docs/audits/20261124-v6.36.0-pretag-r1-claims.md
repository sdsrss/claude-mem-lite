## Findings

### F1 (P3): for verify-apply and restore, `.` is not "the project a write without --project takes, refusal included"
- **Quotes:**
  - CHANGELOG.md:20-21: "`--project .` and `--project current` on a write name the project a write without `--project` takes, and are refused inside `~/.claude/projects/<dir>/…`"
  - Commit e84bf044: "On save / defer add / activity save / import-jsonl / verify-apply / restore they now name the project a write without --project takes, and are refused where that write is."
  - mem-cli.mjs:4451-4452 comment: "On a write they name the project a write without --project takes, refusal included"
- **What is true:**
  - verify-apply without `--project` uses `inferProject()` with no refusal (cli/verify-apply.mjs:138), so in the state dir the flagless write is not refused. `.` is refused there.
  - restore without `--project` keeps each row's own project when every row carries one (mem-cli.mjs:2556-2557), while `.` replaces them all with the directory's project. The test comment says this; the CHANGELOG does not.
- **Evidence:** in `<HOME>/.claude/projects/-home-u-proj/memory` with obs #1 under `-home-u-proj--memory`:
  - `verify-apply va.json --apply --digest 2971328e47b2e809` (no `--project`) → `#1 retire: ok`, exit 0, `superseded_at` set.
  - `verify-apply --print-project` → `-home-u-proj--memory`.
  - `verify-apply va.json --project .` → `Not written: …`, exit 1.

### F2 (P3): the release title and both READMEs say "on a write" without limiting it to the six commands
- **Quotes:**
  - CHANGELOG.md:5 and the daa4e073 subject: "`--project .` on a write is refused in Claude Code's project folders"
  - README.md:253-254: "`--project .` / `current` on a write is refused inside `~/.claude/projects/<dir>/…` … and in a subdirectory names the subdirectory's own project."
  - README.zh-CN.md:210: "写入命令的 `--project .` / `current` 在 … 之内被拒绝 … 在子目录里，它指子目录自己的项目". Neither README lists the six commands.
- **What is true:** `defer update` (new in this release) and `defer drop` are writes that are not in `PROJECT_WRITE_CMDS` (mem-cli.mjs:4006-4013), so `.` there goes through the read resolver.
- **Evidence:**
  - State dir, item D#1 in `-home-u-proj--memory`: `defer update D#1 --priority 3 --project=.` → `Updated D#1 … (priority)` exit 0; `defer drop D#1 --reason r --project=current` → `Dropped D#1` exit 0.
  - Subdir `work/invoice-app/billing` (no rows of its own): `defer update D#1 --priority 3 --project .` → `Updated D#1 "root item" in project "work--invoice-app"`, the enclosing repo's project.

### F3 (P3): the R2-A extractor change also changes reads inside a report, and the release notes describe it as outside-only
- **Quotes:**
  - CHANGELOG.md:28: "Outside a `## 汇报` / `## Report` heading, a header naming several sections reads as in 6.35.5."
  - docs/audits/20261112-d27-preregistration.md:183: "6.36.0 改了 `lib/summary-extractor.mjs`（D#942 R2-A：汇报以外的多段名表头恢复 6.35.5 的读法）"
- **What is true:** the narrowed `MORE_SECTIONS_RE` (lib/summary-extractor.mjs:48-51) applies inside a report too. Headers that 6.35.6 read there are now read as nothing.
- **Evidence:**
  - `## Report\n**Done / Changes**: shipped x` → 6.35.6 Done "shipped x", candidate empty.
  - `## 汇报\n**变更 / 验证**\n- a\n- b` → 6.35.6 Done "- a\n- b", candidate empty.
  - `## Report\n**Changes / Open items**: c` → 6.35.6 Done "c", candidate empty.
  - `## Report\n**Not done / Open items**: z` → 6.35.6 Not done "z", candidate empty.
  - Fuzz with a report heading prefixed: candidate ≠ 6.35.6 on 23,373 of 200,000 inputs.
  - Real data: 0 of 299 reports are affected (A3), so the impact measured here is 0. The finding is the undisclosed scope. Commit bbe7426d's own sentence ("the four original ones again") is accurate.

### F4 (P3): commit 23a47c43 gives the wrong denominator for the 0.27 ratio
- **Quote:** "help lookups per CLI write were 0.27 against O6's target of 0.1"
- **What is true:** R4 divides by CLI and MCP writes together: docs/audits/20261124-r4-session-history-analysis.md:103 "查用法 34 次，CLI 与 MCP 写入 124 次，比值 0.27", and :38 "34/124 = 0.27". The test comment (tests/steering-block-cli-forms.test.mjs:1) says "per write", which is correct.

### F5 (P3): the `cli.mjs help` line understates what `--project` does for `defer update`
- **Quote:** mem-cli.mjs:3456 "`--project P       Project for ordinal resolution (default: current)`"
- **What is true:** `--project` also decides which project a `D#N` must belong to.
- **Evidence:** from project alpha, `defer update D#4 --title x` → "D#4 belongs to project "work--beta"", exit 1. `defer update D#4 --title "beta renamed" --project work--beta` → `Updated D#4`, exit 0.
- The wording is copied from `drop`. The help also omits the `--id` alias that `defer update` accepts.

### F6 (P3): commit 04afc07a says every push is gated
- **Quote:** "after which every push and tag fails `benchmark-gate --strict`"
- **What is true:** ci.yml:3-7 runs on `push: branches: [main]` and on pull requests (strict only on push, ci.yml:208); tags are gated by publish.yml:143. A push to any other branch runs no gate.

### F7 (P3, also in 6.35.6): the space form `--project .` fails when the project name starts with `-`
- **Claim it contradicts:** the CHANGELOG.md:20-21 sentence that `--project .` on a write names the flagless project.
- **What is true:** `.` is replaced before parsing. A name beginning with `-` then reads as a flag, and the error tells the user how to quote a value they never typed.
- **Evidence:** cwd `<HOME>/work/-scratch/app`.
  - `save "flagless lesson"` → project `-scratch--app`, exit 0.
  - `save "…" --project .` → "--project requires a value … A value that starts with - is written --project="…"", exit 1.
  - `--project=.` works.
  - 6.35.6 gives the same output.
- In the candidate the state-dir refusal fires before parsing, so the state dir itself is not affected. Outside it the defect remains, including `defer update … --project .`.
