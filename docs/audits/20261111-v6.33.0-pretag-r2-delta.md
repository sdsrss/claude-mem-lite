## Findings

### F1 — P1 (regression vs 6b3b94fe). The session that starts at a /compact loses its final reply in EVERY summary when its first prompt is stored within 5 s after the compaction
- Where: lib/summary-extractor.mjs:163 + :167 (`const from = firstPromptEpoch - 5000; ... if (at > from) return { from, to: at };`), hook-llm.mjs:1905 (no tail fallback when `window.to` is finite).
- Mechanism: the window opens 5 s before the first stored prompt, and the closing compaction is searched
  from that opening, so the compaction that STARTED the session (boundary < store < boundary+5 s) is taken
  as its end. Window = [store-5 s, boundary]: no turn, `to` finite, so no fallback. Every worker of that
  session (each Stop, the next /compact or /clear SessionStart) computes the same empty window.
- Real shape, measured on this machine's transcripts (probes/compact_precise.py, queued_prompt_timing.py):
  after 11 of 52 manual compactions the first typed prompt is stamped 30-172 ms AFTER the boundary (typed
  during compaction, queued); SessionStart hook attachments land 122-287 ms BEFORE the boundary, the
  UserPromptSubmit attachment 129-275 ms AFTER it, so the prompt is stored in the NEW session within
  0.3 s of the boundary.
- Repro (end to end, real `node hook.mjs llm-summary` worker, stub model records its stdin):
  `cd probes && node summary-driver.mjs <tree> scenarios/<name>.json` (output in probes/summary-driver.out)
  ```
  A-queued-prompt-next-session      base "NEXT SESSION reply (its own)"   cand <none>
  A2-queued-prompt-then-more-turns  base "THIRD reply, the last one"      cand <none>   (3 turns, minutes apart)
  A3-prompt-3s-after-compact        base "NEXT SESSION reply (its own)"   cand <none>
  ```
  Unit repro on dfb47a16's own lib/summary-extractor.mjs (probes/unit-window.mjs):
  ```
  first stored prompt at boundary+200 ms  -> window [-4800, 0] ms, replies []
  first stored prompt at boundary+4900 ms -> window [-100, 0] ms, replies []
  first stored prompt at boundary+5100 ms -> window [100, Infinity] ms, replies []   (hook falls back to the tail)
  ```
- 6b3b94fe: carries the session's own reply in all three (tail of the transcript).
- Fix verified in a scratch copy: `if (at > firstPromptEpoch) return { from, to: at };` → A, A2, A3 give the
  session's own reply, B-H unchanged; the 7 affected test files stay green with it (194 passed, 1 skipped
  — mutation M10 below), i.e. no test pins this boundary either way.
- The comment at hook-llm.mjs:1890 ("The window closes at the first compaction after the session's first
  stored prompt") is false: it closes at the first compaction after (first stored prompt − 5 s).

### F2 — P2 (P1 if the shape is common; prevalence not measured). The word-form drop removes the memories the search was for whenever ANY other leg matches, and on MCP's default `auto` mode it also disarms deep escalation first
- Where: lib/search-core.mjs:1073-1077; deep-search.mjs:55 (`AUTO_DEEP_MIN_RESULTS = 3`).
- Shape: memories say "crash", the user's own stored prompt says "crashes" (the prompts leg searches every
  stored prompt, all projects when no project filter). Seeded sandbox (probes/search-driver.mjs,
  probes/mcp-search.mjs; output probes/search-driver.out):
  ```
  CLI `search crashes`:   base: Found 4 (#3 obs, P#1 prompt, #2 obs, #1 obs)   cand: Found 1 (P#1 prompt only)
  MCP mem_search {"query":"crashes"} (default auto):
    v6.32.0: deep escalation, 1 obs row + P#1        6b3b94fe: 3 word-form obs rows + P#1        cand: P#1 only
  ```
  With 3+ word-form rows the obs leg is not "weak", so escalation does not run; the rows are then dropped,
  leaving the observation leg empty. With 1-2 word-form rows escalation runs and they are kept (F3): more
  stem matches → fewer memories shown.
- `--source observations`, `--type bugfix` (obs+events only), `crash` (matches as written): identical to base.
  Paging/total stay consistent with the rows shown (`--limit 1 --offset 1`: base "Found 1 of 4", cand "No
  results at offset 1"; `--json` total 4 → 1, matches returned); perSourceOffset is always 0, so the drop is
  the same on every page.
- Suggested alternative: rank the word-form rows after the as-written rows instead of dropping them (F2's
  stated harm is outranking, not presence).

### F4 — P2 (same as 6b3b94fe). F1's fix does not cover the most common post-/compact shape on this machine: a background task's notice answered before the next typed prompt
- 33 of 52 manual compactions are followed by a task notice that Claude answers before the next typed prompt
  (probes/shape_scan.py: `manual->task_notification|assistant_text_before_typed=True 33`). The notice and its
  reply "continue the turn before them", and that turn is the pre-boundary `/compact` record, stamped 62-149 s
  before the boundary, so it is inside the previous session's window. The previous session's worker (spawned
  at that /compact) takes the next session's reply if it lands before the read (measured first notices at +0,
  +8, +20, +82, +88 s).
- Repro `B-notice-after-compact-prev-session`: base and cand both "NEXT SESSION reply to the notice".
- False as written: hook-llm.mjs:1888 "The reply is this session's last". Also lib/summary-extractor.mjs:130
  "slash commands ... continue the turn before them": Claude Code records `/compact` as a plain-text user
  record (48 such records found), which `typedPromptText` treats as a typed turn. In the measured shapes this
  does not change which reply is chosen (P3 on its own).
- Possible fix: end the current turn at a `compact_boundary` whose `compactMetadata.trigger` is `manual`
  (mid-turn continuation is only needed for `auto`; 48 of the 52 manual boundaries have the typed `/compact`
  record right before them).
