## Findings

### F1 — P3 (ambiguous): the paragraph now quotes the benefit and the cost against two different baselines
- Sentence: CHANGELOG.md:16-19 "On 30 of the maintainer's own sessions, against the same prompt with only the final reply: a main
  piece of finished work missing from the summary went from 12 to 0, done work written as not done from 4 to 0. On those sessions
  the prompt grows from 2,411 characters on average in 6.33.0 to 5,435."
- The r2 sentence moves the cost baseline to 6.33.0 (2,411; r1 said 4,383 = the final-reply arm). The benefit baseline stays the
  final-reply prompt, and no released version ever sent the model a reply:
  `for t in v6.30.15 v6.31.0 v6.32.0 v6.33.0; do git show $t:hook-llm.mjs | grep -c finalReply; done` → 0, 0, 0, 3 — and at v6.33.0
  the 3 hits are the builder's parameter; its only call (hook-llm.mjs:1882) is
  `buildSessionSummaryPrompt({ project, observations: recentObs, userPrompts })`.
- Read together, the two adjacent sentences say "6.33.0: 12 missed, 2,411 chars → 6.34.0: 0 missed, 5,435 chars". The 12 belongs to
  an unreleased prompt; what 6.33.0's no-reply prompt misses on this ruler was not measured. Each sentence names its baseline
  correctly, so neither is false; the pair is ambiguous to an upgrader. rulers.md:90 (reading 5) states this ("Arm A is the
  final-reply prompt (D19), not 6.33.0's prompt"); the CHANGELOG does not.

### F2 — P3 (ambiguous): "never reads them" is given as the reason to delete the files, and it is not the reason
- Sentences: CHANGELOG.md:7-9 "Going back is pinning `claude-mem-lite@6.33.0`, which never reads the `runtime/turn-replies-*.json`
  files this version writes: delete them by hand."; README.md:245-246 "…delete `runtime/turn-replies-*.json` from the data
  directory: 6.33.0 never reads them."; README.zh-CN.md:206 "…：6.33.0 不读它们。"
- The claim itself holds (see "Checked" below). r1 said "never reads or removes"; r2 dropped "or removes" because 6.33.0's
  `uninstall --purge` removes `runtime/` whole (the v6.33.0 CHANGELOG entry says so). What makes manual deletion worth doing is that
  6.33.0's SessionStart 24 h runtime sweep does not match the prefix (t633 hook.mjs:1972-1983 `gcStalePreRecallCooldowns` lists
  `pre-recall-cooldown-`, `.claude-mem-injected-`, `.claude-mem-keyctx-`, the bugfix-nudge prefix and `RECALL_SHOWN_PREFIX` only).
  So each turn's scrubbed reply text stays on disk until `uninstall --purge`. Not reading a file is a reason it is harmless, not a
  reason to delete it. The instruction is correct; the reason after the colon is not the reason.

### Reflowed `+` lines, wording unchanged since r1 (out of the strict delta)

#### F3 — P3 (overstated): "missing from the summary went from 12 to 0" measures the model's `completed`, not the stored summary
- Sentence: CHANGELOG.md:16-18 (same as F1).
- The stored row keeps a final-reply `report` Done over the model's `completed`: tree lib/fast-summary.mjs, mergeModelSummary
  docstring: "`completed`: a `report` Done is kept; otherwise the model's replaces it". A session with no observation past the
  low-signal filter gets no model call at all: tree hook-llm.mjs, `if (recentObs.length < 1) return outcome('no-obs')`. In
  reading 5's window that is 142 of 331 sessions (ab5/rows.json meta.drop.noObs = 142, windowed = 331), and 2 of the 30 sampled rows
  have a report-sourced `completed` (score.out split provenance:report n=2). In both cases the stored summary still holds only the
  last turn's account. rulers.md says so ("Not modelled … (D23)"); the CHANGELOG and README do not. Not false as worded ("the
  summary" can be read as the model's output); it reaches fewer sessions than the sentence suggests.

#### F4 — P3 (overstated): "reads each turn's last reply" means it reads an excerpt of most earlier replies
- Sentences: CHANGELOG.md:9-10 "One default changes: the session summary model reads each turn's last reply." (and the
  context-line bullet heads in both READMEs).
- tree hook-llm.mjs: earlier turns are cut to SUMMARY_TURN_HEAD 700 + SUMMARY_TURN_TAIL 300, the final turn to 2000 + 1000, and at
  most the first 4 + last 8 turns are shown. run/lens.mjs on reading 5's 30 sessions → `earlier-turn replies 30, of them >1000:
  23; finals >3000: 6/30; max reply 5156 code points`. The 12-turn cap never bites in this population (recompute.out:
  `population turns>12: 0 of 161 max 9`). Shorthand rather than a false claim.
