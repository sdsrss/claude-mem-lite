## Findings

### R2-1 · P1 · introduced by this delta · install.mjs:2001, 2006-2008, 2033-2038
"✓ ... the CLAUDE_MEM_DIR purged below" and "Done!" (exit 0) with nothing purged, when CLAUDE_MEM_DIR
names the link by another spelling.

Mechanism: `purgedBelow` (2001) compares `realpathSync(MEM_DATA_DIR)` with the target, so a
CLAUDE_MEM_DIR that reaches the target THROUGH the link (`$HOME/.claude-mem-lite/`, `$HOME/.claude-mem-lite/.`,
or the link reached via another path to HOME) is "the target". `MEM_DATA_DIR !== homeDir` is a string
compare and `resolveDataDir` does not normalise, so the trailing-slash spelling passes it. Line 2006 then
unlinks the link, the ✓ line promises the relocated purge, and the relocated purge (2033) runs on a
path that went away with the link: `statSync` -> ENOENT, `existsSync(MEM_DATA_DIR)` false, no line, no
`purgeIncomplete`. Result: Done!, exit 0, store + WAL + code + runtime/ all still at the target.
Real shape: README.md:1243 documents the default as `~/.claude-mem-lite/` (trailing slash), so
`export CLAUDE_MEM_DIR=~/.claude-mem-lite/` copied from the docs, or typed with tab completion, is this
case for any user whose ~/.claude-mem-lite is a link.
Parent 240da415, same cases J2/J3: "link is removed, nothing behind it was", "purge is incomplete", exit 1.
Falsifies "the link branch never reports the purge done".

### R2-4 · P3 · introduced by this delta · install.mjs:1994, 2001
An unresolvable link is named by `path.resolve`, which collapses `x/..` lexically without following
`x`, so the printed "target" can be a directory the link does not reach, and `purgedBelow` is computed
against that wrong directory. Y (`node scripts/cases2.mjs '^Y_'`): `~/.claude-mem-lite -> sub/../mem`,
`~/sub -> <outside>/a/b`, `<outside>/a` mode 000 (store at `<outside>/a/mem`), CLAUDE_MEM_DIR=`$HOME/mem`
(another store): `✓ Removed the link ~/.claude-mem-lite to <HOME>/mem, the CLAUDE_MEM_DIR purged below`,
`Relocated data purged from <HOME>/mem`, `Done!`, exit 0; the store the link pointed at stays and is
never named. Also falsifies "names the target as the link spells it": it prints a normalised absolute
path, not the spelling (an absolute or plain relative spelling happens to coincide). Constructed.

## Answers

Q1. The link branch removed nothing but the link in all link shapes tried: directory, file, chain,
relative, relative `../`, into HOME, dangling, unreadable parent, unremovable, self-loop, chain with an
unreadable middle (cases A–H, R, S, W, W2; GONE list = the link only). Deletions outside
~/.claude-mem-lite happened only under a CLAUDE_MEM_DIR the case set, and only claude-mem-lite-format
names: I, K, L, M, O, P, T, V, Y. One reaches through the link: P (R2-3), under a "nothing behind it was
removed" line. CLAUDE_MEM_DIR = the link spelled exactly as `$HOME/.claude-mem-lite` (J): correct,
incomplete, exit 1. Different directory (L): correct.
Q2. No: R2-1 (Done! with nothing purged, P1), R2-2 (✓ purged-below then left-untouched / Done! with
code left), R2-3, R2-4 contradictions or false lines. Plain-link outcomes A–H are truthful, exit 1, no
whole-directory advice.
Q3. The six tests fail on 2 of 8 non-equivalent mutants tried (R2-10); the author's own 10/10 list
(tasks/d825/mut-d811b.out) does not include the six survivors.

Claims: "never reports the purge done" — false (R2-1, R2-2 N/M/U, R2-4). "names the target as the link
spells it" — false for `x/..` spellings (R2-4); holds for plain ones and for the chain first hop (S).
"left to the relocated purge's own report" — false in the catch branch (R2-3), pre-empted by the ✓ line
and silent in R2-1. "a link it cannot remove is named with its target" — holds (H, O, P), except `null`
on the race (R2-7).

Also: `npx eslint install.mjs tests/install-lifecycle.test.mjs` exit 0; `npx prettier --check` same
files clean.
