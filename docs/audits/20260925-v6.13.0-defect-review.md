## P2-1: The green-stamp reporter certifies a `vitest run --exclude <glob>` run as "full suite passed"

- Where: scripts/green-stamp-reporter.mjs:17-30 (`refusalReason`), and :46 (`allIds` from `ctx.globTestSpecifications()`).
- Mechanism: vitest 5 appends CLI `--exclude` to the resolved `exclude`. The chunk contains `cliExclude = toArray(argv.exclude)` and `cliExclude) resolved.exclude.push(...resolved.cliExclude)`. So `globTestSpecifications()` returns the same shrunken set the run used, and `ranIds === allIds` holds. No refusal condition looks at `cliExclude` (or `dir`/`project`).
- Repro (in my tree, git-initialised, clean):
  ```
  node_modules/.bin/vitest run --exclude 'tests/[b-z]*' --exclude 'tests/a[abd-z]*' --exclude tests/activity.test.mjs
  #  Test Files  1 passed (1)   Tests  6 passed (6)       <- 1 of 431 files
  ls .git/mem-lite-green-stamp.json                       <- written
  node scripts/green-stamp.mjs check; echo $?
  #  full suite passed on this exact tree at 2026-09-25T21:14:07.678Z
  #  0                                                     <- pre-commit would skip npm test
  ```
- Why it is realistic: this repo's own review history uses exactly this flag to drop test files that are red in the reviewer's environment. docs/audits/20260914-v6.9.0-claims-review.md:65-66 runs `vitest run --coverage --exclude tests/pre-commit-hook-sync.test.mjs --exclude tests/suite-touches-no-repo-files.test.mjs`. In my extracted tree `tests/suite-touches-no-repo-files.test.mjs` is red, so "exclude the broken file and run everything else" gives a green stamp. Pre-commit then skips a suite that is red on that tree.
- The feature's own docblocks say a wrong YES is the one failure it can add, and that the run must cover "every test file the config collects". This run breaks that contract.
- The unit cases in tests/green-stamp.test.mjs (`refusalReason` it.each) cannot catch it, because they feed a hand-built `config` and never a real vitest config.
- Fix sketch: refuse when `config.cliExclude?.length`. Also refuse on `config.dir` and a non-empty `config.project`. Pin it with one real-vitest case, e.g. spawn `vitest run --exclude …` in a fixture and assert no stamp.
- Severity P2: maintainer tooling that ships to nobody, and CI still runs the full matrix on push.

## P3 findings

**P3-1: A later red run does not invalidate the stamp, and the stamp's age is never checked.** scripts/green-stamp.mjs:94-111 (`checkStamp`); the reporter only ever writes. Take a flaky or time-dependent test that goes red on the SAME tree after a green run. Pre-commit still reuses the older green stamp. `stamp.at` is printed but never compared with anything. Fix: have the reporter delete the stamp on any non-certifying full run of the same key, or cap the stamp's age.

**P3-2: Symlinks and gitlinks are outside the key.** scripts/green-stamp.mjs:60-64 filters with `lstatSync(...).isFile()`. Retargeting a symlink and running `git add` on it after a green run leaves both the key and `git diff --quiet` unchanged, so the stamp is reused. This is latent today: `git ls-files -s` in the shipping repo shows no 120000 or 160000 entries. An untracked, non-ignored symlink behaves the same way.

**P3-3: The key covers worktree files the commit may omit.** This is not a regression, because the old gate also tested the worktree.
- Untracked, non-ignored files are in the key (green-stamp.mjs:57) but not in the commit.
- With `git commit <paths>`, the hook's `GIT_INDEX_FILE` is HEAD plus those paths. A new file that is staged in the real index but not listed shows up as untracked, so `git diff --quiet` stays clean and the key includes it. The result is reuse on a tree the commit does not contain.
- The comment at green-stamp.mjs:14-16 ("the index and the tested tracked content are the same bytes") is accurate for tracked files only. I reasoned this through; I did not execute it inside a real hook.

**P3-4: The unbalanced-quote fallback defeats the per-statement check.** bash-utils.mjs:162 and :175. An apostrophe in a heredoc body or in a `#` comment unbalances the quotes. The code then falls back to the first-word rule. Checked with a RED vitest output fixture:
```
cat > tests/x.test.mjs <<'EOF'\n// don't regress\nit('a', () => {})\nEOF\nnpx vitest run tests/x.test.mjs   -> isHardError false (silenced)
cat > tests/x.test.mjs <<'EOF'\nit('a', () => {})\nEOF\nnpx vitest run tests/x.test.mjs                     -> true  (the test's own case)
sed -n 1,5p f # it's here\nnpm test                                                                        -> false (NEW: sed is now a read verb)
```
- The first line was also silenced before this change, since `cat` was already a read verb.
- The third line is a new silence, because the rule now treats `sed` as a read verb.
- tests/bash-utils-signif.test.mjs:198 pins the fallback, and the heredoc case at :187 passes only because its body has balanced quotes.
- The CHANGELOG line "Every statement and pipeline element is now checked" is not true for this input class.
- Fix: return `false` (not read-only) when the quotes do not balance, or strip heredoc bodies before splitting.

**P3-5: Some new "read" verbs execute or mutate.** bash-utils.mjs:31-48. `sed -i …`, `awk 'BEGIN{system("npm test")}'`, `sort -o f f` and `code-graph-mcp index --rebuild` (any subcommand) are all exempt. So are `$(...)` and `<(...)` contents: `grep x $(npm test)` and `diff <(npm test) exp` are exempt. All verified via `detectBashSignificance(...).isHardError === false` on a TypeError-plus-stack response. The practical impact is small, except for `code-graph-mcp <write subcommand>` failures, which now never trigger error-recall.

**P3-6: `isDismissalAt` false positives withhold credit from a lesson that was applied.** lib/citation-tracker.mjs:121-135. Each result below is a real call:
```
"#12: unrelated tests failed, but the lesson applied"        -> DISMISS
"#12 does not apply to tests but I applied it to lib"        -> DISMISS
"#12 n/a for lib/a.mjs; applied to lib/b.mjs"                -> DISMISS
"#12 unrelated-looking but applied"                          -> DISMISS
"#12 irrelevant rows are now filtered (as the lesson said)"  -> DISMISS
"#12 无关紧要的细节之外，已按它修复"                           -> DISMISS  (无关 has no boundary; matches 无关紧要)
"#12 与本次无关的部分已跳过，核心已采纳"                       -> DISMISS
"| #12 | n/a |"  /  "| #12 | applied | #13 | n/a |"           -> cite (tables missed; safe direction)
"#12 is not irrelevant here" -> cite (OK) ;  "#12 applied; #13 n/a" -> cite/DISMISS (OK)
```
Credit is lost only when every mention of the id in the session is a dismissal (see :142-146), so the blast radius is small. Tightening options: require the English markers to be followed by `\b` or end of clause, and exclude `无关紧要`.

**P3-7: Cite-rate calibers now differ between faces that the docs describe as one.**
- `citation-stats --sidechain` (mem-cli.mjs:2798 → aggregateProjectCiteRecall → computeThreadCiteRecall, lib/citation-tracker.mjs:1302 `includeDismissed: true`) still counts `#NN n/a`.
- README.md:251-253 and the CHANGELOG say "`citation-stats` per-face rates read lower". That is true of the default arm only, not `--sidechain`.
- `--sidechain` is also now on a different caliber from the `subagent` face (`collectSubagentSurface`, :1286, default excludes). The comment at mem-cli.mjs:2797 says "Same methodology, so comparable".
- Separately, `classifyCitationContext` (:224; its comment at :244-246 says "the same numerator the decay loop acts on") still counts dismissals. Its only callers are tests.

**P3-8: The LLM-visible adopt doc understates what `n/a` does.** adopt-content.mjs:92-94 says `'#NN n/a'` "算作已回应，但不算采纳，不会让它上浮". In the decay loop a dismissal is now exactly silence:
- it is excluded from `citedMain` (hook.mjs:1277) but stays in `injected`;
- so `uncited_streak` goes up and `cite_factor` drops to 0.5 / 0.4;
- and `cited_count` stays 0, which keeps the row eligible for `demote_pinned`.

"Counts as answered" is only true for the nudge gate (hook.mjs:1433). An agent reading this doc could reasonably take `n/a` to be rank-neutral. This is a wording issue; a Chinese clause saying it sinks like an uncited lesson would fix it.
