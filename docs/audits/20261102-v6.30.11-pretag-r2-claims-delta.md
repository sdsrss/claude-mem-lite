### Findings

**F1 (P1): `util.inspect` stores a context-BEGIN key even with no double quote anywhere.**

- **Quoted text:** "a diff in a single-quoted string (Python's `repr`, Node's `util.inspect`) whose removed or context BEGIN line has a double quote before the BEGIN (`PEM = """`)".
- **Why it is false:** by default `util.inspect` does not print one single-quoted string. Any string over about 76 characters prints as `'line\n' +` pieces, each quoted separately. In that form, a context BEGIN on a line without `'` is stored, even in a bare key file.
- **Synthetic keys** (`inspect` and `inspect({stdout})`): OpenSSH 10/22 cuts, encrypted PEM 18/33, PGP 22/34. Python repr of the same text stores 0.
- **Real keys** (`inspect({stdout})` of a rotated `id_key`): ed25519 8/17, ecdsa 12/21, encrypted RSA PEM 50/62. The raw diff stores 0 in each.
- **No outside cut is needed:** `util.inspect` cuts strings at 10,000 characters itself ("... N more characters"). Of the diffs where that cut lands inside the key, 6.30.11 stores key text in 4/5 (ed25519), 6/7 (ecdsa) and 30/31 (encrypted RSA PEM).
- **Mechanism** (`concat.mjs`, one cut): one single-quoted string keeps 0 key lines, the default split form keeps 2, the same split with double quotes 0, JSON 0.
- **Repro:**
  - `run.sh repr.mjs openssh,encpem,pgp raw,inspectFlat,inspect,pyRepr` (see the `none ctx` rows)
  - `run.sh realkeys.mjs`
  - `run.sh inspect-trunc.mjs`
  - `run.sh concat.mjs`
  - `run.sh one.mjs openssh none ctx inspect`
- **Output excerpts:**
  - `openssh none ctx … raw: c 0cuts 0/4490 ; inspectFlat: c 0cuts ; inspect: c 10cuts 2682/4490`
  - `ed25519 inspect 10k self-cut texts=5 6.30.11: 4 texts store`
