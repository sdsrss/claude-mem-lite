**P2-1: the verify skill marks a commit as not on the branch when its patch landed under another sha** — `commands/verify.md:76-82` (new in the range, so a regression).
The rule says exit 1 from `git merge-base --is-ancestor` means "an abandoned branch or an archive tag", and that either check "makes the note STALE". A cherry-pick, rebase or squash-merge also gives exit 1, but the code is on HEAD.
- Repro: `probes/verify-cherry.sh probes` prints `merge-base --is-ancestor exit=1`, `log --grep hits: 0`, `patch on HEAD? = f31d666`.
- Real shape, this repo (read-only git): local refs hold 91 commits that main cannot reach; `git log --cherry-mark` finds 71 of them patch-equivalent to a main commit. Example: 05d8a99b (reachable only from tag v2.0.0) and e094eacf on main.
- The maintainer's transcripts show worktree commits cherry-picked onto main (`git cherry-pick -n 0d896e3a`, `-n 0372f402`).
- Impact: wrong STALE proposals. The user still approves every change, which is why this is P2 and not P1.
- Fix: before calling a sha STALE, look for a patch-equivalent commit on HEAD (`git log --cherry-mark --right-only HEAD...<sha>`, or the commit subject via `--grep -F`).
