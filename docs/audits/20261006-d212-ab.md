## 结论

- 按预先登记的规则，**不发 rules 默认**：p=1.00 不满足 p < 0.05。
- 方向上 rules 组更高：主动记录 4 条对 0 条；从第二个会话起子代理都能看到引导，inject 组从来看不到。
- 但两组的主动记录都很少，88 个会话里一共 4 条。按这个基础比例，每组 12 个会话分辨不出 1/12 和 0/12，这个 A/B 在当前基础比例下没有判别力。

不能和 2026-09-29 的 §8.5 直接比较。那次 CLAUDE.local.md 组每条轨迹约 5 条，子代理场景 9/12 个会话有记录。两次之间：

- Claude Code 版本不同；
- 项目多了 AGENTS.md；
- 时间相隔一周，按测量规则 2 不能相减。

为什么现在基础比例这么低，没有测。

## 顺带发现

- **`claude -p` 下插件的 MCP 工具默认被拒**（Claude Code 2.1.292）。
  - 影响：无人值守运行的用户，引导让模型调用的 `mem_save`/`mem_defer` 全部失败，模型也不会改用 CLI。
  - 交互模式下用户会看到授权提示，不受影响。
  - 记为待办。
- 测量仪器：第一轮的计数只看"有没有调用"，没有看结果，所以 13 次被拒的调用在初稿里算成了记录。修订后的计数器在第一轮数据上读出 0/12 对 0/12，说明它能分辨被拒和成功。
