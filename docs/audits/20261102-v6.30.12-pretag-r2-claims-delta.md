### Findings

**F1 [P2] A PEM key that gained a passphrase is still stored in `git diff`, including under `PRIVATE_KEY=-----BEGIN …`, and no list names it.**
- **Sentences:** "…under `PRIVATE_KEY=-----BEGIN …` … every line of a cut-off key was kept … These are erased now." Also the "Still stored" list, where no item (and none in 6.30.11's list) covers this.
- **What is false:** adding a passphrase to a PEM key (`ssh-keygen -p -m PEM`, PKCS#1 or SEC1) keeps the same BEGIN line. `git diff` therefore shows BEGIN as a context line, then the old body as removed lines, then the new Proc-Type, DEK-Info and body as added lines.
  - Cut before the END, 6.30.12 stores every line of the new key that is in the cut. This happens in a `.env` under `PRIVATE_KEY=`, in a Terraform heredoc, and in the bare key file.
  - The label is not the cause: the same diff without a label is stored too.
- **Same instrument, the release's own measurement:** 45,500 of the 728,014 windows 6.30.12 keeps are this shape, not item (c). They come from the author's pkcs1_rsa → pkcs1enc_rsa rotation (`deploy.env` and `main.tf`, in `git diff` and `git log -p`, all five wrappers).
- **Reproduce:** `node …/scripts/repro-enc-rotation.mjs`
  - RSA `.env`, raw and JSON: `{"cuts":28,"present":400,"old":325,"rel":325,"wholeKeyKeptCuts":25}`. `main.tf` and `id_rsa` read the same; EC gives 6/6.
  - Controls: OpenSSH keys (`repro-enc-rotation-openssh.mjs`) and the reverse change, passphrase removed (`repro-dec-rotation.mjs`), give rel 0.
  - `split-728k.mjs`: `{"kept":728014,"concat":682514,"other":45500,"otherOldKept":45500}`.
- **6.30.11:** stores the same lines, so this is not a regression.

**F2 [P3] A key body line in git's hunk-header function context is stored and not listed.**
