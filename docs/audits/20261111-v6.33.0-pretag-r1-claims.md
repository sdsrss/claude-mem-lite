## Findings

**F1 — P2, new in 6.33.0. A re-run purge prints `Done!` and leaves claude-mem-lite's own `runtime/` behind.**
- Claims it breaks:
  - CHANGELOG.md:18-20 "A purge that leaves anything of its own behind … says the purge is incomplete and exits 1 instead of printing `Done!`."
  - README.md:248-250 "exits 1 without `Done!` when the purge is incomplete"
  - README.zh-CN.md:208, the same claim.
- Cause: install.mjs:2231-2236. When `left` is non-empty (runtime/ is kept because it sits beside a user's file), the store is still removed, because `storeKept` looks only at `failed`. A re-run then finds no store and takes the install.mjs:2051-2053 branch: "has no claude-mem-lite.db — left untouched" → `Done!`, exit 0. dc747ced M2 fixed this for `failed` entries only, yet its own comment says the store is "how a re-run knows the directory is claude-mem-lite's".
- Repro: `probes/p18-purge-rerun.sh` follows the run-1 advice ("Remove it yourself once nothing of yours is"): the user moves notes.txt out, then runs the purge again.
  ```
  == run 1   ⚠ Left runtime in …/reloc … ✗ Uninstalled, but the purge is incomplete   exit=1   dir now: ./notes.txt ./runtime ./runtime/hook-state.json
  == run 2   ⚠ CLAUDE_MEM_DIR (…/reloc) has no claude-mem-lite.db — left untouched.   Done!   exit=0   dir now: ./runtime ./runtime/hook-state.json
  ```
  Also seen in p02 scenario A.
- v6.32.0 removed the whole directory, the user's file included, on run 1, so this two-run sequence is new.

**F2 — maintainer record (not shipped; P3 by the rubric). "0 of the 76 suite queries return nothing before this tier" is false.**
- Where it appears: commit 76d7174f, and docs/measurement/findings.md:1641-1647. The record says denoise-ab "never ran the tier" and "neither population … has one".
- Re-measured with `probes/p15-reach.sh`, which compares the shipped search-engine.mjs with a copy whose tier block is disabled: `total: 8/76 reach the tier (reach.mjs's condition counts 0)`.
  - All 8 are in identifier_parts, for example "LayoutEffect" → `layouteffect*` and "did mount" → `mount*`.
  - The tier fired on each of them and returned 0 rows. So Δ=0 holds, but the ruler did run the tier.
- Root cause: tasks/converge-r29/reach.mjs and real-reach.mjs:55 count a reach as `ctx.effectiveFtsQuery === forms`. The shipped tier never sets that field (search-engine.mjs:685, "sets neither … nor effectiveFtsQuery"), so both probes read 0 by construction.
- Consequence: the real-search figure "tier fired on neither" comes from the same blind counter (real-reach.mjs:56-58), so the probe cannot back it.
