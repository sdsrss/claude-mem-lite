# v6.35.2 pre-tag review — defects lens

Candidate `57df7b5ae9e8c8ce13e8119804fd7b093f8bf399` (HEAD confirmed with `git rev-parse HEAD`). Range `v6.35.1..57df7b5a`,
product diff `lib/transcript-digest.mjs`, `lib/persist-reminder.mjs`, `package-lock.json`. Trees built with `git archive`
under `~/.cache/tmp/rv-6352-defects/{cand,v6351,v6350}` with node_modules copied in; every probe ran with a sandbox
HOME, `CLAUDE_MEM_DIR` / `CLAUDE_MEM_RUNTIME_DIR` in that directory, LLM keys and proxies unset, no `claude` on PATH,
`ulimit -v` set. Host: the dev box (Node v26.8.1). It parses 478 MB of JSONL in 0.57 s; issue #53's reporter measured
1.6 s for 475 MB, so that host is about 2.8x slower.

Probes are in `~/.cache/tmp/rv-6352-defects/probes/`: `gen.mjs` (synthetic transcripts), `digest.mjs` (direct call),
`stop.sh` (whole Stop hook, peak RSS from VmHWM), `diff.mjs` (candidate vs v6.35.1), `sub.mjs` (subagent throw),
`g3.sh` / `mkmix.sh` (mixed trees), `poison.mjs`, `zero.sh`. Recreate the transcripts with
`node probes/gen.mjs data/t1024.jsonl 1024` (likewise `t100 100`, `t512 512`, `s100 100 400 1`). I deleted the 2.1 GB
data set and the trees after the run.

## Findings

### F1 — P2 — When the state cannot be saved, Stop reads with no budget and runs past its 5 s timeout on large transcripts

- Where: `lib/transcript-digest.mjs:122-127` (the second `digestPass` with `{ left: Infinity }`), called from
  `hook.mjs:1497`. The Stop timeout is `hooks/hooks.json:106` (`"timeout": 5`). The DB lock deadline is
  `lib/time-constants.mjs:72` (`HOOK_DB_DEADLINE_MS = 3500`, counted from process start).
- Reproduce: plant a directory at each version's own state name, which drives `saveState(...) === false`, then run the
  whole Stop hook:
  `mkdir -p rt-dir/$(node -e "import('./cand/lib/transcript-digest.mjs').then(m=>console.log(m.digestFileName('<abs>/data/t1024.jsonl')))")/x`
  (the same for v6351's name), then `probes/stop.sh <tree> <abs>/data/t1024.jsonl <abs>/rt-dir`.
- Measured (whole Stop hook process, same input, run back to back; two repetitions for 512 MiB and 1 GiB):

  | transcript | candidate | v6.35.1 | v6.35.0 |
  |---|---|---|---|
  | 100 MiB | 0.75 s, writes results | 0.46 s, writes nothing ("still catching up") | 0.81 s, 388 MiB RSS, writes results |
  | 512 MiB | 2.88–2.95 s, 174–187 MiB RSS, writes results | 0.42–0.46 s, 109 MiB, writes nothing | 1.69–1.79 s, 597 MiB, writes nothing (no "citations:" line) |
  | 1 GiB | **5.54–5.60 s**, 229–230 MiB RSS | 0.42–0.47 s, 110 MiB, writes nothing | 3.20 s, 1108 MiB, writes nothing |
  | 100 MiB main + 400 subagent files (404 MiB) | 1.18 s | 0.47 s | 1.39 s, 421 MiB |

  Direct `digestTranscript` alone on 1 GiB with an unwritable dir took 5551 ms, peak RSS 179 MiB.
- Expected: the module header and the CHANGELOG describe a per-Stop byte budget, and Stop has a 5 s timeout. Saw:
  memory stays bounded, but time grows linearly with the unread part, with no cap. On this host Stop crosses 5 s at about
  0.9 GiB. Scaled by the 2.8x parse ratio above, the projection is about 330 MiB on the reporter's host, which means the
  reporter's own 475 MB transcript. That figure is a projection, not a measurement.
- Consequence: the project records that a hook past its timeout is killed together with its output
  (`hook.mjs:289-293`). On a kill, the citations the fallback exists to write are not written. The steps after
  `trackCitationsAtStop` in `handleStop` (`writeFastSummaryBaseline` at `hook.mjs:1904`, `recordStopTurnReply` at 1915,
  `spawnBackground('llm-summary', …)` at 1936) are also lost, on every turn for as long as the condition holds. v6.35.1
  finished the whole Stop in 0.47 s on the same input. At 512 MiB the digest uses 2.9 s of the 3.5 s DB-lock deadline,
  so any lock contention after it drops the turn's writes.
- Shape: REAL in principle, not reproduced here. The trigger is a state write that fails while the rest of Stop runs:
  disk full, quota, or inode exhaustion. `atomicWriteFileSync` creates a new temp file of 180–500 KB on every Stop,
  while `getSessionId` writes nothing when an unexpired session file exists. Large transcripts are REAL (issue #53:
  475 MB). The measured trigger, a planted directory, is CONSTRUCTED. Neither trigger the CHANGELOG names reaches this
  branch in the hook:
  (a) two installed versions now use separate names, so the fallback is not involved;
  (b) an owner-unwritable runtime dir is chmod'ed back to 0700 when `hook-shared.mjs:388-390` is imported (observed:
  `rt-ro` created 555 became `drwx------` and the state was saved). A runtime dir Stop cannot write to makes Stop throw
  at the session-file write before the digest, seen as
  `[ERROR] stop: ENOTDIR … session-home--proj@h1478.tmp-691120` with no `citations:` line.
- Severity: the consequence (a hook killed at its timeout every turn) is hang-class, but the trigger needs a failing
  state write and a transcript of several hundred MiB at once. v6.35.0 already had the same unbounded-time class (3.2 s
  and 1.1 GB at 1 GiB). Rated P2. Uncertain whether, on a really full disk, the DB writes before the digest
  (`markSessionCompletedAndSaveHandoff`) survive long enough to reach it.

### F2 — P3 — A subagent file a rule throws on: its cites are dropped while other files' `seen` of the same id is kept, and a large such file starves the files after it

- Where: `lib/transcript-digest.mjs:142-150` (`catch { continue; }`).
- Reproduce: `probes/sub.mjs`. Agents A and B are both handed `#801`; only B cites it, and B then holds
  `{"type":"assistant","isSidechain":true,"message":{"content":[null]}}`.
- Seen: `{"candComplete":true,"candInjected":[801],"candCited":[],"v6351":"threw: TypeError","withoutPoisonCited":[801]}`.
  The candidate returns a complete digest whose subagent face scores 801 as injected and uncited. The full read cites
  801, v6.35.1 writes nothing, and v6.35.0 empties the whole face (`hook.mjs` of v6.35.0, `collectSubagentSurface` in a
  try that falls back to empty sets). The D#853 F8 test added in this range (`tests/e2e.test.mjs`) states that a decided
  row is then kept by the session's idempotency key. I did not check that separately for this face.
- Starvation: a poisoned file of 6179 B sorted before a good one, with a 2000 B budget, gives
  `["inc","inc","inc","C(…)","inc","inc","C(…)",…]`. Each cycle the poisoned file is re-read from byte 0, uses the
  budget, and leaves the files after it incomplete, so results are written on 1 Stop in 3. The claim "the other
  subagent files and the main results are answered" holds only on the Stop where the poisoned file throws.
- Shape: CONSTRUCTED. The only throw in the two subagent rules is a `null` content block, at `block.type` in
  `lib/citation-tracker.mjs:212`. `addSubagentPromptIdsOf` uses `x?.text`. I did not read real transcripts to confirm
  that none carries a null block.

### F3 — P3 — The new shape check does not check Set members; a planted non-number member passes it and makes decay throw on every Stop

- Where: `lib/transcript-digest.mjs:272` (`if (model instanceof Set) return v instanceof Set;`).
- Reproduce: `probes/poison.mjs` writes a state, then appends `{"planted":true}` to `files.main.acc.injectedMain.pretool.$set`.
  Two Stops (`probes/stop.sh cand poison/t.jsonl poison/rt`) each log
  `[ERROR] handleStop-citation-decay: RangeError: Too few parameter values were provided`. On an unplanted state
  (control) the same Stop logs `citation-decay: touched=0 promoted=0 demoted=0`. The direct digest returns
  `"pretool":[101,{"planted":true}]` with `complete: true`.
- Expected (CHANGELOG): "A saved progress file of another shape is read again from the start … (a development checkout
  across commits, or a hand edit)". Saw: this hand edit is resumed and stops decay for that session on every Stop. The
  state is rewritten each Stop, so its mtime stays fresh and the 24 h GC never removes it while the session runs. v6.35.1
  behaves the same, so this is not a regression.
- Shape: CONSTRUCTED (hand edit). No accumulator in the code puts anything other than an integer into a Set
  (`addObsId` and every rule check `Number.isInteger`).

### F4 — P3 — `loadState` reads any non-regular file at the state path to its end (pre-existing; the FIFO fix covers only the open)

- Where: `lib/transcript-digest.mjs:193-207`. `advance()` checks `fstatSync(fd).isFile()` first (line 239);
  `loadState` does not.
- Reproduce: `ln -s /dev/zero rt-zero/<state name>`, then `probes/zero.sh <tree>`. Candidate and v6.35.1 both returned
  `complete: true`, but with peak RSS 2570 MiB, which is where the process hit my 4 GB `ulimit -v`. Without the cap the
  read is bounded only by the allocator.
- The FIFO claim itself holds: with a FIFO at the state path the candidate's whole Stop returned in 66 ms and replaced
  the FIFO with a regular file. v6.35.1 was still blocked after 15 s, ignored SIGTERM (the hook's SIGTERM handler
  cannot run during a blocking open), and I stopped it with SIGKILL by PID.
- Shape: CONSTRUCTED (a planted symlink, or a FIFO whose writer keeps writing). Pre-existing.

## Answers to the brief's questions (no further findings)

1. **Same input, resumable state:** `probes/diff.mjs` grew 40 transcripts by 40 steps each (MAIN_RECORDS/SUB_RECORDS
   records, partial last lines, subagent appends, budgets 60 B to unlimited), and the candidate and v6.35.1 each kept
   their own state. Seed 7: 1600 calls, 1114 compared, **0 mismatches**, `complete` equal in every call. Seed 99:
   1112 compared, 0 mismatches. Mutation check: a mutant that drops one subagent file and rejects non-empty Sets gave
   149 mismatches and 714 `complete` differences, never completed resumption in 10 000 calls, and never completed
   alternation. So the ruler can say no. Inputs that throw, hang or use unbounded memory: only F1 (time), F3 (a decay
   throw, caught) and F4 (memory).
2. **No-save time and memory:** see the F1 table. Memory stays bounded (≤ 230 MiB RSS against v6.35.0's 1108 MiB);
   time does not.
3. **Accumulation and GC:** one file per (version, transcript), 180–500 KB in these runs (500 KB with 400 subagent
   files). Every version from 6.35.1 on removes any `transcript-digest-*` file older than 24 h, its `.tmp-<pid>`
   leftovers included, unconditionally at SessionStart (`hook.mjs:3100`, prefix test at line 1998). 6.35.0 does not, as
   the CHANGELOG states. Alternation: the candidate and v6.35.1 sharing one runtime dir, at 500 B per call, completed in
   120 calls each, with two separate files. I found no other way for them to reset each other. The names differ by
   construction, and during a swap `package.json` goes last, so candidate code labelled `1:6.35.1` writes
   `hash("1:6.35.1\n"+path)`, never v6.35.1's `hash(path)`. Two development checkouts of one version still share a file
   and a rule change that keeps the shape is not detected (development only, as the header says).
4. **Own state failing its own check:** not found. A 30-turn fixture in which every accumulator is non-empty, plus 3
   subagent files, at 500 B per call, completed in 150 calls, and its answers equal a one-shot read. Empty collections
   round-trip as `{"$set":[]}` → `Set`. Counters only `++` or `+=` numbers. The mutant above shows the probe catches a
   self-rejecting check.
5. **One subagent file throwing:** nothing is double counted, and the main record is untouched (read first, and records
   are not shared). Lost: that file's cites, which can flip a verdict (F2). Left behind: no record, so it is re-read from
   byte 0 each time and can starve later files (F2).
6. **`detectUnpersistedDecision` callers:** the only one is `hook.mjs:1806`, which passes `d.persistence.count`. That
   is always a number: a fresh `init()` or a shape-checked `{count:number}`, and the hook returns before G3 when the
   digest is incomplete. No caller takes the transcript branch on every Stop. Whole hook, two hooks in a row
   (UserPromptSubmit `方案 B 拍板，开工`, then Stop) on v6.35.0, v6.35.1, the candidate and 12 mixed trees:
   `decisionSignal` is `null` with a `mem_save` and `"拍板"` without one, everywhere. Control (v6.35.0 hook with
   v6.35.1's persist-reminder) gives `"拍板"` with a save, so the check can fail.
7. **hono:** a resolve hook on `@modelcontextprotocol/sdk/server/mcp.js`, `server/stdio.js` and `types.js`, on
   `server.mjs` run to exit, and on `cli.mjs recent` saw no hono module. Control: `server/streamableHttp.js` loads
   `@hono/node-server` and `hono`. No shipped file names either package. `scripts/write-shrinkwrap.mjs` on the
   candidate lock keeps `hono 4.13.18` and `@hono/node-server 2.1.8` as prod entries (95 kept, 202 dev dropped). No
   behaviour change in them reaches the shipped runtime. Per its own comment, `scripts/smoke-tarball.mjs` installs with
   `npm install <tgz>`, which ignores the shrinkwrap, so the smoke run does not verify the pins.
8. **Mixed trees at run time:** `swap-mixed-tree.mjs` passes at all 171 split points for both pairs (run with REPO
   pointed at the repository, read-only). Run time: every distinct mixed state (v6.35.0 → candidate after swap index
   2, 4, 79, 80, 86, 108, 110, 111, 163; v6.35.1 → candidate after 2, 86, 111) ran UserPromptSubmit and Stop. Each gave
   no `[ERROR]` from citation code and a cite-recall payload byte-equal (minus `savedAt` and `project`) to the
   candidate's. Every lib export the v6.35.0 hook imports from the changed modules has an unchanged parameter list,
   except `detectUnpersistedDecision`, which the candidate now accepts in both forms.
