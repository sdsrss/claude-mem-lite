## Findings

### F1 — P2 — not a regression (new path) — a turn split by a mid-turn compaction: the reply goes to the next session, the session that asked never gets it
- Where: hook.mjs:1289-1306 (`recordStopTurnReply` keys on Stop's `getSessionId()`), hook.mjs:3351
  (SessionStart(compact) mints the next session mid-turn), lib/turn-replies.mjs.
- Mechanism: an automatic compaction can fire inside a turn. SessionStart(source=compact) mints session B
  and spawns A's summary worker at once. The turn continues; its Stop runs under B, where
  `MAX(prompt_number)` is NULL, so the reply is recorded as B's turn 0. A's record never receives that
  turn's reply, and no later worker for A runs, so A's summary keeps the reply from before the turn as its
  final reply. B's summary gets a reply to a request it does not list.
- Evidence: da129dc9-413e-4ee2-9870-b7055798cedc.jsonl: notice turn starts 08:46:45Z, auto
  `compact_boundary` 12:19:49Z inside it (line 2727), host Stop 12:42:13Z (line 3387, text "Now waiting
  on three things: ..."). Store: A = hook-dev--claude-mem-lite-52dc8acf (prompt 1 at 05:07, last Stop
  before the turn 08:06:14), B = hook-dev--claude-mem-lite-ae7eb63e started 12:19:49, first prompt
  14:17:13. Under the shipped code the 12:42 reply lands in B as number 0; A's final reply stays the
  08:06 one. Second case: f59b4686-886c-46fd-9a0e-ddd444b78abf.jsonl line 5233 (auto boundary
  12:04:19Z, B = hook-dev--claude-mem-lite-cadd6605 started 12:04:19, prompt_counter 0).
- Prevalence (scripts/compact.mjs, scripts/turnctx.mjs): 66 compactions (52 manual, 14 auto). Inside a
  turn: 2 of the 14 auto ones (both in notice-driven turns running 3.5-6 h); the other 12 auto ones are
  "Compacted while idle", between turns. 2 of 1,942 host Stops. Manual: 0 that split a stored prompt's
  turn (one /compact cut a running turn in gsd-lite 2de0bce7 line 3199; that turn had no Stop at all).
- Not affected: a prompt queued during /compact. The first stored prompt after each compaction was stored
  under the new session in 43 of 43 cases (scripts/postcompact-prompt.mjs, 44 matched; the 44th is a
  /loop prompt stored before the /compact, misread by my 5-minute window).
- 12 h lazy expiry, the other way a turn can straddle a rotation: upper bound 7 of 1,942 Stops by
  transcript time (scripts/expiry.mjs, resumes not detected); the store shows 0 turns where a later
  session's first observation falls between a prompt and its Stop without a compaction
  (scripts/expiry-db.mjs).

### F2 — P2 — not a regression (new path) — a Stop that loses the write-lock race records no reply, though recording needs only a read
- Where: hook.mjs:1920-1940. `recordStopTurnReply` sits in the same `try` as
  `markSessionCompletedAndSaveHandoff` (an UPDATE). When another process holds the write lock past
  HOOK_DB_DEADLINE_MS (3,500 ms), the UPDATE throws SQLITE_BUSY, the catch logs "this turn was not
  recorded", and the reply is skipped. The worker is still spawned (by design) and summarizes with the
  previous turn's reply as the final reply, while the user prompts list the unanswered request. The
  contract says a failed record must not affect Stop's other steps; the reverse (another step's busy
  failure dropping the record, which only needs `SELECT MAX(prompt_number)` and a file write) is not
  handled.
- Repro: `HOME_BASE=$PWD bash scripts/busy-stop.sh` (sandbox HOME; a second process holds
  `BEGIN IMMEDIATE` for 8 s during the second Stop) prints `record: ["turn 1 reply"]`: turn 2's
  "turn 2 reply: docs done" is missing.
- Prevalence: not measured. runtime/hook-errors/*.jsonl holds 0 lines with "locked by another process";
  the WARN goes to the debug log only, so the count is unobservable here.

### F3 — P3 — not a regression (new path) — the transcript-tail fallback runs on the current host whenever the last assistant message has no text, and can record another session's reply; "an empty field records nothing" never happens
- Where: hook.mjs:1261-1275 (comment "Kept as given, '' included: an empty one means the turn ended
  without text"), hook.mjs:1289-1296 (fallback when the field is absent),
  lib/summary-extractor.mjs:113-126 (`extractTailAssistantText`: last text-bearing assistant entry of the
  whole file; no compaction/session bound, no `isSidechain`, `<synthetic>` or `isApiErrorMessage`
  filter), tests/e2e.test.mjs:3516-3517 (sends `last_assistant_message: ''` as "the host says so").
- Mechanism: per the host code quoted above, 2.1.322 omits the field instead of sending ''. The hook
  then reads the transcript tail, which is the previous turn's reply, or, across /compact or a resume
  (both keep the same transcript file), the previous memory session's reply. Session ownership of the
  record then depends on the transcript, contrary to the D#825 design note.
- Repro: `HOME_BASE=$PWD bash scripts/fallback-leak.sh` (real hook processes, sandbox HOME): session A
  records "SESSION-A REPLY: backoff fixed, 8/8 pass."; /compact mints B; B's prompt; a Stop without the
  field after a tool_use-only assistant record. Output:
  `A record: ["SESSION-A REPLY: backoff fixed, 8/8 pass."]` and
  `B record: ["SESSION-A REPLY: backoff fixed, 8/8 pass."]`.
- Prevalence: 0 of 1,942 host Stops here had a text-less last assistant record (scripts/stops.mjs), and
  0 ended on a `<synthetic>` or API-error record (scripts/synthetic.mjs). On a host that predates the
  field, every Stop takes this path.

### F4 — P2 — not a regression (ruler) — `stopReplies` does not rebuild what the shipped Stop records on 17 of 183 transcripts
- Where: benchmark/summary-events-ab.mjs:121-160 (`stopReplies`), tests/summary-events-ab.test.mjs:112.
- Method (scripts/ruler-vs-stop.mjs): per transcript with stored prompts (183), prompts from the store by
  cc_session_id. Ruler = `stopReplies(entries, {start:-Inf, end:Inf, prompts})`. Shipped = at each host
  Stop record, the last assistant record's text (fallback: last text) under the number of prompts stored
  by then, last wins. The comparison ignores session splitting, which affects both sides the same way.
  Result: 17 of 183 differ (15 have ruler-only replies, 13 have shipped-only replies); 18 on a later
  rerun because the live transcript grew.
- Causes found (scripts/rvs-cause.mjs, rvs-cause2.mjs, meta-turns.mjs, rvs-one.mjs):
  a) /loop and ScheduleWakeup prompts are `isMeta: true` user records (`system/scheduled_task_fire`
     before them). UserPromptSubmit stores them: 13 of 13 here, in 8 transcripts. The host fires Stop at
     the end of the turn before them. The ruler skips meta records (line 154), sees no turn start, and
     overwrites that turn's final reply with the next turn's text. Example 7d930de8 (rvs-one.mjs): the
     host's n=1 final is "只剩第 2 轮 delta 评审还在跑…" (18:24:09); the ruler keeps the older
     "第 1 轮评审发现的问题已修完…" for n=1. Treating stored meta prompts as turn starts alone takes the
     differing transcripts from 18 to 11 (scripts/ruler-fixed.mjs, first two rows).
  b) The ruler records Stops the host never fired. It treats any following user record or boundary as a
     Stop: synthetic `"No response requested."` records (`model: "<synthetic>"`, 7 cases, e.g.
     dbc97cf7 line 1255; they replace the turn's real reply under the same number), a user interrupt (1,
     00f7749d line 43-44: the partial text "of 0 / 0 tokens<budget:token_budget>…" becomes turn 1's
     reply), a turn cut by a typed /compact (1, gsd-lite 2de0bce7), and the 2 mid-turn auto compactions
     of F1 (line 150 calls `stop()` at every boundary).
  c) Smaller: the number is "prompts stored by the last text's timestamp", not `MAX(prompt_number)` at
     Stop time; `start` is `sdk_sessions.started_at_epoch`, which for a lazily minted session is its
     first prompt, so its number-0 replies are dropped; no scrub, trim or 12,000 cut (no byte effect
     below 12,000, see F5 and the idempotence check).
- Impact: arm C of the D22 A/B and the equivalence check (tasks/d825/equiv.out, "13 of 30 differ from
  the record") treat this ruler as the record. The commit claim "the ruler reads them as Stop records
  them" does not hold for (a) and (b).
- The test meant to pin (a) cannot fail: mutation X7 (meta user records start a turn) survived
  tests/summary-events-ab.test.mjs 24/24, because its only meta record follows the turn's text.

### F6 — P3 — not a regression — "never creates the runtime dir" is false under a race, and the dir comes back at 0755
- Where: lib/turn-replies.mjs:71-79 checks `existsSync(runtimeDir)`, then reads, then calls
  `atomicWriteFileSync`, which runs `if (!existsSync(dir)) mkdirSync(dir, { recursive: true })`
  (lib/atomic-write.mjs:49-50). That recreates the runtime dir and its missing parents at
  0777 & ~umask, not the 0700 that hook-shared.mjs:388-391 enforces. Separately, every Stop process
  already recreates RUNTIME_DIR when it imports hook-shared.mjs:388-391 (it is not a background
  worker), so the guard covers only the window after import.
- Repro: `PROBES=$PWD node scripts/toctou.mjs` (deletes the data dir from inside the record's read,
  as `uninstall --purge` would) prints
  `{ wrote: true, runtimeRecreated: true, mode: '755', files: [ 'turn-replies-sess.json' ] }`.
- Prevalence: a window of microseconds between `existsSync` and the write. Constructed.

### F10 — P3 — constructed on this host — without CLAUDE_PID, two processes in one project write one record without a lock
- hostScopeSuffix() falls back to the per-project session file when CLAUDE_PID is absent (hook-shared.mjs
  418-425). Both processes then share the memory session and the prompt counter, and
  recordTurnReply's read-modify-write (lib/turn-replies.mjs:73-79) is unlocked. One process's reply

  documented pre-CLAUDE_PID session merge. This host sets CLAUDE_PID: every session file in
  runtime/ carries `@h<pid>`.
