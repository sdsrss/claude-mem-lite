### P2

**F1. A red node:test run is classified as green when another run in the same command printed "fail 0"** (a regression from main)
- bash-utils.mjs:674-684. The new label-first alternative `^[ \t]*(?:ℹ|#)[ \t]*fail[ \t]+0[ \t]*$` sets
  hasGreenTestSummary when ANY summary in the output reads `fail 0`. hasHardErrorSignal
  (bash-utils.mjs:680) only lists ERR!/panic/traceback/…/AssertionError/TypeError:/SyntaxError:,
  so a plain `Error:` with a stack trace does not rescue it. Then isError=false, which also forces
  isHardError=false.
- Repro. Real node 22 output from two runs, one green and one throwing `new Error('boom: total mismatch')`.
  The same shape comes from `npm test --workspaces`, `npm test && npm run test:e2e`, or a per-package loop:
  ```
  (cd g && node --test); (cd r && node --test)   # output contains "ℹ fail 0" … "ℹ fail 1" … "Error: boom"
  detectBashSignificance({command:'npm test 2>&1 | tail -30'}, out)
  HEAD (80335a4): {"isError":false,"isHardError":false}
  main          : {"isError":true,"isHardError":true}
  ```
- The same mechanism, in one run: a node:test run whose only failures are timeouts prints
  `ℹ fail 0` + `ℹ cancelled 1` and exits 1. Once piped (so PostToolUse fires) it reads HEAD
  isError=false, where main read isError=true. Verified with a real `node --test` timeout
  fixture (exit=1).
- Impact: error-triggered recall (hook.mjs:798, gated on isHardError) no longer fires. Rule-2
  significance (Bash isError && isTest) and importance=3 are lost. The episode summarizer and
  the handoff see a passing run.
- Fix direction: exempt only when no `fail [1-9]` / `cancelled [1-9]` summary appears, and add
  HARD_ERROR_RE's stack-frame arm (`\n\s+at\s+\S`) to the hard-signal list.
- Severity is a judgment call. It is a real error read as green, which the task names
  explicitly, but it needs a multi-summary output or a timeout-only failure.

### P3

**F2. The edge fallback reproduces the package.json noise on the episode shape that motivated the fix** (not a regression vs main, but the fix is incomplete)
- hook-llm.mjs:1221 (`files: edgeFiles.modified.length > 0 ? edgeFiles.modified : episodeFiles`) and
  hook-handoff.mjs:410 (Key Files, same rule). When an episode's only edit is to a path the capture
  drops, modified comes back empty. Examples: the host auto-memory, which d6c6b17 now drops, or the
  scratchpad. The code then falls back to the "read-only discovery" branch, and the lesson/event
  edges plus handoff Key Files become everything the episode READ.
- Probe: Read package.json, Read README.md, Write ~/.claude/projects/-w-app/memory/MEMORY.md gives
  `modified: [] -> edges / Key Files: [package.json, README.md]`.
- The episode is still significant (rule 1). utils.mjs:162 isEditEntry and hook.mjs:767 isSignificant
  key on EDIT_TOOLS, not on files, and explainSignificance returned `{significant:true, rule:1}` for a
  Write whose files were [].
- Fix: fall back to the read set only when no entry is an edit. An edit whose files were all dropped
  should yield no edges, and arguably should not make the episode significant.

**F3. The TDD-red gate treats every file of a project under a `test/`, `tests/`, `spec/` or `__tests__/` ancestor directory as a test file**
- lib/cite-back-hint.mjs:134-135. TEST_FILE_RE runs on ABSOLUTE paths, and `(?:^|[\\/])(?:tests?|__tests__|spec)[\\/]`
  matches an ancestor segment.
- Probe: the episode is Edit src/money.js, then a hard failure, then Edit src/money.js.
  `/home/u/work/app` gives NUDGE, but `/home/u/test/app` and `/srv/spec/app` stay silent.
- Result: in such a project, every edit-then-fail episode is silenced (a false negative on an
  advisory nudge). Fix: match on the path relative to the project root, or on the last segments only.

**F4. Handoff "Recent activity" drops genuine piped failures that HARD_ERROR_RE does not name**
- hook-handoff.mjs:59. `failed = e.isHardError`, which is false for `go test … | tail`
  (`--- FAIL` / `FAIL`), `cargo test | tail` (`panicked at` — the `\bpanic\b` word boundary does not
  match it) and a pytest `-q` tail. Probe: isError=true, isHardError=false for the go and cargo
  fixtures, so on main these were listed and at HEAD they are not.
- PostToolUse only sees exit-0 (so piped) runs, and piping is the common agent shape. This is a
  trade-off against the green-run noise, but it was never stated.

**F5. The isolation downgrade can latch on a transient auth error for the life of a long-lived process**
- haiku-client.mjs:621. AUTH_REJECTION is unanchored to any flag (`authentication_error|oauth token`),
  and compatRetry's onSuccess (haiku-client.mjs:643) sets `_isolationOk=false` process-wide.
- Probe: `_isIsolationRejection('API Error: 401 {…"authentication_error","message":"OAuth token has expired…"}') === true`.
- A transient expired or racing OAuth refresh whose plain-args retry succeeds disables isolation for
  the rest of the MCP server's lifetime. The measured ~32.7k vs ~8k token cost then returns silently,
  behind a debugLog WARN only. This is the same class the FLAG_TOKEN comment (haiku-client.mjs:596-604)
  warns about for 529s.
- Also, short-lived hook processes never keep the cache. An apiKeyHelper user therefore pays one
  failed spawn on every background LLM call (a latency cost, not tokens).

**F6. readGitState resolves porcelain paths against cwd, but porcelain v1 paths are repo-root-relative**
- lib/git-state.mjs:55 calls `isOwnAdoptionArtifact(cwd, l.slice(3), …)`.
- Real-git probe from a subdirectory cwd:
  (a) the plugin-only root CLAUDE.md is still counted: `[ '?? CLAUDE.md' ]`;
  (b) with a USER-text root CLAUDE.md and a plugin-only sub/CLAUDE.md, the user's file is HIDDEN
  and the plugin's is counted: `[ '?? sub/CLAUDE.md' ]`. That is the "hide real user work"
  direction the docblock (claudemd.mjs:183) calls unsafe. The displayed count is unchanged in (b),
  so the impact is low.
- Fix: resolve against `git rev-parse --show-toplevel`.

**F7. Minor edges of isTransientPath** (lib/bash-file-targets.mjs:41-46)
- `/[\\/]\.claude[\\/]projects[\\/][^\\/]+[\\/]/` matches inside any repo, for example
  `/home/u/dev/myrepo/.claude/projects/foo/bar.md` gives true.
- CLAUDE_CONFIG_DIR=$HOME makes every `~/projects/<x>/…` file transient. Probe:
  `/home/u/projects/myapp/src/index.js` gives true.
- A relative CLAUDE_CONFIG_DIR is ignored. A Windows CLAUDE_CONFIG_DIR never matches, because the
  prefix is built with `/`.

**F8. The /clear Working State line still cuts working_on at 200 characters**
- hook-context.mjs:830-831 `truncate(safeText(prevClearHandoff.working_on), 200)`. f6ec285's
  600-character first prompt reaches the `<session-handoff>` renderer (hook-handoff.mjs:976) but
  not this /clear block. The fix is partial.
