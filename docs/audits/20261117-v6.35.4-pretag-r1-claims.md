# v6.35.4 pre-tag review: claims lens

Candidate: `git rev-parse HEAD` printed `0b91f2296c9f3d909d41e0080c80efeaeda5f1ec` (matches). The range is `v6.35.3..0b91f229`; efef05b1 and 2b3c7822 are out of scope.

**Method.** I built five trees with `git archive <rev> | tar -x`, each with a copied `node_modules`: v6.35.2, 2b3c7822, f3c48cb5, d96f7d2f and 0b91f229. 2b3c7822 has the same code as v6.35.3: `git diff --stat v6.35.3 2b3c7822` touches only CLAUDE.md and docs.

- Probe driver: `~/.cache/tmp/rv-6354-claims/probe.mjs <tree> [scenario]`. Each scenario gets a fresh git sandbox with HOME, CLAUDE_MEM_DIR and the runtime dir set inside it. It calls the tree's `silentAutoAdopt`, `cmdAdopt`, `cmdUnadopt` and `cleanupClaudeMdLegacyBlock`, the same way the tests do. One scenario (E1) runs the shipped `scripts/hook-launcher.mjs hook.mjs session-start` instead.
- Probe logs: `probe-head.log`, `probe-2b3c7822.log`, `probe-v6.35.2.log`.
- Test runs and mutation runs: `run-*.log`, `mut-*.log`.
- Every shell unset the `*_API_KEY` variables and the proxy variables. TMPDIR was inside this directory.

**Verdict.** Every number in the four commit messages reproduces: 15/22, 7, 17/17, M11, the O1 output, the 3349f6fa case, and the "→ created" adopt.

The CHANGELOG's three bullets are true for the shapes they name. The headline holds for a clone's committed links; the clearest proof is E1, end to end through the shipped hook: 6.35.3 overwrote both outside files and 6.35.4 left them.

Two P2 findings:

1. The "what to do" that the entry credits `adopt` with tells the user to copy the target the repository picked into the repository.
2. Layouts users built themselves are now refused, and SessionStart stops syncing them silently. The entry understates this.

The rest are P3 imprecisions.

## Findings

**C1 · P2 · lib/project-link.mjs:62 (endorsed by CHANGELOG.md:21, "`adopt` names the link and what to do", and by f3c48cb5, "adopt says so and what to do").**

For a link the repository commits, the remedy printed is "Replace the link with what it points to, then run adopt again."

- Repro, probe `R1` on 0b91f229: commit `.claude -> ../../.ssh`, then run adopt. It prints `… .claude: a link this repository commits, to <SB>/.ssh, outside this project; not written through. Replace the link with what it points to, then run adopt again.`
- Repro, probe `R2`: commit `CLAUDE.md -> .git/config`. The message says `to <SB>/work/app/.git/config, outside this project; … Replace the link with what it points to`.
- Expected: for the case this release exists for, the remedy is to delete the link, as the whole-file branch at :49 already says. Following the printed advice puts a copy of the target the repository picked into the repository's work tree: `~/.ssh`, or `.git/config`, which can hold credential-bearing remote URLs. Separately, `.git/config` is not "outside this project".
- `unadopt` prints the same text after unadopting (probe A4: "⚠ left …/.claude alone: … then run adopt again").
- Shape: REAL. A cloned repository can commit both links. v6.35.3 printed nothing here; it wrote through the link.
- Severity: P2. It is arguably P1 under "wrong security action", but the target path is printed in the same line.

**C2 · P2 · CHANGELOG.md:17-22, lib/project-link.mjs:41-45, hook.mjs:3199-3203. Upgrade change for user-built layouts is understated.**

On 6.35.3 each of these layouts was written through. On 6.35.4 each is refused:

- **(a) Outside git, CLAUDE.md or `.claude` linked into a dotfiles tree.** Probes D1 and D1s.
- **(b) The user committed the link themselves**, for example `CLAUDE.md -> ../shared/CLAUDE.md` shared by sibling repos. Probe D2. It is labelled "a link this repository commits".
- **(c) A repository git refuses for ownership** (safe.directory: a bind mount, a share, WSL `/mnt/c`). Probe D6, simulated with `GIT_TEST_ASSUME_DIFFERENT_OWNER=1`. This is not mentioned anywhere.
- **(d) The user's link in place of a tracked symlink.** See C3.

What the user sees:

- SessionStart returns `{"ok":false,"action":"skipped","reason":"error"}`. That reaches `debugLog` only, which prints only when `CLAUDE_MEM_DEBUG` is set (utils.mjs:479).
- `adopt --status` still prints `CLAUDE.md: ✓ adopted (v1)` (probe D1s on 0b91f229). On 2b3c7822 the same probe gives `"action":"refreshed"`.
- `doctor` says nothing: nothing in install.mjs imports `linkRefusal`, unlike the D#369 stopped-sync warning at install.mjs:3383-3397.

This is round 2 F3's shape ("SessionStart silently stops refreshing; status says adopted") moved to other layouts.

- The entry says only "Outside a git work tree, a link out of the project is refused", and it says it inside the bullet about *committed* links. (b) and (c) are implied only by the rule's wording, or not at all.
- The remedy from C1 would make these users dismantle their dotfiles link. Running `git init` fixes (a), and untracking the link fixes (b).
- tests/project-links-out.test.mjs:4 says "The layouts users build with links keep working". That is false for (a) to (d).
- Shape: REAL, for the dotfiles-managed CLAUDE.md in an unversioned project, sibling repos sharing a committed relative link, and repos on a mount owned by another uid.

**C3 · P3 · CHANGELOG.md:18, "in place of a tracked file", is wider than the code.**

A link that replaces a tracked *symlink* keeps mode 120000 in the index, so lib/project-link.mjs:127-130 treats it as the repository's and refuses it.

- Probe D3: the repo commits `CLAUDE.md -> AGENTS.md`, and the user points `CLAUDE.md` at a dotfiles file (`git status` shows ` M CLAUDE.md`). 0b91f229 refuses; 2b3c7822 refreshed.
- f3c48cb5's wording, "a tracked file of another mode", is exact; the CHANGELOG's is not.
- Shape: REAL, rare.

**C4 · P3 · CHANGELOG.md:23, "A detail doc or state file you linked yourself is written again", holds only inside a git work tree.**

Outside git, probe D1b shows 0b91f229 still refusing, with "Delete the link, then run adopt again". 6.35.3 behaves the same, so this is not a regression; the bullet simply does not say it applies only inside git.

**C5 · P3 · CHANGELOG.md:19-20 ("any other link in their place is refused wherever it points") and lib/project-link.mjs:17 ("git shows the user made it: the rest of the path is theirs").**

`linkRefusal` returns null at the first link the user made (:41) and never looks at later components.

- Probe D5: the repository commits `cfg/plugin_claude_mem_lite.md -> ../../../outside/plugin_claude_mem_lite.md`, and the user's own untracked link is `.claude -> cfg`.
- 0b91f229: adopt prints "→ created" and the outside file is overwritten (VICTIM becomes the 6479-byte doc).
- 2b3c7822 refused it ("a symbolic link; not written through"); v6.35.2 wrote it.
- Shape: CONSTRUCTED. It needs the user to link `.claude` into a directory the repository ships. It is a regression against 6.35.3 for this shape only.

**C6 · P3 · The "untracked means you made it" premise (lib/project-link.mjs:6-9) does not hold for an archive unpacked inside an enclosing work tree.**

- Probe D4: `$HOME/work` is a git repo, `app/` has no `.git`, and `app/.claude -> ../../outside`. 0b91f229: adopt prints "→ created" and writes the doc and state file in `outside/`.
- "Outside a git work tree, a link out of the project is refused" (CHANGELOG.md:20) is literally true, because this project sits inside one. But the refusal text names archives (:45), so a reader may think archives are covered.
- Shape: REAL-ish, for example a release tarball vendored into a monorepo before it is committed. 6.35.3 behaves the same.

**C7 · P3, unsupported and not reproduced · "outside `.git`" (CHANGELOG.md:19).**

`within()` compares segments case-sensitively (`!segs.includes('.git')`, lib/project-link.mjs:86), after the JS `realpathSync`, which keeps the case of the link text. On a case-insensitive filesystem a committed `CLAUDE.md -> .GIT/config` would pass this check. That covers macOS by default, and package.json `os` includes darwin. I had no darwin host, so this needs a macOS run before the claim stands unqualified.

**C8 · P3 · f3c48cb5: "The other 7 pin layouts that keep working and passed on both trees".**

7 cases did pass on 2b3c7822. But "SessionStart does not overwrite the user's untracked file inside the repository" pins a refusal that 6.35.3 already made (052e969d). So the 7 are 6 layouts plus 1 refusal.

**C9 · P3 · f3c48cb5: "17 of 17 red, each on its own case".**

17 of 17 reproduced red on f3c48cb5 (`mut-f3c4.log`, same case lists as `tasks/d880/mutations-c1.log`), and every mutated file was restored byte for byte (cmp).

However, M4 (removeManaged doc) and M5 (removeManaged state) turn exactly the same two cases red, so the suite cannot tell which of those two sites broke. M7, M13, M14 and M17 each turn red only cases that another mutation also turns red. "Each on its own case" holds only in the sense "each turns at least one case red".

**C10 · P3 · f3c48cb5, "so a refusal no longer leaves the block written (round 1, D5)", and the claudemd.mjs:428-430 comment.**

This is true for link refusals only. Round 1 D5's other shape still writes the block and then fails.

- Probe D5big: commit a regular `.claude/plugin_claude_mem_lite.md` of 4 MiB + 10 B, then run adopt. It exits 1 with "not a regular file, or over 4194304 bytes", and CLAUDE.md holds the block afterwards. Both 0b91f229 and 2b3c7822 behave this way.
- Citing D5 reads as if D5 is closed.
- Shape: REAL; no data loss.

**C11 · P3 · Test text.**

- tests/project-links-out.test.mjs:322 is named "an *untracked* state sidecar …", but the fixture commits the state first (:324), so it is a typechange. M17 (the typechange branch) turns it red; M18 (the untracked branch) does not.
- :84 "written into the file at argv path" describes a function argument, not argv.

**C12 · P3 · Completeness.** CHANGELOG.md:14-16 lists what a committed CLAUDE.md link caused, but leaves out that SessionStart also added the AGENTS.md import to the outside file. f3c48cb5 names it, and the vitest case on 2b3c7822 confirms it: the outside file began with `<!-- claude-mem-lite adopt: imports A…`.

## Questions

**Q1.** Answered in the tables above.

**Q2.** For a clone's links, the entry describes what a user will see. It leaves out these changes for layouts users built themselves:

- Outside git, a dotfiles CLAUDE.md or `.claude` link is now refused.
- A link the user committed is treated as the repository's.
- A link replacing a tracked symlink is refused.
- A repo that git refuses for ownership has every user link refused.
- In all four, SessionStart stops syncing with no signal, and status still reads adopted (C2, C3).

**Q3.** Statements that make the code look safer than it is:

- C5 (constructed; a regression against 6.35.3 for that shape).
- C6 (literally true, gap for archives).
- C7 (unverified on darwin).
- C10 (the D5 citation).

Statements that make it look wider, i.e. say something is written when it is refused: C3 and C4. C1 is a wrong remedy.

**Q4.** All six version sites are in sync at 6.35.4: package.json, package-lock.json `version` and `packages[""].version`, plugin.json, marketplace.json `plugins[0]`, and the CLAUDE.md:5 `**Version**` line. `npx vitest run tests/install-e2e.test.mjs tests/plugin-manifest.test.mjs tests/pre-commit-version-sync.test.mjs -t version` passed: 12 passed, 52 skipped by the filter, exit 0.
