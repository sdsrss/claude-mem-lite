FINDINGS
1. should-fix · haiku-client.mjs:559. The check `const plainHttp = apiUrl.startsWith('http:')` tests the raw user string, and it is case-sensitive. The resolver validates `parsed.protocol` (lib/anthropic-base-url.mjs:89) but returns the raw text (:96). So `HTTP://127.0.0.1:4000`, `Http://localhost:4000` and a tab-split `h\ttp://…` all count as accepted loopback http, but they skip postDirectHttp. Native fetch then hands x-api-key to HTTP_PROXY under NODE_USE_ENV_PROXY=1. This breaks contract 1, and it makes the README:1094 claim ("always goes straight") false.
   Evidence:
   - Resolver output: `{"url":"HTTP://127.0.0.1:4000","error":null} startsWith(http:)= false`.
   - I copied tests/plain-http-gateway-env-proxy.test.mjs with the origin changed to `HTTP://${host}` and it fails 2/2.
     - Node 26.8.1 proxy log: `{kind:'request', key:'test-key-not-real'}`.
     - Node 22.23.3 proxy log: `connect` plus `tunnelled-request` carrying the key.
   - Fix: decide on `new URL(apiUrl).protocol`, or have the resolver return a normalized URL. The same root cause makes doctor report "direct" for this spelling.
2. should-fix · hook-update.mjs:108. `failed(Boolean(fresh.rateLimited))` reads a flag saved to disk. Only a successful lookup clears that flag. So after any earlier 403/429, a later network or proxy failure prints "GitHub is rate-limiting… Try again later", and keeps doing so until a lookup succeeds. Contract 2 still holds, but the diagnosis is wrong.
   Evidence: with state `{"rateLimited":true}`, fetch rejecting ENOTFOUND and proxies unset, `checkForUpdate({force:true,allowInstall:true,reportFailure:true})` returned `{"checkFailed":true,"rateLimited":true}`.
3. note · CHANGELOG.md:25. "LLM calls through a proxy were not affected" claims more than was measured. For the two named hosts it holds: a credential-free POST returned 401 with both `Host: api.anthropic.com` and `…:80`, and openrouter.ai behaved the same. But the tunnel also carries portless https ANTHROPIC_BASE_URL gateways (Azure Foundry, LiteLLM). Those got `Host: gw:80` before the fix, and nobody has measured them.
4. note · README.md:192. "as the other methods do" is wrong for Method 1: a plugin install keeps no source in ~/.claude-mem-lite (the getCurrentVersion comment in hook-update.mjs says so). The rest of the paragraph checks out:
   - deployCodeTree (install.mjs:502) copies unless `--dev`.
   - isDevMode looks at ~/.claude-mem-lite, not at the clone, so `node install.mjs update` from a clone takes the signed path.
