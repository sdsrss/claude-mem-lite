## P2-1 — cutoff-reach-probe's `neverMissed` ("in use") bucket can only contain edges that were NEVER resolved

- `benchmark/cutoff-reach-probe.mjs:54` `neverMissed = edges.filter(e => !e.last_cited_session_id && e.miss_streak === 0)`.
- `benchmark/cutoff-reach-probe.mjs:17` claims "The first two are what the cut would evict while still in use", and the probe returns them as `inUse`.
- Mechanism: in `lib/edge-attribution.mjs`, only `updateHit` resets `miss_streak` to 0, and it ALWAYS stamps `last_cited_session_id` (lines ~109-115). `updateMiss` only increments.
  So `miss_streak = 0 AND last_cited_session_id IS NULL` means no hit ever and no miss ever: the edge was never resolved.
  That is the opposite of "in use". It covers edges never injected, edges injected only in subagents, and edges that predate edge counting.
- Evidence: on a read-only `.backup` snapshot of the maintainer DB taken 2026-09-27T09:17Z, with `--now 2026-12-31`, the probe returned total 313, cited 100, neverMissed 180, rest 33.
  For every `miss_streak=0 AND last_cited_session_id IS NULL` edge in the live, importance>=2 population: **180 had inject_count=0 and 0 had inject_count>0**.
  - Repro: `sqlite3 "file:$HOME/.claude-mem-lite/claude-mem-lite.db?mode=ro" ".backup snap.db"` then `node scratchpad/review-defect/probe-run.mjs <tree> snap.db`.
- `tests/cutoff-reach-probe.test.mjs` encodes the same conflation. Its "never missed" fixture edge is inserted with inject_count 0 and no cite, and is asserted to be in `inUse`.
  Its "cited" fixture (`cited:'sess-x', miss:2`) is a state `updateHit` cannot produce.
- Consequence: `docs/measurement/rulers.md:25` records the B3 reading as "**149 in use (88 cited, 61 never missed)**". By construction the 61 are not in use.
  The probe exists to decide proposal B3 (move the cut from creation age to last use), so the decision input overstates in-use eviction by 61/149.
- Fix direction: drop `neverMissed` from `inUse`, or redefine it on `inject_count > 0` plus a recent `last_resolved_session_id`. Correct the rulers.md reading and the test fixture.

## P3-1 — a single-line chunk longer than the budget is cut mid-sentence with NO omission marker, and can split a surrogate pair

- `lib/hook-text-cap.mjs:82` `kept.push(lines[0].slice(0, budget))`, then `:85-87`. For a one-line text, `dropped` is empty, so no footer is written.
- Reachable through `writePlainHookText` when 501 <= remaining < line length.
  Example: `hook.mjs:3285` writes the task-imperative line, which runs up to ~580 chars with the 500-char lesson cap.
- Repro: `node scratchpad/review-defect/imp.mjs <tree>`. A 9,312-char first chunk followed by a 742-char imperative line emits
  `"Memory — a past lesson applies to THIS task. You must: Do NOT skip this step. … Do NOT skip this \n"`.
  The instruction is truncated mid-sentence, its `(#NN)` is gone, and nothing says it was cut. A truncated "You must:" imperative can change meaning.
- Fuzz: `node scratchpad/review-defect/fuzz.mjs <tree>` ran 3,000 random multi-chunk runs. Results: max total 9,887 (never over cap), tag blocks always balanced, but **232/3000 outputs contained a lone surrogate** from this slice.
  On the plain-stdout path Node writes a lone surrogate as U+FFFD. The icons are astral: 🔴🟡⚪ in D#N rows, emoji in FYI rows.
- Fix direction: when truncating a line, append `…` plus the footer, and back off one code unit if the cut lands on a high surrogate.

## Answers to the specific questions

- **>10,000 chars / lost output / one-JSON contract.** Every injected-text writer on a hook in `hooks/hooks.json` now goes through the cap:
  - `flushHookStdout` for SessionStart, PostToolUse, PostToolUseFailure, Stop, pre-tool-recall and post-tool-recall
  - `writePlainHookText` for both UserPromptSubmit handlers
  - `writeCappedHookText` for PreCompact

  The bash hooks write nothing to stdout themselves; they hand off to node. No remaining `process.stdout.write` / `console.log` exists in the hook scripts or hook-*.mjs.
  The fuzz never exceeded 10,000 per process. The document count per process is unchanged: `hook.mjs user-prompt` queues nothing, so the dispatcher tail flush writes no JSON after the plain chunks.
- **Harmful cut places.** Tag blocks are re-closed (fuzz: 0 unbalanced). JSON-ish lines are safe because the cap runs on the decoded field before `JSON.stringify`. The exceptions are mid-line / mid-surrogate truncation (P3-1).
- **Budget leak across calls.** `plainUsed` is module state, reset at the top of `handleUserPrompt` (`hook.mjs:3316`) and of `user-prompt-search.js` main (`:701`). Each hook is its own process, and no other caller of `writePlainHookText` exists. No leak found.
- **Framing A/B vs consumers.** See P3-8. The suite is green apart from the env-only failure above.
- **Matcher change vs decay.** See P3-6. No double counting. The population grows by the failure path, as intended.
- **Probe population.** See P2-1 and P3-5.
