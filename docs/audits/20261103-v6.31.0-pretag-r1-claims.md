### P2-1: the git-record claim is broader than the rule (CHANGELOG.md:23, README.md:254, README.zh-CN.md:210)
Claim: "Error recall stays silent on a git command that succeeded when its only failure words are in the commit records git printed" (zh: 成功的 git 命令不再触发 error recall，前提是报错词只出现在 git 打印的提交记录里).

What the code does: it only strips the 3 record shapes, and only after 8 subcommands (lib/error-recall-gate.mjs:112-147).

Repro: `node scripts/gateprobe.mjs $C probe-git/sandbox-cases.json`, and the same with probe-git/compound-cases.json and probe-git/session-cases.json. The outputs are real git outputs captured in sandbox repo gitrepo/; the cases are in probe-git/o, o3. Every command exits 0, and its only failure words are commit subjects that git printed:
- `git stash`: "Saved working directory and index state WIP on main: 76fc081 test: panic when the store is ENOENT" → FIRES
- `git reset --hard HEAD`, and `git checkout --detach HEAD && git checkout main`: "HEAD is now at 76fc081 test: panic …" → FIRES
- `git stash list` → FIRES
- `git commit -q -m "fix: a traceback on import" && git log -1 --format=%B` → FIRES. The same holds for `--format=%s`, `--format="%ad %s"` and `--abbrev-commit` (header `commit f9f61a6`; COMMIT_HEADER_RE requires 40 hex).
- `git reset --hard HEAD~1 && git log --oneline -1` → FIRES. The oneline line is stripped; the "HEAD is now at" line is not.
- Real shape from this review session: `for s in …; do echo …; git log -1 --format='%B' $s | cat; done`. Installed 6.30.15 fired on it (block #462/#969/#590), and the candidate gate still fires (S2: isHardError=true verdict=null).

Silenced as advertised: `git commit -m …` ([main sha] line), `git commit -q … && git log --oneline -3`, `… && git log -1 --stat`, the reset-then-commit-then-oneline chain, and this session's real `git rev-parse && git log --oneline v6.30.15..f5b70ba9 | cat && … ls; df` firing (S1: base FIRES, cand verdict=git-record).

v6.30.15 behaves the same on every shape above, so this is not a behaviour regression. The new prose is what is false. Reach in the corpus: none of these unstripped shapes drives any of the 432 exit-0 firings in the top-level transcripts; the one real occurrence is S2 in this session.

The README env row (README.md:1268) lists the three shapes and is accurate. Fix: say "a `[branch sha]` line, a `--oneline` line or a `commit <sha>` block printed by git log/show/commit/…", as that row does.
