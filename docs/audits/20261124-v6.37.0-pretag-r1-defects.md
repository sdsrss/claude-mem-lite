  `LIMIT ? OFFSET ?` paging are unchanged. The diff touches neither the events query nor the dedup, cooldown,

then `tools/vt.sh <copy> <the 58 files>`.

**F2 — P3, constructed (mutation): the off spellings that contract item 1 names are not tested.** Code at
`scripts/pre-tool-recall.js:280-282` behaves correctly (SQL capture above: `OFF`, `0`, `false`, `No` all give
v6.36.0's text). The tests only use lowercase `off`. Removing `.toLowerCase()` (M10) or shrinking the list to
`['off']` (M11) leaves 1317/1317 green. M11 does change behaviour: `CLAUDE_MEM_PRETOOL_RECENCY_FIRST=0` and
`=FALSE` then give the new order on Read (lesson D instead of A).

**F3 — P3, real: "the newest lesson first" holds only inside the observations leg.** The merge is unchanged

(2026-11-10T16:16Z), while `E#9933` (2026-11-16T17:35Z) matches the same file and appears third on Edit. This was 1
of 4 sampled files. Also, "Edit two": Edit showed 3 rows (2 observations + 1 event) on all 4 files. The behaviour
predates 6.37.0, but the new text says "newest" without that scope: `CHANGELOG.md:10-11`, `README.md:248-251`,
and the matching README.zh-CN.md bullet. Repro: `N=1 tools/timing2.sh` after re-taking the store backup
(`tools/backup.mjs`), then read `timing2/times.tsv`.

**F4 — P3, real: an internal ruler note is now out of date.** `docs/measurement/rulers.md:26` says "The product
still CONSUMES the signal — pretool's per-file sort key (`citeFactor`)". With the default arm, citeFactor only
