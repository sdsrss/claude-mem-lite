## Findings

### F1 · P3 · real shape, but needs an abnormal setup · catch-up never finishes if the saved state cannot be reused, so no citation result is ever written
- `lib/transcript-digest.mjs:115-117,172,228`; `hook.mjs:1496-1503`.
- **How it fails:** catch-up makes progress only if the next Stop reuses the saved offset. If every Stop starts again from byte 0 on a transcript over 64 MiB, `complete` stays false on every Stop and `trackCitationsAtStop` returns before writing anything. This happens for:
  - **Two code homes of different versions** running Stop on the same transcript with the shared RUNTIME_DIR. This is the double-registration state that `plugin-cache-guard.mjs:3-13` documents as real and self-heals at SessionStart. Each version rejects the other's state (`s.code !== code`).
  - A runtime dir where the atomic write fails.
  - `digestCodeIdentity()` returning null (package.json unreadable).
  - A filesystem whose inode numbers are not stable across opens.
- **Before vs after:** every Stop wrote its results, or timed out on files over the memo budget. Now nothing is written, permanently, for that population.
- **Repro** (alternates two copies of the digest whose package.json versions differ, on a 100 MiB transcript):
  `node --max-old-space-size=4096 fuzz/twoversions.mjs <100MiB transcript> <rt dir>`
  → `alternating versions, complete per Stop: false false false false false false false false false false false false`, then `one version only afterwards: false true true true`.
  The fixture was `head -c 104857600` of `perf/gen.mjs`'s 300 MB file. `after-v2/` is `after/{lib,*.mjs}` with version `6.35.0-other`.
- **Related, by design but worth stating:** every version change invalidates every state, not only one that changes a scanner rule. After each update, every long session gets a window of ceil(bytes/64 MiB) Stops in which nothing is written. That is 8 Stops for the issue's 475 MB session.

### F2 · P3 · real shape, during a killed or in-progress update · v6.35.0 hook.mjs plus the new lib/persist-reminder.mjs fires the G3 reminder although the session persisted
- `lib/persist-reminder.mjs:113-116` changed `detectUnpersistedDecision({prompts, transcriptPath})` to `({prompts, persistenceCount})`.
- **Swap order:** lib/persist-reminder.mjs is swapped at source-files.mjs:200 and hook.mjs at :373. At the split points between them, v6.35.0's hook.mjs:1815-1818 passes `transcriptPath`. `persistenceCount` is then undefined, `undefined > 0` is false, and the result is `fire: true`.
- **Effect:** the next SessionStart shows "Last session mentioned a finalized decision … but persisted nothing" (cite-back-hint.mjs:455-457).
- **Contract 6 is false for this function:** a path-based persist-reminder export no longer accepts a path.
- **Why the release check misses it:** `scripts/swap-mixed-tree.mjs v6.35.0 28472b3b` passes ("every entry point loads at every split point", exit 0), because it checks names only.
- **Repro:** a transcript with one `mem_defer` tool_use, prompts `['方案 B 拍板，开工']`.
  - Old lib: `{"fire":false,"signal":"拍板"}`.
  - New lib, same call shape: `{"fire":true,"signal":"拍板"}`.
  - The persistence count in that transcript is 1.

### F3 · P3 · real shape (transcripts > 536,870,888 bytes) · the "same as before" claims are false above V8's string limit, and the digest has no oracle there
- **Old behaviour:** `readTranscriptEntries` decodes the whole file into one string (transcript-scan.mjs:106-111). Above 0x1fffffe8 characters that throws, and the code returns `[]`. So before this range, `extractTailAssistantText` returned null and every Stop scanner answered empty.
- **New behaviour:** the backward reader and the digest answer correctly.
- **Contracts affected:** contract 1 (same Stop answers) and contract 5 (same return "for any file") do not hold for this population. The docstring at summary-extractor.mjs:113 ("the answer are the forward parse's") is wrong there too. The change goes in the right direction.
- **Unverified region:** the path scanners, which serve as test oracle, equiv ruler, CLI and benchmark, are still blind above the limit. Nothing checks the digest's answers there, and no real transcript here is that large (largest: 21,974,184 B).
- **Repro:** `node --max-old-space-size=4096 fuzz/huge.mjs <545 MB gen.mjs file + one line citing #123> <rt>` gives:
  - `old tail: null`
  - `new tail: "final reply cites #123"`
  - `before-tree path scan cited: []`
  - `after-tree path scan cited: []`
  - `digest calls to complete: 9 cited: [ 123 ]`

### F4 · P3 · constructed (Claude Code does not write it) · a `null` line: path scanners and the old tail reader throw, the digest and the new tail reader skip it
- **Where:** `transcript-digest.mjs:303` drops `null` and other primitives. `readTranscriptEntries` keeps `null`, and every scanner's `entry.type` throws on it.
- **Before:** the whole Stop citation block threw, so nothing was written.
- **After:** results are written.
- **Old vs new tail reader:** old `extractTailAssistantText` threw; new returns the reply. Contract 5 says "for any file", so this counts against it.
- **Repro:** `node fuzz/shapes.mjs <dir>` →
  `nonobject-line-null … diff:["THROWS:Cannot read properties of null (reading 'type')"]` and
  `tail:nonobject-line-null … old:"THROWS:…", neu:"b #2"`.
  Number, string, array and `true` lines are equal.
- **Untested guard:** mutating the guard to `entry === undefined` leaves 22/22 digest tests passing.

### F5 · P3 · constructed · a whole record written without its newline, then more bytes appended to the same line: the digest counts the first record, the path scan drops the merged line
- `transcript-digest.mjs:285-288` consumes a parseable unterminated last line and moves the offset to `size`.
- If the next bytes continue that line (`{…#8}{…#9}\n`), the path scanners see one unparseable line and keep neither record. The digest keeps both.
- **Repro:** `shapes.mjs` → `sameline-step2 … diff:["cited","citedMain","citedMainAnswered","citeRecall","mainText"]`.
- **Not affected:** half-written records that do not parse are handled the same in both (several cases in shapes.mjs, plus the repo test).

### F6 · P3 · constructed · same inode, same length, bytes changed between the two 4 KiB probes: stale accumulators, `complete: true`, results written
- `transcript-digest.mjs:225-233` is the documented limit of claim 5.
- This contradicts claim 4: the digest reports complete without having read the changed bytes.
- **Repro:** `shapes.mjs` case `mid-rewritten-same-inode-same-length`. Three lines of ~6 KB each; `#11` → `#12` rewritten with `r+`; then append. Result: `diff:["cited","citedMain","citedMainAnswered"]`.

### F7 · P3 · comment and commit message state a bound the code does not keep · "reads at most maxBytes / 64 MiB"
- `transcript-digest.mjs:13-14`, `:45`, and commit 28472b3b ("A Stop reads at most 64 MiB of new bytes").
- **Chunk overshoot:** the budget is charged per consumed line (`:275-278`), but a whole 4 MiB chunk is read first. Each catch-up Stop read 68.01-68.02 MiB (steady.out).
- **Long lines:** a line longer than the budget is consumed whole in one call. With `maxBytes: 100`, the first call consumed a ~5 KB line (`budget-100-vs-5KB-line … calls:2`).
- **No memory cap on a single line:** pending pieces are copied (`:266`) and then concatenated.

### F8 · P3 · test gap · claim 4 is held by a test only for the cite-recall payload
- The e2e test (tests/e2e.test.mjs:3221-3260) asserts only that `cite-recall-*.json` is absent after the first Stop.
- **Mutation M1** (gate removed): that test fails.
- **Mutation M1b** (gate moved to just before the payload block, hook.mjs:1735, so access bumps, decay, both funnel tables and edge attribution run on a partial digest):
  - The test passes.
  - So do e2e.test.mjs plus every citation, transcript, stop, cite, persist, funnel, d124, d152 and d177 test file: **29 files / 602 tests pass** with M1b applied.

### F9 · P3 · planted or edited state file (needs write access to the user's runtime dir) · a state file that matches the version string is trusted without further checks
- **Wrong-typed accumulators:** `loadState` and `continues` (`:169-177`, `:225-233`) check only that each key exists. Planting `acc.cited = [1]` makes every Stop throw `ids.add is not a function`. The state is never rewritten (mtime unchanged), so citation writes stop for that transcript until the 24 h GC.
  - Repro: `fuzz/state.mjs <dir> plant` → `stop 0/1/2 THROWS … state rewritten: false`.
- **FIFO at the state path:** `readFileSync` blocks. The transcript open uses O_NONBLOCK (`:203`); the state read does not. Stop hangs until killed. Repro: `mkfifo` at the state path; `timeout 5 node fuzz/state.mjs … fifo` exits 124.
- **No size cap** on the state read.
- **Size under normal use:** state files over the 196 real transcripts total 413,607 B, largest 8,564 B. Normal use is bounded, and the files are GC'd after 24 h by prefix, including the atomic-write temp files.

### F10 · P3 · constructed · a per-record rule that throws on one subagent record now blocks every citation write in the session
- **Before:** b91b6384 hook.mjs:1500-1505 wrapped `collectSubagentSurface` in its own try/catch. A throwing subagent file left `sub` empty, and the main results were still written.
- **After:** the digest has no per-file containment. It throws before saving state (`:136-146` is never reached), the outer catch (hook.mjs:1874) skips everything, and the next Stop throws again.
- **Repro:** a subagent file with `{"type":"assistant","isSidechain":true,"message":{"content":[null]}}` gives `stop 0 digest THROWS: Cannot read properties of null (reading 'type') | state files: 0`, and the same on stop 1.

### F11 · P3 · ruler coverage · claim 2's 784/784 does not exercise several arms
`tasks/issue-53/equiv.mjs`:
- **citeBack:** `nonEmptyChecksPerAnswer` has no `citeBack` key under either seed, so its equality was 0/784 non-vacuous.
- **Subagent growth:** subagent dirs are copied whole before the first cut, so incremental subagent reads (appear, grow, shrink, recreate) are never exercised.
- **Catch-up:** the largest transcript is 21.97 MB, below 64 MiB.
- **String limit:** no file is above 512 MiB.

My `fuzz/shapes.mjs` covers what the ruler misses, and found these cases equal: subagent lifecycle, CRLF, invalid UTF-8, a BOM, newlines at the 4 MiB chunk edges (±2 B), the tail reader at 64 KiB-448 KiB chunk sizes, symlink retarget, and budget catch-up. Result: 56 cases, 4 unequal. The 4 unequal ones are F4 (counted twice, digest and tail), F5 and F6.

## Checked, no defect found
- **Concurrent Stops:** two digesters (~3.4k calls each) raced an appender writing records in two halves, plus a subagent file. 4/4 rounds equal the path scanners, including the non-idempotent counters (`fuzz/conc.mjs`).
- **Backward reader cost:** worst case (reply at byte 0, 6M short lines, 252 MB) is on par with the forward parse: new 1814-1841 ms vs old 1856-2044 ms, ABBA order. Both are linear in the distance read.
- **Refactor of the path scanners:** the per-record split is behaviour-preserving for the shapes above. `hookPromptOf` is null-safe, and no SURFACE_MATCHERS `accepts` reads `prompt`.
- **Hook wiring vs b91b6384:** the same sets go to the same consumers (relevance set: `unionSurfaces(d.injected)` = `extractAllInjected`; decay and gate: `injectedMain`).
- **Unit tests:** transcript-digest, summary-extractor, persist-reminder, citation-surface-funnel and d124 files: 5 files, 147/147 pass in the after tree.
