### Findings

**F1 (P2, pre-existing, real shapes): the "Still stored" item is narrower than what is stored.** CHANGELOG.md:34-37:
"the shapes 6.30.12 lists, in text pasted into a prompt; a credential label at a line start or a double-quoted credential
value in a JSON string that a tool prints itself (...), through the tool-call hook and import-jsonl". 6.30.12 listed D#663 and D#664
without naming a path. 6.30.13 limits them to prompts and to JSON a tool prints. They are also stored when the JSON string sits in file
content the agent writes:
- import-jsonl, Write or Edit input: a `.env` line `APP_CONFIG="{\"api_key\":\"V\",\"password\":\"V2\"}"`, a source file holding an
  escaped JSON literal (`const body = "{\"password\":\"V\"}";`, the usual form in Java, C# and Go tests), and a Jupyter notebook written with Write.
- the tool-call hook, Edit entry: `scrubTruncate(new_string, 40)` keeps the value.

The fixed list at CHANGELOG.md:26-27 ("a JSON object, each in a file written with Write") makes the gap easier to miss.
`node probes/p12-json-in-file.mjs` and `node probes/p19-hook-edit.mjs`, output identical in base and cand:
```
Write .env with a JSON value             import-jsonl stores 2/2
Write JS with an escaped JSON literal    import-jsonl stores 2/2
Edit JS with an escaped JSON literal     import-jsonl stores 1/2
Write a Jupyter notebook (.ipynb)        import-jsonl stores 2/2
"{\"password\":\"<V>\"}" (Edit new_string)  hook desc STORED   (also API="{\"api_key\":...}" and s = "x\nAPI_KEY=<V>")
```

**F2 (P3, over-scrub direction): "that label is kept now (`POSTGRES_DB: app` was stored as `*** app`)" is false on the
tool-call hook path.** CHANGELOG.md:13-16 names that path in the same sentence. It holds for raw-text scrubbing (prompt hook,
import-jsonl), but the hook's Bash entry still stores `*** app`:
- `scrubTruncateEnds` collapses whitespace (utils.mjs:449).
- Then hook.mjs:867 runs `scrubSecrets` over the one-line text, where `POSTGRES_PASSWORD: POSTGRES_DB: app` has no line break left.

`node probes/p3-hook-label-kept.mjs`, cand: `scrubSecrets(raw)= "...POSTGRES_PASSWORD:\n  POSTGRES_DB: app\n"` but
`hookDesc= "cat pgdb → environment: POSTGRES_PASSWORD: *** app"`. Base is the same. In raw text too, a next-line label with an empty
value is still erased (`environment:\n  POSTGRES_PASSWORD:\n  JWT_SECRET:\n  POSTGRES_DB: app` → `  ***`), by both versions
(probes/p1-basic.mjs, row `composeTwoEmpty`). The secret-scrub.mjs comment (line 82) says "(`NAME: v`, `NAME=v`, `"name":`)",
which is accurate. The CHANGELOG's unqualified "that label is kept now" is not.

**F3 (P3, wording that overstates the old defect).** CHANGELOG.md:20-21 says import-jsonl "scrubbed a tool call as the JSON text of
its input and result" and "Every string sat one escape level deep". This is false for string results, what Bash and Read return.
v6.30.12 scrubbed those as raw text (`typeof toolResult?.content === 'string' ? toolResult.content : JSON.stringify(...)`), and
lib/import-jsonl.mjs:251-252 still says so. Two of the seven fixed groups are Bash string results (the passphrase `git diff`, the
`git show` hunk header). The marker cut fixed those, not the escape level. The commit 0f6ccb6a ("scrubbed as the JSON text of the
parsed value") and the test header ("of a parsed object") are scoped correctly.

**F4 (P3, number): "about 5,000 levels".** Appears at CHANGELOG.md:31, lib/import-jsonl.mjs:95 and in the commit 0f6ccb6a.
- Node 22.23.4, plain `JSON.stringify` (`probes/p4-depth.mjs`): first throws at depth 4,165 (objects) and 4,166 (arrays).
- v6.30.12's import on Node 22 (`probes/p5-deep-node22.mjs`, mock DB): last OK at 4,171, rejected from 4,172 with
  `RangeError Maximum call stack size exceeded`. At 5,000 and 20,000: base REJECTED, cand OK.
- Node 26.8.1: plain `JSON.stringify` does not throw up to 200,000.
- With a replacer (`probes/p14-replacer.mjs`): 4,162 (Node 22) and 5,660 (Node 26).

The rest of the claim holds: the whole transcript failed, and cand calls `JSON.stringify` only on leaves and keys.

**F5 (P3, disclosure): "Session ids ... are erased now as well" is not the only new loss of non-credential text.** Scrubbing each
string as raw text also erases command text after a quoted credential name, up to the next quote.
`node probes/p20-newly-erased.mjs`:

Real transcripts outside this repo (`probes/p6b-erased.mjs`): newly erased tokens are about 31 session ids, 5 `backend/.env` paths in
daagu Bash inputs, 2 `${{ secrets.… }}` references, and 2 credential-shaped mock values. The live hook already scrubbed commands as raw
text, so this aligns import-jsonl with it.

**F6 (P3, disclosed in mechanism, not in "Still stored"): a `<private>` tag anywhere in a part turns off per-string scrubbing for
the whole part.** The D#663 and D#664 shapes are then stored as in 6.30.12. CHANGELOG.md:24 says "unless a string holds a `<private>`
tag". "Still stored" does not list the consequence, and "stores none" (line 26) reads as unconditional. `probes/p7-import-groups.mjs`,
row `P  <private> tag + .env in one Write`: base STORED, cand STORED. The same `.env` without the tag: base STORED, cand erased. I did
not measure real reach.

**F7 (P3, pre-existing, constructed-leaning): the stored title is not cut at the private-key marker.** CHANGELOG.md:24-26 says "a tool
call's input or result keeps only what comes before its first private-key marker". The narrative obeys this. The `title`
(`importedObsTitle`, lib/import-jsonl.mjs:62-68: 80 characters of `input.command`) does not. `node probes/p11-title.mjs`, command
`printf '%s\n' '-----BEGIN RSA PRIVATE KEY-----' '<line1>' '<line2>'`:
- base: title 16 key windows, input 98.
- cand: title 16 key windows, input 0.

The title holds about the first 31 characters of the first body line, which for common key types are mostly fixed header bytes. The
other four command shapes I tried (echo -e, heredoc whole and cut, ssh-add here-string) stored 0 windows in both.

**F8 (P3, constructed): two empty labels in a row.** The lookahead does not treat a next line with an empty value as a label. So:
- `password:\ntoken:\n  <V>`: the second label is consumed and its value, written below it, is stored. Raw scrubber, both versions
  (probes/p1-basic.mjs, row `twoEmptyThenBelow`, leaked=1 in both). This contradicts the contract "values written below their label
  must stay erased" for this shape and has been there since before D#683.
- One import-jsonl variant regresses: a Write of `password: \n\n  session_id =\n\t<V>`. 6.30.12 erased V (pattern #40 over the
  escaped JSON text) and 6.30.13 stores it (`node probes/p17-two-empty.mjs`: base `import-jsonl erased`, cand `import-jsonl STORED`).

Constructed. My independent fuzz found no other import-jsonl regression of this kind (see Verified).

**F9 (P3, constructed): one unchanged pattern still has the D#683 shape.** Pattern #5 (`--token`/`--password` flag, `[=\s]+`) still
