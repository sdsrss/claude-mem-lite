## P2-1: a read-only inline script counts as a file WRITE, and that verdict feeds four "is this an edit" consumers

**Where**: `lib/bash-file-targets.mjs:335-336` (`SCRIPT_WRITE_RE`) + `:577` (`const sink = SCRIPT_WRITE_RE.test(program) ? writes : reads`).

`SCRIPT_WRITE_RE` contains `\.write\s*\(` and `\bprint\s*\([^)]*file\s*=`. These match `process.stdout.write(`, `sys.stdout.write(` and `print(x, file=sys.stderr)`, which are how agents PRINT from `node -e` / `python3 -c` / `python3 - <<EOF`. When the regex matches, **every** quoted path literal in the program goes to `writes`, including files it only opened for reading.

**Repro** (vitest, extracted tree):
```
× a read-only python one-liner that prints via sys.stdout.write writes nothing
  AssertionError: expected [ '/repo/tests/foo.test.mjs' ] to deeply equal []
× a node -e that prints via process.stdout.write writes nothing
  AssertionError: expected [ '/repo/package.json' ] to deeply equal []
```
Commands: `python3 -c "import sys; sys.stdout.write(open('tests/foo.test.mjs').read())"`, and `node -e "const p=require('./package.json'); process.stdout.write(p.version)"`.

**Downstream effects**. Each one is reproduced below or follows from the code path named:
1. **Error recall is silenced on a REAL test failure** (Q4). If the agent reads a test file with such a one-liner and then runs the test, the failure is classified `tdd-red` and nothing is injected. `lib/error-recall-gate.mjs:58-61` says explicitly that reading a test before running it is how a real failure is investigated and must keep firing. Only the `cat` form keeps firing.
   ```
   × reading a test file that way does not make its real failure a "deliberate TDD RED"
     AssertionError: expected { reason: 'tdd-red' } to be null
   (control: same flow with `cat tests/foo.test.mjs` -> null, fires)
   ```
2. **Finding #7 regresses (importance 3 inflation)**. `computeRuleImportance` (utils.mjs:208-216) promotes to 3 on an "edited" schema./migration/auth file, and the immediate save uses `ruleImportance` directly (hook-llm.mjs:783). Before the range, a Bash entry was never an edit, so this was 1.
   ```
   × printing schema.mjs version from node -e is not a critical (imp 3) schema edit
     AssertionError: expected 3 to be less than 3
   (python3 -c "...sys.stdout.write(open('config/auth.yaml').read())" also -> 3; `cat schema.mjs` -> 1)
   ```
3. **Episode significance, rule 1**: hook-episode.mjs:457 uses `isEditEntry`, and hook.mjs:746 sets `isSignificant` for any Bash write. A read-only inline print makes the window significant, so it is saved and an LLM call is spent on it.
4. **PreToolUse:Bash recall fires in EDIT mode on a read**: scripts/pre-tool-recall.js:457-459 picks `t.writes[0]`. The prefilter passes `python3 -c` / `node -e` through `prog_re`.
5. **The D#69 subagent rule leaks**: hook.mjs:797 `subagentEditsProject` = entryEditedFiles(...bashWrites). A reviewer subagent that prints a project file this way counts as "editing the project", so its window enters the main buffer. That is the exact shape D#69 set out to exclude.

**Suggested fix**: exclude stdout/stderr sinks (`(?:process|sys)\.(?:stdout|stderr)\.write`, `print(...file=sys.std(out|err))`). Better, attribute a write only to the literal that is the target of a write call (`open(<lit>, 'w'|'a')`, `writeFileSync(<lit>`, `Path(<lit>).write_text`, `rename*(…, <lit>)`) and classify every other literal as a read. Independently, `isDeliberateRed` could accept only structural writes (redirect / tee / sed -i / perl -i / cp / mv targets) and not interpreter-literal guesses. Add the repro cases as regressions.

**Where**: `lib/episode-input-filter.mjs:26` (`MUT_VOCAB_RE`), `:98-101` (the `weak` rule = the word + a test run), `:127-156` (`filterSummaryInput` drops the entry and, after an `opens-probe`, up to 4 following test runs). Precision was measured on THIS repo only (27/30, docstring :71-74), where "mutation" means a mutation probe. ## P3-1: prefilter false negatives. Node would recall, bash never starts it

**Where**: `scripts/pre-tool-recall-bash.sh:66-70`.
```
F2 premise: node side recalls a bare `python3 <<EOF` patch            ✓ (lesson injected)
F2: prefilter hands a bare `python3 <<EOF` patch to node              × expected '' to contain 'Keep the v export first'
```
Prefilter/parser matrix (skip = prefilter exit 0, node verdict in the second column):
```
skip write  python3 <<EOF …          (prog_re needs space/'/$ after <<)
skip write  python3 <<-EOF …   /  python3 <<"EOF" …  (JSON-escaped `\"`)
skip write  /usr/bin/python3 -c "open('a.json','w')…"
skip write  truncate -s 0 lib/x.log  /  ln -sf lib/a.mjs lib/b.mjs   (node write verbs absent from verb_re)
skip view   time cat lib/x.mjs  /  env FOO=1 cat lib/x.mjs  /  cat Makefile (no ext)
skip view   "echo hi\n\tcat lib/x.mjs"   (JSON `\t` is not [[:space:]])
```
The commit's 3276/3277 corpus figure suggests these shapes are rare in this repo's transcripts. Their rate elsewhere is not measured.
**Fix**: `(<<-?)` followed by `[\"'A-Za-z_]`; allow a path prefix before the interpreter and `python3.NN`; add `truncate|ln` to verb_re; accept `\\t` in `start`; allow `time|env|nice|timeout …` prefixes.

## P3-2: parser shapes. Missed writes and wrong cwd

**Where**: `lib/bash-file-targets.mjs:419-438` (prefix/keyword handling, cd tracking).
```
× `then sed -i` inside an if is a write        expected [] to deeply equal ['/repo/lib/x.mjs']
× a cd inside a subshell does not leak          (cd sub && cat a.js); cat b.js -> views ['/repo/sub/a.js','/repo/sub/b.js']
```
Also observed. None of these throw:
- `do sed -i …` in for/while loops, `{ cat a; }`, and `! cat a` → the keyword becomes the verb, so the operand is only a mention.
- `find … -exec sed -i … {} +` and `xargs sed -i` → no writes.
- `sudo -u bob cat /etc/x` and `timeout -s KILL 5 cat x.js` → the option becomes the verb.
- `cp -t dest a.js b.js` → b.js classified as a write.
- `jq --arg name value '.f' file.json` → phantom read `/repo/.f`.
- Windows `C:\…` paths → nothing, and no throw.

I found nothing on the hook hot path that throws. The lexer is linear, 8 ms at 200 KB. The heredoc regexes in episode-input-filter are superlinear on commands with many `<<` (240 ms at 200 KB of `1 << n` lines), which is within budget.
**Fix**: treat `then|do|else|elif|{|!|if|while|until|time` as transparent prefixes, and save/restore `cwd` across `(` … `)`.
