## Defects

### P3-A — an id that straddles the ellipsis cut is shown truncated and dropped (or mis-namespaced) in the footer
`lib/hook-text-cap.mjs:105-107`: `head = safeSlice(lines[0], budget - 1)`, `cutRest = lines[0].slice(head.length)`, and the footer's ids come from `idsIn([cutRest, …])` (`:48`). An id cut in the middle is in neither half as a whole token:
- the visible head ends `#424…` / `#42…` (a real-looking but WRONG id), and the footer names no id;
- `E#34` cut after `E`: `cutRest` starts `#34`, which `ID_RE`'s lookbehind accepts at string start, so the footer says `(ids: #34)` — an observation id, not the event `E#34`.

Reproduce (scratch probe, pad = 9499 − k so the cut lands k chars into the token, followed by 2000 more chars):
```
#4242 cut after 3 chars of token | head ends "aa#42…" | footer [claude-mem-lite] a line was cut short — hook output limit
#4242 cut after 4 chars of token | head ends "a#424…" | footer [claude-mem-lite] a line was cut short — hook output limit
E#34 cut after 1 chars of token | head ends "aaaaE…" | footer [claude-mem-lite] a line was cut short — hook output limit (ids: #34)
```
Before the commit the same input had no footer at all, so this is not a regression of shown ids; it is a gap in the new P3-1 behaviour ("the footer says … with the ids from the cut part"). Reachability is low: the ellipsis path fires only when the FIRST line alone exceeds `cap − 500`. Fix shape: move the cut back to before a partial `[A-Z]?#\d+` token at the boundary (or extract ids from the whole line and subtract the ids whole in `head`).

## Claims

### FALSE-1 — "the 60-day cut is the only AGE-based retirement a file lesson has … none of which retires a lesson that is still being injected"
Where: `benchmark/cutoff-reach-probe.mjs:26-31`, `docs/measurement/rulers.md:25` (same sentence), commit body ("the 60-day cut is the only AGE-based retirement, not the only one"; 4ce4cb0 correction "the only age-based retirement").

The `decay` maintain op is age-gated and does retire lessons PreToolUse is still injecting:
- `lib/maintain-core.mjs:471-478`: `UPDATE observations SET importance = MAX(1, importance − 1) … WHERE importance > 1 AND access_count = 0 AND injection_count = 0 AND created_at_epoch < ?`; `hook.mjs:1922` passes `now − 30 * DAY_MS`, `hook.mjs:1976` runs it in the daily auto-maintain (on by default; `decay` is in `DEFAULT_MAINTAIN_OPS`, `lib/maintain-core.mjs:59`).
- `hook-memory.mjs:529-534`: "scripts/pre-tool-recall.js bumps NOTHING"; `injection_count` is bumped only by the UPS faces. So a file lesson that PreToolUse injects every session but that is never cited (no `access_count` bump) and never UPS-injected has `injection_count = 0` — "never-injected" to decay — and drops from 2 to 1 at 30 days, leaving recall's `importance >= 2` pool 30 days BEFORE the 60-day cut.

Reproduce (temporary test in the scratch tree, since removed):
```
insertObs importance 2, lesson 'do x', created 40 d ago; observation_files inject_count 5, miss_streak 5
decayAndMarkIdle(db, { staleAge: now − 30 d })
PROBE {"before":{"importance":2,"injection_count":0,"access_count":0},"r":{"decayed":1,"idleMarked":0},"after":{"importance":1},"edge":{"inject_count":5}}
```
On the DB copy the exposed population is small today: of the 170 projected edges, 1 `missed` and 2 `neverInjected` edges have importance 2 with `injection_count = 0 AND access_count = 0` (the 88 `cited` edges have 0 — citing bumps `access_count`). The mechanism statement is what is false. A true wording: "the only age-based retirement for a lesson that has been cited or UPS-injected; a lesson only PreToolUse injects, never cited, is demoted out of the pool by `decay` at 30 days."
