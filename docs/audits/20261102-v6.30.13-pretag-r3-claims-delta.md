## Findings

### F1 (P2): CHANGELOG.md:32-36, a "Still stored" item narrower than reality
> "the shapes 6.30.12 lists, in text pasted into a prompt; a credential label at a line start or a double-quoted credential
> value in a JSON string, such as one a tool prints (...) or one written into a file (...), through the tool-call hook and import-jsonl"

The 6.30.12 list (CHANGELOG.md:60) reads "a credential label **or token** at the start of a line in a JSON string (`\nAPI_KEY=…`,
`\nghp_…`) (D#663)". The 6.30.13 clause for the hook and import-jsonl keeps "label" and drops "token". It therefore reads as if a
bare token after an escaped line break is now erased on those paths. It is not.

Repro: `node probe/token-linestart.mjs`. The text is `{"notes": "rotate this one:\n<token>\nthanks"}`, where `\n` is the escape.
The values are the longest run of the token that is kept:
```
cand ghp    len 40 | longest run kept: scrubSecrets 40 | hook(cat) 40 | import Write 40 Bash 40 MCP 40
cand akia   len 20 | longest run kept: scrubSecrets 20 | hook(cat) 20 | import Write 20 Bash 20 MCP 20
cand slack  len 54 | longest run kept: scrubSecrets 54 | hook(cat) 54 | import Write 54 Bash 54 MCP 54
cand sk     len 56 | longest run kept: scrubSecrets 56 | hook(cat) 56 | import Write 56 Bash 56 MCP 56
```
- **v6.30.12:** identical output, so this is not a regression.
- **Shape:** the project listed it itself in 6.30.12. In real transcripts (`node probe/real-escaped.mjs`), a token right after an
  escaped `\n` occurs 0 times in the 12 other projects and 2 times in -home-ai-dev-claude-mem-lite.
- **Fix:** "a credential label or token at a line start …".

A related P3 point on the same sentence: "in a JSON string" is narrower than "a string whose line breaks are escaped". A Python
bytes repr `b'FOO=1\nAPI_KEY=<V>\nBAR=2\n'` stores the value through scrubSecrets, the hook and import-jsonl (Write and Bash),
in both versions (`node probe/label-json-string.mjs`). This shape is constructed or rare.

### F2 (P3): CHANGELOG.md:18-20, the heading names only MCP results
> "`import-jsonl` stored credentials from a tool call's input and from an MCP tool's result, and lines of private keys"

MCP is not the only tool whose result is made of blocks. In real transcripts (`node probe/result-shapes.mjs`), block results by
tool are:

| Tool | Block results |
|---|---|
| Agent | 896 |
| ToolSearch | 537 |
| mcp__* | 368 |
| SendMessage | 194 |
| Read | 5 |

For comparison, there are 118,203 string results.

v6.30.12 stored a credential label at a line start in an Agent result, and 6.30.13 erases it (`node probe/claims-684.mjs`):
```
base | Agent result blocks, label at line start | V stored=true  ... [{"type":"text","text":"found:\nAPI_KEY=<V>\n"}]
cand | Agent result blocks, label at line start | V stored=false ... [{"type":"text","text":"found:\nAPI_KEY=***\n"}]
```
The heading understates the fix. That matters because the entry also says stored text is not rescanned on upgrade, so a reader
checking old imports would look at MCP rows only. Suggested wording: "a result made of blocks (an Agent's or an MCP tool's)".

### F3 (P3): CHANGELOG.md:28-29, the `grep "^API_KEY=" .env | …` example reproduces only conditionally
Text is erased only when a later double-quoted string follows on the same command (`node probe/claims-684.mjs`):
```
cand | grep "^API_KEY=" .env | cut      -> {"command":"grep \"^API_KEY=\" .env | cut -d= -f2"}   unchanged
cand | grep "^API_KEY=" .env | wc -l    -> unchanged
cand | grep "^API_KEY=" .env | sed "…"  -> {"command":"grep \"^API_KEY=\"***\"s/=.*//\""}
```
- **v6.30.12:** all three are unchanged.
- **Reading the example:** the "…" hides the condition. As written, the common forms (`| cut`, `| wc -l`) do not reproduce. What
  is erased is the text up to the next double quote.
- **The session_id example reproduces:** in `echo '{"session_id": "<SID>", …}' | node hook.mjs`, base stores the id and cand
  writes `***`. In a Bash string result, both versions already erased it.

### F4 (P3): CHANGELOG.md:14, the deletion of "with empty labels" un-states the population
> "On 100,000 generated config texts (247,410 values), 6.30.12 stored 4,417 values that 6.30.13 erases"

texts in general. Searching the tree for "247,410" finds only CHANGELOG.md, so the generator is not tracked and the three
numbers cannot be re-measured.

My own generator (`node probe/fuzz-683.mjs 100000 <seed>`, seeds 1-6) produces empty labels, values below labels,

- 247,385 to 247,436 values per seed.
- 6,075 to 6,084 values that base stored and cand erases.
- 982 to 988 values that cand keeps and base erased.
- 0 of those 982 to 988 are on a line that base erases when the line stands alone.

So the claim's structure holds.

Real transcripts (`node probe/real-683.mjs`; 7 of the 13 project dirs hold transcripts):
- 328,205 strings, of which 776 have a credential keyword, a separator and a line break.
- 9 lines differ between the two versions. All 9 are non-credential lines that cand now keeps, for example `  token:` followed
  by `    description: …`.
- 0 credentials are erased by cand only, and there are 0 counterexamples.
- This repo's own project: 111,119 strings, 295 with the shape, 0 differ.

### F5 (P3): tests/secret-scrub-empty-label.test.mjs:7
> "Each condition of the next-line label test has a row that fails without it (v6.30.13 r1)."

This is true for the seven conditions b692c874 names, dropped at all sites together. It is false for two other conditions of
the same lookahead. Each was dropped at all 6 unquoted sites, and each mutation was checked to have landed:
- **`.` and `-` dropped from the name class `[\w.-]{1,64}`:** 29/29 green. Then `  password:\n  client-secret: <V>` and
  `  token:\n  api-key: <V>` store V; pristine erases it (`node probe/dash-mutation.mjs`). Hyphenated YAML keys are a real shape.
- **The full-width `：` dropped from `[=：]`:** 29/29 green. Then `password:\nAPI_KEY： <V>` stores V. This shape is constructed.

Mutating one site at a time (`probe/mutate.mjs persite` and `probe/persite-observe.mjs`) gives a weaker result:
- For the seven named conditions there are 46 (condition, site) pairs. Only 5 of them have a row that fails.
- Of the other 41, 35 change the output of a site-specific input while all 29 tests stay green, and 27 of those 35 store the value.
- Example: `(?!=)` dropped at the prose-position `password:` site alone makes `the db password:\n  <V>==` stored.

### F6 (P3): tests/secret-scrub-empty-label.test.mjs:5-6
> "A value written on the line after its own label (YAML continuation, prettier's break after `=`, base64 padding, CRLF) is
> still erased"

A base64 value with a single `=` of padding, followed by anything else on its line, is read as a label. 6.30.13 stores it where
v6.30.12 erased it (`node probe/below-label-variants.mjs`):
```
base64 `=` then a YAML comment   password:\n  <V>= # rotated 2026-10   | base stored: false | cand stored: true
base64 `=` then `;`              const DB_PASSWORD =\n  <V>=;          | base stored: false | cand stored: true
value `a=b` below its label      token:\n  sv=<V>                      | base stored: false | cand stored: true
```
- **Shape:** constructed. None of the 9 real lines that differ between the versions has it. This is the only reason it is P3
  rather than P1.
- **Against CHANGELOG.md:15-17:** the claim itself holds, because base keeps each of these lines when it stands alone. The
  parenthetical reason given there ("no pattern covers its label") does not describe this case, though: here the value itself
  is read as a label.
