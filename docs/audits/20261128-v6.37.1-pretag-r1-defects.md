## Findings
**F1 P3, constructed. A typed leading pair stops a `<private>` redaction.** `lib/host-blocks.mjs:59-77` treats any well-formed leading pair as host text, including a pair typed right after the real block. `:105-110` then ignores an unclosed `<private>` inside that pair. Run end to end through each tree's `hook.mjs` user-prompt, the prompt `<browser_instruction><private></browser_instruction> my password is hunter2` is stored as:
- v6.37.0: `<browser_instruction>[redacted]`
- candidate: `my password is hunter2`

Repro: `node probe/leak-shape.mjs`. The same pair mid-prompt stays redacted.

**F2 P3, constructed: timestamp-less lines only. A new prompt is skipped as already imported.** The pre-pass at `lib/import-jsonl.mjs:485-489` adds a line's legacy key. The budget at `:492-498` then counts every row stored under that key. Prompts that v6.37.0 stored with identical text therefore count against each other's budget. That happens in two cases:
- an unclosed `<private>` in the block, so every typed text redacts to the same row;
- the 10000-character cap, when two pastes of a long log (over ~5.8 KB) differ only after the cap.

`node probe/import-legacy-collision.mjs`, v6.37.0 import followed by the candidate re-importing the transcript with one new line appended, in the same run:
| case | v6.37.0 → v6.37.0 | v6.37.0 → candidate |
|---|---|---|
| unclosed `<private>` in block | inserted=1 | inserted=0 |
| capped, shared prefix | inserted=1 | inserted=0 |
| timestamped control | inserted=1 | inserted=1 |

**F3 P3, test gap. The UPS sentinel test cannot fail.** `tests/user-prompt-search.test.mjs:975` seeds no observation, so stdout is `''` whatever the code does. With `scripts/user-prompt-search.js:774` reverted to `rawPrompt.startsWith(...)`, the full suite passes (only the same 2 sandbox-environment reds as v6.37.0). A seeded variant kills that revert.

**F4 P3, test gap. The suite has no timestamp-less re-import case without the cap.** The existing cases are `:458`, `:503` and `:546` at 10500 characters, and `:417`, which has a timestamp. The candidate's code is correct here. Two mutants survive the full suite and break it:

Repro: `node probe/legacy-uncapped-notts.mjs <tree>`.

## Answers to the brief's questions
- **Redaction compared with v6.37.0.** Generated inputs, 4 runs, 1.1M in total:
  - With no leading block, 0 differences from `stripPrivate`, byte for byte.
  - A region opening in the block and closing in typed text is never leaked (0 cases).
  - The only class where the candidate keeps text that v6.37.0 redacted: an unclosed opener inside a leading block (~19% of block inputs).
  - That kept text is user-typed. It was meant to be private only in the F1 shape.
  - Ruler mutation-verified (2761 hits on a crossing-region mutant).
- **Worst-case prompt cost.** Interleaved with v6.37.0 in the same run, at the real caps (load about 7):

  | shape | 64 KB (UPS cap), v6.37.0 → candidate | 256 KB (hook cap), v6.37.0 → candidate |
  |---|---|---|
  | worst: `<private>` packed in a block (17 scans) | 0.2 → 4.8 ms | 0.7 → 16.9 ms |
  | ~256 KB of leading whitespace | — | 0.06 → 5.3 ms |

  It is bounded and linear. Import of 30k lines: 2188 → 2202 ms.
- **import-jsonl pre-pass vs main loop.** The pre-pass skips the same lines the main loop does: blank lines, parse failures, non-user events, timestamped lines and `tool_result` parts with an id. Re-importing exactly what v6.37.0 imported added no row in 1,500 randomized replays, including shuffled order. Two caveats:
  - The pre-pass gate matches raw text, so a `<`-escaped file skips it. This is constructed.
  - The stripped-key seed at `:427` matched the legacy key exactly in my replays (identical outcomes on 800 replays). It looks redundant, but this is not proven.
- **Handoff.** The only callers are foreground hooks, which Claude Code gives `CLAUDE_PROJECT_DIR`:
  - Stop (`hook.mjs:1894`)
  - SessionStart (`:3365`)
  - UserPromptSubmit (`:3671`)

  The CLI, the MCP server and the background workers never reach them. Without the variable, PWD in a shell-launched hook equals cwd, which is v6.37.0's behaviour. The test-guard containment at `paused-reader.mjs:82` is unchanged.
- **Per-site regressions.** I mutated 23 sites one at a time and confirmed each mutation was applied. 18 are caught. The survivors:
  - UPS sentinel (F3)
  - import seed (`:427`, equivalent)
  - import count and guard (`:457` and `:485`, F4)
  - UPS empty return (equivalent, because later gates return)
- **Upgrading from 6.37.0.**
  - `swap-mixed-tree v6.37.0 → 9b16f159`: every entry point loads at all 174 split points.
  - `utils.mjs:37` still re-exports `stripPrivate`.
  - Full suite, same sandbox: candidate 10494 pass, 2 fail, 1 skip; v6.37.0 10441 pass, the same 2 fail, 1 skip. Both reds come from the environment (`MEM_NO_AUTO_ADOPT`, `CLAUDE_MEM_DIR`).
  - Rows already stored with the block are not cleaned: schema 49, nothing to run.
  - A prompt that is only the block now also skips handoff injection.
