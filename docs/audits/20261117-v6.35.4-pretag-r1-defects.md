# v6.35.4 pre-tag review: defects lens

Candidate `0b91f2296c9f3d909d41e0080c80efeaeda5f1ec` (checked with `git rev-parse HEAD` at the start and the end). Base: `v6.35.3`.

Setup: both revisions were extracted with `git archive` into `~/.cache/tmp/rv-6354-defects/{cand,old}`, with node_modules copied in. The mixed tree is in `.../mixed`. Every run used a sandbox HOME and CLAUDE_MEM_DIR, had LLM keys and proxies unset, and set TMPDIR inside my directory. The repro scripts are in `~/.cache/tmp/rv-6354-defects/probes/` and the sandboxes in `.../sbx/`.

Sanity check: the range's own tests, run in my tree (`npx vitest run tests/project-links-out.test.mjs tests/symlink-preserving-writes.test.mjs tests/audit-r7-adopt-boundary.test.mjs`), passed 42/42.

**Verdict: do not tag.** There is one P0 regression (F1) and one P1 regression (F2). Both come from the new rule that a link git lists as untracked was made by the user, together with the early `return null` for any link the user made. Under that rule the plugin writes the detail doc and the state file through links that a downloaded archive or a repository put in place. In 6.35.3 those two files were never written through any link.

## Findings

### F1 · P0 · An archive's untracked links make SessionStart overwrite any file they name (regression; 6.35.3 refused)

**Where:**
- `lib/project-link.mjs:40-41` returns null for a link it judges user-made (`if (made) return null`) before the whole-file refusal at `:46` runs.
- `userMade` at `:120-129` runs `git ls-files -z -s -o`. That lists every path that is not in the index, ignored paths included, because `--exclude-standard` is not passed. An untracked entry fails the regex, so `if (!m) return true`.
- The writes happen at `claudemd.mjs:441` (doc) and `:267` (state), through `lib/atomic-write.mjs:44`, which resolves the link and replaces the file it points to.

**Shape: REAL.** A project is downloaded as a zip or tarball: GitHub "Download ZIP", degit/tiged, a template, or an attachment. It carries a `CLAUDE.md` with the managed block, plus `.claude/plugin_claude_mem_lite.md -> <target>` and/or `.claude/.plugin_claude_mem_lite_state.json -> <target>`. Then one of these happens:
- (a) the user runs `git init` before the first `git add`, or
- (b) the archive is extracted anywhere inside an existing work tree: a monorepo's `vendor/` or `third_party/`, or a home directory kept as a git repo. Ignored paths count too.

Nothing more is needed than starting a session, because auto-adopt is on by default. Running `adopt` in such a project goes through the same `writeManaged` path.

A target inside the project can also be guessed. For example, `.claude/plugin_claude_mem_lite.md -> ../.env` overwrites the `.env` the user creates after unpacking.

**Repro:** `bash ~/.cache/tmp/rv-6354-defects/probes/F1-e2e.sh old`, then the same with `cand`. The script runs unzip, `git init`, then the real `hook.mjs session-start`.
- 6.35.3: `victim/dot-env` still reads `DB_PASSWORD=hunter2` and `victim/authorized_keys` still reads `ssh-ed25519 AAAA me@laptop`.
- Candidate: the hook exits 0. `victim/dot-env` now starts with `<!-- managed-by: claude-mem-lite -->` (the 10 KB detail doc) and `victim/authorized_keys` now reads `{ "version": "v1", ...`. The original contents are gone.
- Variant (b): `bash probes/B.sh cand outer` returns `{"ok":true,"action":"refreshed"}` and overwrites both victims. `B.sh old outer` refuses.
- Ignored-path variant (`sbx/homerepo`, outer `.gitignore` = `*`): `linkRefusal(...)` returns null.
- Outside any work tree, `B.sh cand none` refuses, which is correct.

**Expected:** refused, as in 6.35.3 (`a symbolic link; not written through`). **Seen:** the target is overwritten.

**Suggested direction (not tested):** write a whole-written file through a link only when the link's target is absent or provably the plugin's. For the doc that means the managed-by marker is on its first line; for the state file, that it holds the plugin's JSON keys. This keeps the dotfiles case this release wants and closes F1 and F2 without asking git.

### F2 · P1 · A committed detail-doc link is written through when reached via a `.claude` link the user made (regression)

**Where:** `lib/project-link.mjs:40-41`. A link the user made returns null for the whole rest of the path. A link the repository committed below it, which `:46` would refuse, is then never checked.

**Shape:** REAL repository content plus a layout users build. In a `git worktree`, the user replaces `.claude` with a link to the main checkout's `.claude` to share settings. The repository commits `CLAUDE.md` with the block and `.claude/plugin_claude_mem_lite.md -> ../../victim/file`.

**Repro:** `bash probes/F2-worktree.sh old` and `... cand`.
- 6.35.3: both sessions are refused and the victim file is unchanged.
- Candidate: the session in the main checkout is refused. The worktree session returns `{"ok":true,"action":"refreshed"}`, and `victim/file` now starts with `<!-- managed-by: claude-mem-lite -->`.

**Reach:** narrower than F1. It needs a hostile repository and that layout.

### F3 · P2 · On a case-insensitive file system, a cloned repository can pass a CLAUDE.md link off as the user's

**Where:** `lib/project-link.mjs:111-129`.

**Shape:** REAL on macOS (APFS default) and Windows. The repository commits `CLAUDE.md` as a regular file and `claude.md -> ../outside/file`. What happens:
1. In index order `CLAUDE.md` comes before `claude.md`, so the later entry (the link) is what stays on disk; git warns that paths collided. This step is reasoned, not run.
2. `lstat("CLAUDE.md")` finds the link.
3. `ls-files -s -o -- <root>/CLAUDE.md` matches the `100644 CLAUDE.md` entry. The pathspec is case-sensitive even with `core.ignorecase=true`, which I measured in `sbx/icase`.
4. `m[1] !== '120000'`, so the link counts as user-made.

**Repro (state after the clone, simulated on Linux):** `sbx/CI`, with index entries `100644 CLAUDE.md` and `120000 claude.md` and on disk `CLAUDE.md -> ../outside/target.txt`. Running `cli.mjs adopt` prints `created` and exits 0, and `outside/target.txt` grows from 1 line to 20. The candidate and 6.35.3 behave the same.

**Effect:**
- `adopt` appends the block to any file the link names.
- The sync and the legacy cleanup rewrite a target only when it already holds the block or the legacy span.
- 6.35.3 wrote through every CLAUDE.md link, so this is not a regression, but it falsifies claim 1 on these platforms.
- The doc and state file cannot be reached this way. Their all-lowercase names sort last, so the link left on disk is exactly the `120000` entry the pathspec matches.

### F4 · P2 · The `.git` exclusion compares names case-sensitively

**Where:** `lib/project-link.mjs:86` (`!segs.includes('.git')`). Node's `realpathSync` keeps the spelling written in the link.

**Shape:** REAL on macOS and Windows: a committed `.claude -> .GIT/info` or `CLAUDE.md -> .GIT/config`.

**Repro (the check alone, on Linux, using a real directory named `.GIT`):** in `bash probes/L.sh cand`, case L7b, `linkRefusal(root, '.claude/plugin_claude_mem_lite.md', {whole:true})` returns `null`. In L7 the lowercase `.git/info` target is refused.

**Effect on a case-insensitive FS (reasoned):** SessionStart writes the doc and state file into `.git/info/`. `adopt` appends the block to `.git/config`, and git then rejects that config. 6.35.3 had no `.git` check at all: in L7 it wrote into `.git/info`.

### F5 · P2 · `unadopt` on a refused CLAUDE.md exits 0, leaves the block, deletes the doc and state, and says "run adopt again"

**Where:**
- `claudemd.mjs:534` sets `skipped-symlink`, but `:545` and `:551` still delete the doc and the state file.
- The remedy text at `lib/project-link.mjs:49` and `:62` ends with "...then run adopt again". It is printed by `adopt-cli.mjs:1132` and `:1087`.
- `adopt-cli.mjs:1081` neither counts the skip nor sets an exit code.

**Shape:** REAL. A dotfiles-managed `CLAUDE.md` in a project outside git, or in a repo where git fails (F6), that was adopted under 6.35.3 or earlier.

**Repro:** in `sbx/L-cand/L2` (`CLAUDE.md -> ../dotfiles/projA/CLAUDE.md`, no git):
- `cli.mjs unadopt` prints `→ skipped-symlink`, then `⚠ left …/CLAUDE.md alone: a link git does not show as one you made (a cloned repository or an archive can carry one), to …, outside this project; not written through. Replace the link with what it points to, then run adopt again.` It exits 0. The block is still in the target (grep count 1) and `.claude/` is gone.
- `unadopt --all` prints the same line, then the summary `removed 0 CLAUDE.md block(s) … across 1 known project(s)`, and exits 0.
- 6.35.3 (`sbx/L-old/L2`) prints `→ removed` and the block is gone from the target.

The committed-link cases in `probes/U.sh` behave the same way:
- U1: the doc and state file are deleted while the block that points to them stays loaded through the link.
- U2: unadopt tells the user to "Delete the link, then run adopt again" about a committed file.

**Expected:** the remedy names unadopt (or removing the block by hand), the outcome does not read as success with exit 0, and the doc stays while its block stays.

### F6 · P2 · A git failure inside a work tree is treated as an untrusted link

Layouts 6.35.3 wrote are now refused, and the message blames an archive.

**Where:** `lib/project-link.mjs:97-103` and `:118-123`. Any git error gives null, which reads as "not shown as yours". When `gitTop` is null, only `root` counts as the project.

**Shapes: REAL.**
- A `safe.directory` refusal, when another user ID owns the repo: WSL on `/mnt/c`, a container bind mount, a shared checkout.
- git missing from the hook's PATH.
- The 5 s timeout on a slow file system.

**Repro:** `bash probes/L.sh cand`:
- L3 (`GIT_TEST_ASSUME_DIFFERENT_OWNER=1`, an untracked dotfiles CLAUDE.md link inside a repo): refused, and the block is not refreshed.
- L3b (no git on PATH): refused.
- L4b (a monorepo's `packages/foo/.claude -> ../../shared/.claude`, committed and inside the repo): refused as "outside this project".
- `L.sh old` writes L3 and L4b.
- `cli.mjs adopt` under L3 prints `error: … a link git does not show as one you made (a cloned repository or an archive can carry one) … Replace the link with what it points to` and exits 1. Running `git status` in the same repo prints "detected dubious ownership".

The CHANGELOG states the refusal outside git; it does not state this one.

### F7 · P3 · A refused SessionStart sync leaves nothing a user or `doctor` can see

`hook.mjs:3202` logs only `skipped project=… reason=error` at DEBUG level; the refusal text is dropped. With `adoptAction='skipped'`, nothing is injected (`hook.mjs:3411`). So a project whose sync is refused (L2, F6) never refreshes its block again and nothing says so. 6.35.3 reported its other sync errors through the same channel.

### F8 · P3 · A user's link that replaces a committed link is refused as "a link this repository commits"

`L.sh` L6: the repository commits `CLAUDE.md -> AGENTS.md`, and the user re-points it into a dotfiles tree. The candidate refuses; 6.35.3 wrote. This needs the user to re-point a committed link (CONSTRUCTED). The CHANGELOG's "in place of a tracked file" does not cover a tracked link.

### F9 · P3 · Inherited `GIT_DIR` / `GIT_INDEX_FILE` change git's answer

`project-link.mjs:95` passes `process.env` through to git. In `sbx/gitdir`, a committed `CLAUDE.md` link out of the repo is refused by default. With `GIT_DIR=<another repo>`, or `GIT_INDEX_FILE=<a missing file>`, `linkRefusal` returns null. CONSTRUCTED: it needs that environment, for example `claude -p` started from a git hook, which exports both variables. local-steering's existing git calls inherit them as well.

### F10 · P3 · Legacy cleanup: CRLF leaves a stray CR, and text after the end tag on its own line still gets joined (both as in 6.35.3)

**Where:** `hook-context.mjs:488` tests for "no LF right after the end tag", not for "end of file".

**Repro:** `bash probes/C.sh cand|old`.
- `keep this\r\n<span>\r\ntrailing\r\n` becomes `keep this\r\r\ntrailing\n`; the candidate matches 6.35.3.
- `…</claude-mem-context>## Notes` becomes `keep this## Notes`; again the same in both.
- The newline-terminated LF cases are fixed: the result is `keep this\ntrailing\n`, where 6.35.3 gave `keep thistrailing`.

**Shapes:** the CRLF file is REAL (`core.autocrlf` on a Windows checkout of a committed CLAUDE.md). The same-line text is CONSTRUCTED: the old writer always ended the span with LF (`4fe175c9^:hook-context.mjs`), so it takes a hand edit.

### F11 · P3 · Mixed tree (new `claudemd.mjs`, old `adopt-cli.mjs`; `SOURCE_FILES` 132–137) prints wrong unadopt messages

`mixed/` is 6.35.3 plus the new `lib/project-link.mjs` and `claudemd.mjs`; it loads.
- `unadopt` on L2 prints a bare `→ skipped-symlink` with no reason.
- `unadopt --all` prints `cleaned partial residue (detail doc/state, no block)` and `+1 partial-residue cleanup(s)` while the block stays in place.

No data is lost. The window is six renames, or a killed update until the next repair. I found no run-time break for SessionStart, adopt or `install.mjs status`: `install.mjs:3388` imports names that both versions export.

### F12 · P3 · Git cost and worst case

On a 1,000,000-entry index (88 MB) with 200k untracked files (`probes/big.sh`):

| Command | Time |
|---|---|
| `ls-files -z -s -o -- <root>/.claude` | 0.143–0.152 s (3 runs) |
| `rev-parse --show-toplevel` | 0.002 s |
| existing `git status --porcelain`, same repo | 1.189 s |

If git hangs, each refused file can cost 2 × 5 s (ls-files plus rev-parse), and the one-time cleanup another 2 × 5 s. SessionStart's timeout is 15 s. This only happens when git hangs, which already stalls local-steering's existing 5 s calls.

## Claims

1. **No link a repository commits makes the plugin write outside the repo or into `.git`.** This holds for a plain clone on a case-sensitive file system (A.sh, L7). It is falsified by F2 (Linux, reproduced), by F3 and F4 (case-insensitive file systems, reasoned) and by F9 (constructed environment).
2. **A link the user made is written through wherever it points.** This holds inside a work tree where git works (L1, L4, L5). It is falsified when git fails (F6) and for a user's link that replaces a committed link (F8). The converse the rule relies on, "untracked means the user made it", is false (F1).
3. **With no link on the path, no git process is started.** Holds: the shim saw 0 calls.
4. **`writeManaged` writes nothing when any of its three files is refused.** This holds for refusals: in A.sh, adopt errors and CLAUDE.md is unchanged, and the range tests pass 42/42. A failure that is not a refusal still leaves a partial write. With a dangling `.claude` link the user made, CLAUDE.md is refreshed and then `mkdir` fails with ENOENT. 6.35.3 does the same.
5. **Outside a git work tree, a link out is refused and adopt says what to do.** The refusal holds (L2, B.sh none). The "says what to do" part is weak: adopt and unadopt print the same remedy, so unadopt users are told to run adopt (F5). When git fails inside a work tree, the message names the wrong cause (F6).

## NOT CHECKED

- A real case-insensitive file system (macOS APFS, Windows NTFS). The F3 and F4 effects are reasoned; I did not observe git's collision outcome or the case `realpathSync` returns.
- Windows / Git Bash: backslash pathspecs, `rmdirSync` on a junction, clones with `core.symlinks=false`.
- `claude --worktree`'s own layout, including whether it links `.claude` into the worktree.
- A network file system or a hanging git. The timeouts were reasoned from the code, not induced.
- An archive that ships its own `.git` (a crafted index, or a gitfile pointing at another repo). By reading the code it is the same class as F1; not run.
- Index entries in a merge conflict (`100644` vs `120000` stages), and sparse or skip-worktree entries.
- The full suite, lint, coverage and the benchmark gates. I did not run `swap-mixed-tree.mjs` itself (it checks load time only).
- Races between `linkRefusal` and the write.
- Claims in docs/ and the README (the claims lens covers those).
