## Findings

### D1 — P0 — Project `.claude/settings*.json` is still read without bound on every node hook event
`scripts/hook-launcher.mjs:199-219` (`pluginDisabled()`, `readFileSync(path,'utf8')` at :210, called at module top level :219) and
`scripts/post-tool-use.sh:49-56` (`_settings=$(<"$_f")` at :54, called on every PostToolUse Read at :94).

hooks.json does not run `hook.mjs` directly. Every node hook goes through `hook-launcher.mjs`, which reads the user, project and local
settings scopes with a plain `readFileSync` before it imports the entry. The bounded `readSettingsScope` in `hook.mjs` therefore
never runs on this shape. The PostToolUse prefilter does its own unbounded bash read before anything else.

The release's test drives `hook.mjs` directly, not the launcher that hooks.json runs: `tests/project-files-not-regular.test.mjs:145-153`
("every hook event reads the project settings scopes" → `await import(hook.mjs)`).

Repro (REAL shape: git stores symlinks, so a cloned repository can contain `.claude/settings.json -> /dev/zero`, as the CHANGELOG itself says):
```
D=~/.cache/tmp/rv-6353-defects; source $D/env.sh; P=$D/projz; mkdir -p $P/.claude; ln -sfn /dev/zero $P/.claude/settings.json; cd $P
echo '{"session_id":"s1","prompt":"x"}' | ( ulimit -v 4194304; CLAUDE_PROJECT_DIR=$P timeout -s KILL 6 node $D/new/scripts/hook-launcher.mjs hook.mjs user-prompt ); echo rc=$?
printf '{"tool_name":"Read","tool_input":{"file_path":"%s/a"}}' $P | ( CLAUDE_PROJECT_DIR=$P timeout -s KILL 7 bash $D/new/scripts/post-tool-use.sh ); echo rc=$?
# full matrix: $D/matrix.sh new .claude/settings.json   (rows in $D/matrix.log: rc, wall ms, peak RSS KiB)
```

Uncertain: whether Claude Code itself survives a project `.claude/settings.json -> /dev/zero` (not checked). If the host stalls

### D2 — P0 (security, data loss) — Committed symlinks out of the project are written through at SessionStart
`adopt-cli.mjs:486-488` (session sync: `needsRefresh` → `writeManaged`), `claudemd.mjs:419` (`atomicWrite(dp, docContent)`),
`claudemd.mjs:250` (`writeState` → `atomicWrite`), `lib/atomic-write.mjs:44` (`realpathSync` — writes THROUGH a symlink on purpose, for
dotfiles-managed CLAUDE.md).

A cloned repository needs only three things: a CLAUDE.md that carries the claude-mem-lite managed block (the documented
"share it with the team" shape of `/adopt`), and `.claude/plugin_claude_mem_lite.md` and `.claude/.plugin_claude_mem_lite_state.json`
committed as relative symlinks pointing outside the repository. Then the first SessionStart (auto-adopt is on by default)
replaces the targets' content with the plugin's detail doc and state JSON. `git status` stays clean, so the user sees nothing.
```
D=~/.cache/tmp/rv-6353-defects; $D/symtest.sh new ss     # also: new adopt, old ss, old adopt
# builds $HOME/up (CLAUDE.md with the block; .claude/plugin_claude_mem_lite.md -> ../../../.victim-doc;
# .claude/.plugin_claude_mem_lite_state.json -> ../../../.victim-state), git clone → $HOME/dev/repo, runs SessionStart there
```
Seen (candidate and v6.35.2 alike): `victim-doc: <!-- managed-by: claude-mem-lite --> # claude-mem-lite 插件契约（完整）`,
`victim-state: { "version": "v1", "blockHash": ...`. Before the run both held `VICTIM-... original user content`.
`git status` was empty, and both links were still in place.
Expected: plugin-owned files in a project are never written outside the project.
REAL shape: any cloned repository can commit these symlinks, and the block is a shipped, documented team shape. The attacker
picks the target (a relative path from a guessable clone depth, e.g. `~/.bashrc`, `~/.ssh/authorized_keys`), but not the
content written, so the effect is destruction of that file. This is pre-existing, but the release reworked exactly these
reads and writes for "files a cloned repository can occupy". Its new bounded reader follows the same links: it read the
victim and found its text differed, which is what makes `needsRefresh` true.

### D4 — P3 — A CLI heal that never ran starts the 6 h wait
`lib/binding-probe.mjs:461` arms the marker before `rebuildBindingViaCli`. `install.mjs:4876`: rebuild-binding exits 1 when
install.lock is busy, and healAndReexec keeps the marker on failure.

Seen: first command: `[install] Another install/repair is in progress — it owns the rebuild; skipping.` and
`... — rebuild-binding exited 1`, with **0 npm runs**. After the lock was released, the next command printed
`automatic rebuild skipped: last attempted under a minute ago (one per 6 h)`, with 0 npm runs, although a rebuild would have
fixed it (fake npm in fix mode). The `Fix:` line is printed. If the lock holder fails or is killed, the CLI does not try
again for 6 h.
REAL: after a Node upgrade, the MCP launch (`scripts/launch.mjs`) and the SessionStart heal both rebuild under install.lock
while the user or a `/search` skill runs the CLI.
Other Q4 results — sequential, fake npm failing: 3 commands → 1 rebuild (2 npm calls), then 2 skips (83 / 77 ms).
Concurrent: 6 processes, and 16 processes × 3 rounds → exactly 1 rebuild per round, 15 skips. Hand-run `rebuild-binding`
during the wait: npm ran (not held back). On success the marker was removed, and the next `recent` opened the DB.
The re-exec guard prevents loops.

## Questions — answers and evidence

**Q1 (project-file reads).** Shipped reads of project paths reachable from hooks, adopt/unadopt and install status/doctor:
- Bounded on the candidate: `claudemd.mjs` (CLAUDE.md, CLAUDE.local.md, rules file, detail doc, state; every read goes through
  `lib/regular-file.mjs`); `readSettingsScope` (hook.mjs, isPluginDisabledForProject, adopt-cli `claudeMdExcludesSet`, install
  `projectPluginOverride`, `.mcp.json`); local-steering `package.json` / `.npmignore` / `.gitignore`; hook-context legacy cleanup;
  paused-reader (stat isFile + size, then read — a swap between the two calls needs a local process); reread-guard / file-intel
  (stat isFile + bounded read).
- Unbounded: D1 (launcher and Read prefilter, every hook event) and D8 (opt-in).
- Not committable: adopt-cli.mjs:576-581 reads the worktree `.git` file. git will not check out a `.git` path.
- Matrix (`$D/matrix.sh`, `$D/matrix.log`): 14 project files, each committed as a link to /dev/zero (CLAUDE.md, CLAUDE.local.md,
  .claude/CLAUDE.md, both settings scopes, .mcp.json, package.json, .npmignore, .gitignore, AGENTS.md, the rules file, detail doc,
  state file, tasks/x-paused.md). 17 surfaces each: SessionStart ±auto-adopt, UserPromptSubmit ×2, Stop, PreCompact, PreToolUse
  Read/Bash/Agent, PostToolUse Read/Edit, Edit recall, PostToolUseFailure, adopt, unadopt, status, doctor. Both trees.
- Candidate: only the two settings files misbehave (D1). Every other file stays under 140 MB and 700 ms. The adopt errors are D5.
  doctor exits 1 in every row, the control included (sandbox not installed).
- v6.35.2: CLAUDE.md, the detail doc, the state file, package.json and the paused note also reached 2.5–2.8 GB, so the release
  fixed those.
- The bounded reader still opens the device (O_NONBLOCK, then fstat), but never reads it. No side effect was found for an
  unprivileged user.

**Q2 (same result for regular files).** `$D/q2/cmp.mjs`: `readRegularText` vs `readFileSync(p,'utf8')` give identical text for
empty, CRLF, BOM (kept by both), Latin-1, surrogate, overlong, truncated, a 3-byte char across the 64 KiB chunk edge, and exactly
4,194,304 bytes. 4,194,305 bytes → null (old: text). Sites where null/throw now leads to a visible wrong action: D3 (unadopt over

**Q3 (plugin-disabled).** Answers differ between versions only for a scope that is not a regular file or is over 4 MiB.
- Not a regular file — v6.35.2 crashed or hung; the candidate's hook.mjs and status say "sets nothing", but the launcher still

- Over 4 MiB — v6.35.2 disabled; the candidate's hook.mjs, `isPluginDisabledForProject` and status say enabled while the

BOM, a directory, an unreadable file and a link to a regular file give the same answer in both versions.

**Q4 (cooldown).** See D4: one rebuild per 6 h in the sequential and concurrent runs; hand-run `rebuild-binding` is not held
back and clears the wait. What the user sees:
- first failure: stderr `[mem] native DB binding unusable — rebuilding for this Node (…)…`, then stdout
  `[mem] Error: … — rebuild-binding exited 1` and `[mem] Fix: … rebuild-binding`;
- inside the wait: `… — automatic rebuild skipped: last attempted N min ago (one per 6 h)` plus the Fix line.

Never rebuilding when a rebuild could fix it happens for up to 6 h after a failed or lock-skipped attempt (D4). That is by design
except for the lock case. No loop found.

**Q5 (time limits).** With the default exec:
- first probe: 30 s
- `npm rebuild … --dangerously-allow-all-scripts`: 240 s
- fallback `npm rebuild`: 240 s, only when the first throws
- verify: 30 s
- source build: **no limit**
- final verify: 30 s

A throwing npm step skips the source build.

Callers:
- CLI: `rebuildBindingViaCli` and the re-exec have no limit.
- `rebuild-binding`: per code home as above, under install.lock.
- `install`: `npm install` has no limit (pre-existing), then the steps above.
- `scripts/launch.mjs`: 10 s lock wait, then the steps above. Its source build is now unbounded (was 240 s). It is not a hook,
  and it blocks the MCP start for the whole compile.
- hooks: `binding-probe-cli.mjs` keeps 20 s per npm step and no source build (the injected exec's `timeout: 20000` overrides the
  new 240 s). `healNativeBindingIfBroken` runs detached. `attemptHeal` runs `repair` under a 300 s spawnSync inside a 15 s
  SessionStart (pre-existing).

No hook path newly blocks past its timeout. install.lock is held only by a live process during a compile; a dead holder is taken
over at once, and a live one after 1 h (`LIVE_HOLDER_MAX_MS`). Pre-existing: setup.sh's probe can take 8 + 20 + 20 + 8 s against a
30 s hook timeout.

**Q6 (mixed trees, run time).** 14 files differ between the trees (package-lock, source-files.mjs, regular-file, binding-probe,
plugin-key, claudemd, local-steering, adopt-cli, paused-reader, install, hook-context, hook, mem-cli, package.json). Scripts and

- SessionStart with auto-adopt, UserPromptSubmit, Stop;
- `recent`, `search`, `adopt`, `unadopt`;
- `install.mjs status` (also with a project-scope disable), `doctor`, `rebuild-binding`.

180 runs: 179 exit 0 with no TypeError, missing-export or missing-module text. The exception is k=2 `doctor` (rc 1). There the
new manifest lists `lib/regular-file.mjs` before that file has been copied, and doctor correctly reports `Managed files: 1 missing`.
install.mjs's namespace fallback for `readSettingsScope` is never exercised going forward, because plugin-key is swapped
before install.

**Q7 (publish.yml).** NOT CHECKED — api.github.com is unreachable without a proxy, and the brief forbids proxies. The only
local evidence is prose: Dependabot's commit message (dfeab644) gives the compare range `efb35369…8a0cd651` for 3.0.3 → 3.0.4.
