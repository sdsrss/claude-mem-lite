## Design

- **tdd-red** fires on both hook events. Conditions:
  - a test runner ran (`isTest` or `node --test`);
  - the output or command names test files (`*.test|spec.*`, `test_*.py`, `*_test.{py,go}`);
  - EVERY named file matches, on a path-segment suffix, a file that was edited.

  "Edited" means one of two things:
  - `entryEditedFiles(e)` for an episode entry from the same `ccSession`: an edit tool's `files`, or a Bash entry's `bashWrites`. It never means a Bash entry's `files`, which now also holds relative READS.
  - This call's own writes (`currentWrites`). The call joins the buffer only after recall has run, so it cannot be found there. PostToolUse passes the captured `bashWrites`; PostToolUseFailure runs `extractFileTargets` on the same cwd/project.
- **data-print** fires on PostToolUse only (exit 0 by construction). Every program in the line must be one of these, plus reads and neutral commands:
  - an inline script: `node|bun -e/-p/--eval/--print`, `python -c`, `python -`, or a heredoc-fed interpreter;
  - `gh … --log|--log-failed|--json`.

  The line is parsed with `isReadOnlyCommand`'s own statement/pipeline/substitution splitter (#239 applied).

  Exception: a stack frame in this repo's own source keeps the firing. That means an absolute path under `inferProjectDir()`, outside `node_modules`, and not `[eval…]`/`<stdin>`. This is the narrowest form that works on the data: it admits 0 of 41 printer firings. The looser "repo path:line anywhere" form admits 2, and both are wrong: a printed review note, and an `[eval1]`-only crash.
- The gate is metered as `error_recall_suppressed {reason, exitZero}` and fails open.

## CHANGELOG-ready paragraph

**error-recall no longer injects on a deliberate TDD RED or on printed error text (N2).**
- **TDD RED:** a test run is silent when every test file it names was edited earlier in the episode by the same session, or by the same Bash call. "Edited" means an Edit/Write/NotebookEdit or a Bash write, on both PostToolUse and PostToolUseFailure. Reading a test does not count.
- **Printed error text:** an exit-0 command whose only programs are inline scripts (`node -e`, `python3 -c`, `python3 - <<EOF`) or `gh … --log/--log-failed/--json` reads is silent too, unless a stack frame points into the project's own source.
- **Measured:** replaying 199 local session transcripts in one walk, 466 of 1107 firings go quiet: 423 TDD REDs and 43 printers. Suppressions are metered as `error_recall_suppressed`.

## Not done / residual

- **Outcome not measured.** The per-face cite rate from `citation-live-replay --split` needs transcripts from after deploy.
- **`pending-*.json` entries are not consulted.** Those are episode entries written when the lock timed out, so a RED right after a lock timeout still fires.
- **Only the current episode is consulted.** An edit flushed out of the buffer (after 10 entries or a 5-minute gap) no longer makes a later RED of that test deliberate.

That clobbered this worktree's index, recovered with `git reset -q`. It may also have written core.bare again; I did not observe that. All later commits reused a green stamp.
