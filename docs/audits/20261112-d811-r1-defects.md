- Regression in output vs v6.33.0 (6.33.0 printed no "Data purged" line here, only "Done!"/exit 0, and kept the link); falsifies claim 2 as implemented.
- install.mjs:1988-1995. `realpathSync(DATA_DIR)` is in a bare `catch { /* the target is gone */ }`; any errno (EACCES on an ancestor, ELOOP from a long chain, EIO/ESTALE on a network mount) yields `target = null` -> `ok('Data purged (~/.claude-mem-lite/ was a link to nothing)')`, no purgeIncomplete. Same class the neighbouring relocated branch already fixed with `err.code` (install.mjs:2019 "Not existsSync: it is false on EACCES too ... then Done!", R32 depth-2 M1). The null branch also does not name where the link pointed, so a target on an unmounted volume (ENOENT, real shape) also reads "Data purged" with no hint where the data is.
- Severity: false deletion report; reproduced shape (EACCES) is constructed, EIO/ESTALE analogues not reproduced -> P2 rather than P1.
