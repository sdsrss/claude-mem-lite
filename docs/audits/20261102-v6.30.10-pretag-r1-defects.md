## Findings

### F1 [P2] Q3: short escapes before quoted BEGINs at several escape depths, 17-28x benign under coverage (v6.30.9 2.3-3.5x)

Location: `secret-scrub.mjs:577` `const LINE_START_SCAN = 4096;` (was 256 in v6.30.9) and the walk in
`lineStartPastQuotes` `:955-:983`: every stop costs one loop iteration with a sticky lookbehind exec
(`:961` LINE_BACK_RE, `:973` BACKSLASH_BACK_RE), and an escaped quote also a JS `backslashesBefore` (`:981`).
D#642 passes a LONG backslash run in one step, but a region of many SHORT runs (`\t`, `\a`, `\"`) is still one
iteration per run, up to 4,096 characters back per BEGIN. Walks of BEGINs at different escape depths do not stop
at each other's breaks, so every BEGIN of a depth cycle walks the whole region; nothing is erased (both trees
return the same text), so the CHAIN keeps every BEGIN for all 32 passes.

Input (`tabRegion4`): CHAIN + ' ' + unit repeated to 200,000 chars, unit = the two characters `\t` x 2,048,
then for d in 1, 2, 4, 8: `'-----BEGIN RSA PRIVATE KEY-----` + `\`xd + `n-a: b` + `\`xd + `n`.
`bsaRegion<k>` uses `\a` and depths 1..2^(k-1); `escQuoteRegion1` uses `\"` x 2,048 and depth 1 only.
Output: identical in both trees (sameOut true).

Repro: `/home/ai/.cache/tmp/rv-6310-defects/repro/q3-escape-region.sh` (plain node via `q3/time.mjs` +
`q3/shapes-new.mjs`; vitest via `x-rv-linear.test.mjs` copied into each tree with `rv.vitest.config.mjs`,
the repo's v8 provider and include list, results in `q3/rvratios.txt`).

### F5 [P3] Q5: lineStartPastQuotes is not nextLine's line start at depth > 0 (same in v6.30.9)

Location: `:955-:983`. It matches v6.30.9's character walk at the same bound on 600,000 fuzzed texts and 4,368
boundary texts, but against nextLine semantics, `repro/q5-linestart-divergence.mjs`:
```
(a) "ab\\\ncd'-----BEGIN RSA PRIVATE KEY-----\\nMII\\n" (u=1)  lineStartPastQuotes = 4, nextLine line start = 0
(b) "x = 'a\\n' +\n  '-----BEGIN RSA PRIVATE KEY-----\\nMII\\n" (u=1)  lineStartPastQuotes = 12, nextLine = 15
```
(a) a real newline right after a backslash: nextEscapedLine steps over it, the walk (like prevLine) stops there.
(b) a single-quoted concatenation: nextLine starts the BEGIN's line after the opening quote; the walk goes past
the quote to the physical indentation, so `isDiffContextLine` (`:884`) treats any indented single-quoted JS
concatenation as a diff context line (the input of F3's example and of r1 F4). No output change was traced to
(a); (b) is the entry to the context reading for those inputs.
