## 发现

### F1（P2，回归，构造形状）：标签下一行的值开头像标签时不再擦除
- 位置：secret-scrub.mjs 的 14 个位点。NAME 形式在 90、131、135、140、155、279 行（`[*~\`]{0,3}[\w.-]{1,64}[*~\`]{0,3}…(?:[=：](?!=)|:(?=[\s'"]))[^\S\r\n]*\S`）；引号形式在 182、186、190、196、269、320、333、349 行（`(?:"…"|'…')[^\S\r\n]*[:=：]`）。
- 机制：下一行只要以 `[\w.-]+` 开头、后面紧跟 `=` 加非空字符（或 `：`、`: `），就被当成“标签行”拒绝，于是标签自己的值也没被擦掉。引号形式的规则把 `"值" ===` 和 `"值":` 也当成标签。
- 复现：
  - `node probes/s2-per-pattern.mjs`：14 个位点各一例，全部是 `base erased | cand STORES`；对照组（普通值写在标签下方）两边都擦除。
  - `node probes/save-path.mjs`（saveObservation，即 mem_save / CLI save 路径）：输入 `password:\n    Ab3=<V>`，6.30.12 擦除，候选存为 `"…password:\n    Ab3=<V>\n"`。
  - `node probes/hook-desc.mjs`（makeEntryDesc，工具调用钩子的条目描述）：Bash `cat secrets.yml` 和 Edit new_string 两例都是 6.30.12 擦除、候选存下。
  - `ARM=raw N=30000 node probes/gen-scrub.mjs`：生成的 1,881 个“写在已覆盖标签下方、带内部 `=`”的值里，6.30.12 擦除 1,412 个，候选保留其中 1,255 个。
- 范围：只影响原始文本路径（钩子、prompt、save）。import 不受影响：JSON 外层的整体扫描在 6.30.12 里本来就没擦这类值，两边都存。两个 Node 版本结果相同。
- 真实性：形状是我构造的。791 份本机 transcript 里出现 0 次（见下文语料差分）。现实中可能的写法：带 `=` 的密码写在 YAML 标签下一行；单个 `=` 填充的 base64 后面跟注释（`abcdef1= # rotated`）；prettier 把 `"…" === x` 折到 `=` 的下一行。
- 与说法的关系：提交说明写的是“值可以从下一行开始，除非那一行以自己的标签开头”。实现上标签的判定是 `NAME=非空`，所以这类值被误判成标签。CHANGELOG 说“96 个值……不被任何模式覆盖”，按它字面的判据（值所在行单独存在时 6.30.12 也保留），这一类恰好也满足，所以 CHANGELOG 没有把它列成单独一类。

### F2（P3，回归，已整体披露）：`.env` 空凭据标签下一行的未覆盖 `NAME=value` 现在被存下
- 例子：`DB_PASSWORD=\nENCRYPTION_KEY=<V>`。6.30.12 把下一行整个 `NAME=value`（中间没有空格）当成值擦掉了，候选保留。同类名字还有 SECRET_KEY_BASE、APP_KEY=base64:…、SESSION_KEY（`DATABASE_URL=` 打头时也一样）。
- 复现：probes/s-cases.mjs 的 S1、S1b、S1c、S20；probes/save-path.mjs 的 S1；probes/hook-desc.mjs。
- 披露情况：CHANGELOG.md 17–19 行已整体披露（“96 个值……该行单独存在时 6.30.12 也保留”）。但给的例子是全角冒号 `DATABASE_URL：`，读者看不出常见的 `.env` 写法（未覆盖名字 + `=` + 不带空格的值）也在这一类里。
- 真实性：语料里 0 次。

### F3（P3，既有问题，说法被证伪）：以自己标签开头的下一行仍被吃掉
上面那句“除非那一行以自己的标签开头”在另一个方向也不成立。下面几种情况 6.30.12 和候选输出相同，泄漏都还在：
- (a) 连续两个空标签，值写在第二个标签下方：`  POSTGRES_PASSWORD:\n  JWT_SECRET:\n    <V>` 和 `password:\napi_key:\n  <V>` 两边都存 `<V>`。
  - 原因正是候选自己加的“分隔符后面必须有非空字符”（`[^\S\r\n]*\S`）。去掉这一条的变体会把两例都擦掉，3 个守卫用例的输出不变（`node probes/s6.mjs`）。
- (b) Markdown 冒号写在加粗里面：`**Password:**\n**API_KEY:** <V>`，两边都存 `<V>`。D#128 的模式接受分隔符后面跟 `**`，新的前瞻不接受。
- (c) 分隔符后面是 U+2028、`\f` 或 `\v`（构造形状）：这几个字符落在 `[^\S\r\n]` 里，被当成水平空白。
- (d) 名字超过 64 个字符（构造形状）。
- 复现：probes/s-cases.mjs 的 S3、S5、S5b、S5c、S6、S12。
