## Claims to falsify: verdicts

- **"repair-db writes nothing to the store, and leaves it byte-identical, whenever it refuses": FALSIFIED** (F4). Two refusal paths write first: the probe-saw-damage path and the backup-error path. Both run the exclusive probe, and its close checkpoints the log into the main file. In the repro, the main file alone read 595 observations before the refusal and `SQLITE_NOTADB` after it. Separately, every refusal of a store that has no -wal leaves a new empty -wal and a -shm behind (main bytes unchanged). That happened on all 62 + 51 refusals of the two main-file sweeps (seeds 21 and 22).
- **"When repair-db exits 0, every row the old store could read is in the repaired store, or the output names it": FALSIFIED.**
  - F3: a store from a newer schema whose schema_version page is damaged. Exit 0, the newer column and all its values are dropped, the store is stamped v49, and no line says so.

- **"A connection opened before the repair and used after it leaves the repaired store sound": HOLDS** in what I ran. - **"The store as found is kept byte for byte": HOLDS.** Main file and log matched (sha1) in every repair of the three sweeps, and in the targeted log and big-store runs. The -shm is not kept; it holds no rows.
- **"The printed set-aside and restore lines, run twice, never overwrite the kept files": HOLDS.**
  - Setup: sh, dash and bash; a data dir named `we ird'$HOME\x "q" …`; with and without a non-empty -wal; set-aside and restore. Between the two runs, a "next session" store and -wal were written.
  - Run 1 exited 0 and kept the main file and log under the `.damaged-` names.

## F1 — P1 — rows a damaged cell count drops are lost with no line whenever no full index of the table reads to the end

**Where:** lib/db-repair.mjs:257-367 (copyTable) and 807-820. The gap warning is printed only for a scan that *threw* (`r.gaps`), and only when `!r.indexed`. Index lookups recover dropped rows only when a full index iterates to its end.

**Why it is silent.** A leaf whose cell count is damaged ends a scan early **without an error**. So nothing is reported when either:
- the table has no full index: deferred_work's only indexes are partial (idx_deferred_open, idx_deferred_closed_by), and `INDEXED BY` a partial index fails "no query solution";
- or its only full index is itself damaged: observations has exactly one full index, idx_obs_epoch_project; its other five indexes are partial.

**Repro 1, the shipped command** (Appendix B `dw.mjs` builds 40 deferred_work rows on leaves 64 and 65, then sets leaf 64's cell count to 1):
```
rows SQLite reads after the plant: 20
$ node install.mjs repair-db
  ⚠ SQLite's integrity check fails: Fragmentation of 3732 bytes reported as 0 on page 64
  ✓ Copied 25 rows into a fresh file, checked it, rebuilt its search indexes, and wrote it into …/claude-mem-lite.db.
  ✓ The store as found is kept as …damaged-2026-10-21T23-44-49-708Z — delete it once you no longer need it.
exit=0
after repair: deferred_work rows 20 seq 40
$ node install.mjs doctor  →  ✓ Database integrity: ok
```
- 20 of 40 deferred items are gone, exit 0, and no line names deferred_work.
- doctor is green afterwards, and the output tells the user the only copy holding them can be deleted.
- The same happens through a log frame: log sweep seed 13, plant 520, deferred_work page 60 cell count → 1: 29 rows lost, no line.

**Repro 2: observations, two damaged pages** (Appendix B `obs2.mjs`: an observations leaf's cell count → 1, plus the header of an idx_obs_epoch_project leaf a third of the way along):
```
leaf[5]:  observations before 1195 after 1193 | missing reported 0 indexed false gaps 0
leaf[9]:  observations before 1195 after 1182 | missing reported 0 indexed false gaps 0
leaf[15]: observations before 1195 after 1184 | missing reported 0 indexed false gaps 0
[ok] Copied 3892 rows into a fresh file, … (no observations line)
```

**Sweep:** UNREPORTED loss on the index-less tables `zz_noindex` and `zz_values` in 3/800 main, 1/300 two-leaf and 9/800 log plants. Example: zz_values cell count → 1 lost 59 of 60 rows with no line.

**Correct:** when the store fails integrity_check and a table was not covered end to end by a full index, report that table as possibly incomplete. Better, map integrity_check's page numbers to their tables through dbstat and name the table, or compare the rows read with the per-page cell area. Never print only "✓ Copied".

**Where:** lib/db-repair.mjs:643 (`if (built.reason === 'unreadable' && sizeOf(wal) > 0)`) and 496-499. The main-file-alone fallback runs only when the store will not open, or when exactly zero observations read. A log frame that hides most of a table, but not all of it, keeps the with-log copy.

**Repro** (Appendix B `interior.mjs`: log variant, the newest log frame of observations' interior root page gets cell count → 1):
```
observations page 5 | store with log reads 1495 | main file alone reads 1195
$ node install.mjs repair-db
  ⚠ observations: 1474 row(s) an index lists could not be read (ids 12, 13, … and 1464 more).
  ✓ Copied 3725 rows into a fresh file, checked it, rebuilt its search indexes, and wrote it into …
  ✓ The store as found is kept as … and …-wal — delete them once you no longer need it.
```

- 1,474 rows are reported as unreadable, but 1,195 of them read from the main file the repair itself kept.

## F3 — P1 — a store from a newer schema whose schema_version page is damaged is "repaired" to v49, dropping the newer columns silently

**Where:** lib/db-repair.mjs:455-460 and 280. When the version cannot be read, `hasLatestMigrationColumn` (true for a newer store) lets the copy proceed. `cols` is `oldCols ∩ freshCols`, so a column the fresh schema lacks is dropped, and no line ever reports a dropped column. schema_version is not copied (line 488), so the fresh v49 stamp stands.

**Repro** (Appendix B `newer.mjs`: `ALTER TABLE observations ADD COLUMN v50_payload TEXT`, filled; `schema_version` → 50; the schema_version page header damaged):
```
repaired 0
[warn] SQLite's integrity check fails: Tree 63 page 63: btreeInitPage() returns error code 11 (and 1 more)
[ok] Copied 1051 rows into a fresh file, checked it, rebuilt its search indexes, and wrote it into …
columns now: 0 | schema_version: [ 49 ]
```

**Why this path is realistic.** A stale code home is a known product state (CLAUDE.md, "A DB written by a NEWER claude-mem-lite locks every older code home out"). A damaged schema_version also makes that older tree's SessionStart report a damaged store rather than skew, and its notice prints that tree's `cli.mjs repair-db`. The newer tree then sees v49 and re-runs its migration onto an empty column.

**Correct:**
- Refuse when the version cannot be read and any old table has a column the fresh schema does not.
- In general, refuse (or name the column) whenever `oldCols` contains a column outside `freshCols`, since the contract says "refuse … when the store is at another schema version".

## F4 — P1 — a refusal after the probe or the backup writes the log into the main file; the store can end up unreadable, and later faces never mention the checked copy

**Where:** lib/db-repair.mjs:722-763. probeExclusive (131-149) opens read-write. When `BEGIN EXCLUSIVE` fails on damage, or `source.backup()` fails (`swap.probe` not busy, or `swap.backupError`), the probe has already closed as the only connection. That close checkpoints the -wal into the main file and deletes it. The run then exits 1, "so it was not replaced". The comment at 746-748 and README.md:1003 say it writes nothing in such a case.

**Repro** (Appendix B `page1.mjs`: log variant with VACUUM, the newest log frame of page 1 gets 64 × 0xff; this is the suite's "cannot write through the file" plant):
```
refused 1
[fail] SQLite cannot write into …/claude-mem-lite.db (file is not a database), so it was not replaced.
[info] The checked copy is ….repaired-2026-10-21T23-47-00-697Z; the store as found is kept as ….damaged-2026-10-21T23-47-00-728Z. …
before { main: 'ee134e092949', wal: 'ff18b2efa1e2', alone: 595 }
after  { main: '73fe79149000', wal: null,          alone: 'SQLITE_NOTADB' }
```

**Consequences:**
- Before the run, any session start would have dropped the log (ensureDbWithWalRecovery) and read 595 observations from the main file. Now the main file is not a database.
- If the user does not run the printed `rm … && mv …` line right away, the next `repair-db` sees the main file as not a database. It prints only the set-aside ("so the next session creates a fresh store") and never mentions the `.repaired-…` checked copy or the earlier `.damaged-…` pair.
- doctor likewise names only repair-db.
- The data survives only in files no face points to.

Measured second run:
```
  ✗ SQLite cannot read …/claude-mem-lite.db: file is not a database. Nothing was written to the database.
    No backup snapshot exists beside the database. This command sets the damaged file aside so the next session creates a fresh store. …
```
The disk-full backup failure takes the same branch (F14, measured): the main file is changed by the probe's checkpoint, and the run exits 1.

**Correct:** probe without a checkpoint-on-close: keep the probe connection open and do the backup through it, or use `SQLITE_FCNTL_PERSIST_WAL` / a read-only lock probe. On any refusal, leave the main file and log as found. A refusal that leaves a checked copy should be found and named by later runs (doctor / repair-db / SessionStart).

## F5 — P2 — a save committed between the probe and the backup's first step is lost from both the store and the kept file

**Where:** lib/db-repair.mjs:722-735. The last storeState check (723) and the probe come before `new Database(tmp)` and `backup()`. The probe releases its exclusive lock on close. After that nothing re-checks the store; the backup's first step copies every page over whatever was committed since.

**Repro, fault-widened** (Appendix B `window.mjs`: `Database.prototype.backup` delayed 1.5 s; a child commits a deferred_work row at 0.7 s):
```
repair: repaired 0 | child: child saved id 8
row in repaired store: 0
row in kept file: 0
```

**Window without injection** (`wintime.mjs`, 3 runs): storeState → probe closed 0.23-0.25 ms; probe closed → `backup()` called 0.05 ms; then one setImmediate to the first step.

**Likelihood.** Small but real:
- Hooks honour the barrier only at launch, so a spawnBackground child or a hook that started earlier and opens late is not stopped.
- The MCP server and CLI do not check the barrier.
- On SQLITE_BUSY at the first step, better-sqlite3's backup retries, so a writer that began in the window commits and is then overwritten.

**Correct:** record the store's state right after the probe closes. Compare it again once the backup's destination holds its write transaction, i.e. after the first step (better-sqlite3's `progress` callback runs after each step), and abort the backup if the state moved. Alternatively, make the probe and the write-back one connection, so the exclusive lock is never released between them.

## F6 — P2 — "a row could not be written" refusals are a dead end: no next step, and doctor keeps sending the user back

**Where:** lib/db-repair.mjs:682-692. **How often:** 56/530 (10.6 %) of integrity-failing single main-file plants, 49/554 (8.8 %) of log-frame plants, and 49/272 (18 %) of two-leaf plants end here. In the sweep these are almost all garbage cells decoded from a damaged page: misdirected cell pointers yield rows with NULL in NOT NULL columns, out-of-domain CHECK values, or duplicate rowids.

**Repro** (Appendix B `deadend.mjs`: observations leaf 87, first two cell pointers → 0x0000 / 0xffff):
```
$ node install.mjs repair-db
  ⚠ SQLite's integrity check fails: Tree 5 page 87 cell 1: Offset 65535 out of range 196..4092 …
  ✗ observations: 2 of 295 rows could not be written to the fresh file (NOT NULL constraint failed: observations.memory_session_id).
    Nothing was written to the database.
exit=1
$ node install.mjs doctor
  ✗ Database integrity: Tree 5 page 87 cell 1: …
      Once every Claude Code session is closed, run: node …/cli.mjs repair-db — it copies every row SQLite can still read …
```
The "2 of 295 rows" are two garbage rows that replaced the two real cells; the table still scans 295. Nothing tells the user what to do. doctor exits 1 forever, with a remedy that refuses.

**Correct:**
- Name the rows by rowid and table, and offer a way through: skip them and report them by id, or keep them in the kept file. The p10-v5 rationale is a whole-column NOT NULL failure; that can stay a refusal by ratio or by column, rather than by a single row.
- Or print the snapshot / set-aside fallback on this refusal too, the same way `refuseUnreadable` does.

## Checked, no defect

- **Value fidelity:** BLOBs with NUL bytes, ±2^63 and 2^53+1 integers, REALs, and TEXT with embedded NUL are identical after repair: 0 "changed" rows over 1,194 repairs. Lone surrogates are already stored as U+FFFD by better-sqlite3, so they round-trip. Invalid UTF-8 written by `CAST(x'ff' AS TEXT)` would come back as EF BF BD; the product has no such writer.
- **Rows only in the log:** 0 lost in non-fallback repairs (log sweep). The kept main file and -wal equal the store as found in every repair. The undo line restored both byte-for-byte in sh and dash, run twice.
- **Two damaged leaves of an indexed table:** the rows between them are recovered through the index (two-leaf sweep: 0 unreported or named loss on product tables except deferred_work's class, F1).
- **Tables created on first use** (search_runs, search_results, migration_cursors) and custom tables are copied with their indexes; no table was dropped in any sweep.
- **AUTOINCREMENT:** the seq is kept (deferred_work seq 40 with 20 rows after the F1 repro, so no id is reused); the suite's id-301 test passes.
- **Symlinked database path:** a write through the link during the repair is detected ("changed while it was being read"), and the link stays a link.
- **A connection opened before the repair and used after it:** sound (verdict above).
- **A child opening, reading and writing throughout:** 4/4 repairs refused, 0 SQLite errors in the child.
- **The real MCP server (server.mjs) holding the store:** "Another process has … open", exit 1.
- **8 concurrent runs (with PID-namespace lock stealing):** no file damaged in 3 trials, row diff 0.
- **SIGKILL at 12 points of a 389 MB repair:** the store is always either the original or the sound repaired store, never a new damage.
- **Set-aside and restore lines:** sh, dash and bash, awkward path, with or without -wal, run twice: correct, and they stop at `ln` (verdict above).
- **SessionStart human notice, doctor ✗ Database, and the server FATAL line** all name repair-db for a not-a-database store. The note comes before the command. The server no longer says "Try: rm <wal> <shm>" (v6.30.3 did).
- **`node cli.mjs repair-db`:** dispatches; exit codes 0/0 (repaired, then nothing to repair); `--help` prints the install usage.

```js
/** A rich store. Returns { p }. With `log`, some rows exist only in the -wal, and some main rows are updated/deleted there. */
export function richStore(dir, { obs = 1200, log = false, pageSize = 4096, vacuum = false } = {}) {
  mkdirSync(dir, { recursive: true });
  const p = join(dir, DB);
  const db = new Database(p);
  db.pragma(`page_size = ${pageSize}`);
  db.pragma('journal_mode = WAL');
  db.pragma('foreign_keys = OFF');
  initSchema(db);
  db.pragma('foreign_keys = OFF');
  ensureSearchTelemetrySchema(db);
  db.exec(`CREATE TABLE IF NOT EXISTS migration_cursors (name TEXT PRIMARY KEY, below_id INTEGER NOT NULL)`);
  db.prepare(`INSERT INTO migration_cursors VALUES ('obs-terms', 777)`).run();
  db.exec(`CREATE TABLE zz_values (id INTEGER PRIMARY KEY AUTOINCREMENT, b BLOB, big INTEGER, r REAL, t TEXT)`);
  db.exec(`CREATE TABLE zz_noindex (a TEXT, b INTEGER)`);
  for (let i = 0; i < 20; i++)
    db.prepare(`INSERT INTO sdk_sessions (content_session_id, memory_session_id, project, started_at, started_at_epoch) VALUES (?, ?, 'p', datetime('now'), 1)`).run(`c-s${i}`, `s${i}`);
  db.exec('BEGIN');
  fill(db, { obs });
  db.exec('COMMIT');
  db.prepare('DELETE FROM observations WHERE id > ?').run(obs - 5); // seq > max(id)
  db.pragma('wal_checkpoint(TRUNCATE)');
  db.close();
  if (!log) return { p };
  const pristine = readFileSync(p);
  const raw = new Database(p);
  raw.pragma('foreign_keys = OFF');
  raw.exec('BEGIN');
  fill(raw, { obs: Math.floor(obs / 4), start: obs + 10, tag: 'late' });
  raw.exec('COMMIT');
  raw.prepare(`UPDATE observations SET title = title || ' updated' WHERE id % 50 = 0`).run();
  raw.prepare(`DELETE FROM user_prompts WHERE id % 97 = 0`).run();
  if (vacuum) { raw.exec('VACUUM'); raw.prepare(`INSERT INTO deferred_work (project, title, created_at_epoch) VALUES ('p', 'after vacuum', 5)`).run(); }
  const walBytes = readFileSync(`${p}-wal`);
  const mainNow = readFileSync(p);
  raw.close();
  writeFileSync(p, mainNow);
  writeFileSync(`${p}-wal`, walBytes);
  rmSync(`${p}-shm`, { force: true });
  return { p, pristineMain: pristine };
}

/** Ordinary tables (not FTS) → Map(rowid string → JSON) */
export function record(p, { readonly = true } = {}) {
  const db = new Database(p, { readonly, fileMustExist: true });
  try {
    const all = db.prepare(`SELECT name, sql FROM sqlite_master WHERE type='table'`).all();
    const virtual = all.filter((r) => /^CREATE VIRTUAL/i.test(r.sql || '')).map((r) => r.name);
    const out = {};
    for (const { name: t } of all) {
      if (virtual.includes(t) || virtual.some((v) => t.startsWith(`${v}_`)) || t === 'sqlite_stat1') continue;
      const m = new Map();
      for (const r of db.prepare(`SELECT rowid AS __rowid, * FROM "${t}" ORDER BY rowid`).safeIntegers(true).iterate()) {
        m.set(String(r.__rowid), ser(r));
      }
      out[t] = m;
    }
    return out;
  } finally {
    db.close();
  }
}

/** Per table, which truth rowids a rowid lookup on `p` can read (on whatever handle state p is in, read-only). */
export function readable(p, truth) {
  const out = {};
  let db;
  try {
    db = new Database(p, { readonly: true, fileMustExist: true });
  } catch (e) {
    return { __error: e.code || e.message };
  }
  try {
    for (const [t, rows] of Object.entries(truth)) {
      const m = new Map();
      let stmt;
      try {
        stmt = db.prepare(`SELECT rowid AS __rowid, * FROM "${t}" WHERE rowid = ?`).safeIntegers(true);
      } catch (e) {
        out[t] = { error: e.code || e.message, rows: m };
        continue;
      }
      for (const id of rows.keys()) {
        try {
          const r = stmt.get(BigInt(id));
          if (r) m.set(id, ser(r));
        } catch {}
      }
      out[t] = { rows: m };
    }
  } finally {
    db.close();
  }
  return out;
}

export function pageMap(p) {
  const db = new Database(p, { readonly: true });
  try {
    return db.prepare(`SELECT pageno, name, pagetype FROM dbstat ORDER BY pageno`).all();
  } finally {
    db.close();
  }
}

export function plantMain(p, pageno, offset, bytes, ps = 4096) {
  const fd = openSync(p, 'r+');
  try {
    writeSync(fd, Buffer.from(bytes), 0, bytes.length, (pageno - 1) * ps + offset);
  } finally {
    closeSync(fd);
  }
}

function walChecksum(buf, s0, s1, be) {
  for (let i = 0; i + 7 < buf.length; i += 8) {
    const a = be ? buf.readUInt32BE(i) : buf.readUInt32LE(i);
    const b = be ? buf.readUInt32BE(i + 4) : buf.readUInt32LE(i + 4);
    s0 = (s0 + a + s1) >>> 0;
    s1 = (s1 + b + s0) >>> 0;
  }
  return [s0, s1];
}
export function walFrames(p) {
  const wal = readFileSync(`${p}-wal`);
  const ps = wal.readUInt32BE(8);
  const frames = [];
  for (let o = 32; o + 24 + ps <= wal.length; o += 24 + ps) frames.push({ o, pg: wal.readUInt32BE(o), commit: wal.readUInt32BE(o + 4) });
  return { frames, ps };
}
export function plantWal(p, frameIndex, offset, bytes) {
  const wal = Buffer.from(readFileSync(`${p}-wal`));
  const be = wal.readUInt32BE(0) === 0x377f0683;
  const ps = wal.readUInt32BE(8);
  const frames = [];
  for (let o = 32; o + 24 + ps <= wal.length; o += 24 + ps) frames.push({ o, pg: wal.readUInt32BE(o) });
  const f = frames[frameIndex];
  Buffer.from(bytes).copy(wal, f.o + 24 + offset);
  let [s0, s1] = walChecksum(wal.subarray(0, 24), 0, 0, be);
  for (const fr of frames) {
    [s0, s1] = walChecksum(wal.subarray(fr.o, fr.o + 8), s0, s1, be);
    [s0, s1] = walChecksum(wal.subarray(fr.o + 24, fr.o + 24 + ps), s0, s1, be);
    wal.writeUInt32BE(s0, fr.o + 16);
    wal.writeUInt32BE(s1, fr.o + 20);
  }
  writeFileSync(`${p}-wal`, wal);
  rmSync(`${p}-shm`, { force: true });
  return f.pg;
}
export function copyPair(from, toDir) {
  mkdirSync(toDir, { recursive: true });
  const to = join(toDir, DB);
  copyFileSync(from, to);
  if (existsSync(`${from}-wal`)) copyFileSync(`${from}-wal`, `${to}-wal`);
  return to;
}
```

```js
const [work, variant, countS, seedS] = process.argv.slice(2);

const out = join(work, `results-${variant}-${seed}.jsonl`);

  { off: 0, bytes: () => Array(8).fill(0x41), what: 'hdr' },

  { off: 3, bytes: () => [0x7f, 0xff], what: 'ncellbig' },
  { off: 8, bytes: () => [0, 0, 0xff, 0xff], what: 'right-child/ptr' },

      plants.push({ pg, off, what: o.what, frame: fi });

      // phantoms

      const phantomIds = [];
      for (const [id, json] of after[t]) if (!truth[t].has(id) && t !== 'sqlite_sequence' && t !== 'schema_version') { phantom++; if (phantomIds.length < 3) phantomIds.push(id); }

      if (changed && t !== 'sqlite_sequence' && t !== 'schema_version') res.problems.push(`changed ${t}: ${changed}`);
      if (phantom) res.problems.push(`phantom ${t}: ${phantom} (e.g. ${phantomIds.join(',')})`);
      if (namedLost) res.problems.push(`named-lost ${t}: ${namedLost}`);
      if (mainReadableLost) res.problems.push(`main-alone-readable lost ${t}: ${mainReadableLost}`);
      if (logOnlyLost) res.problems.push(`log rows lost via main-only ${t}: ${logOnlyLost}`);

    else {

    if (before.wal === null && now.wal === EMPTY) res.note = 'empty wal+shm created';

    res.why = r.lines.filter((l) => l.level === 'fail').map((l) => l.text.slice(0, 160));
    // anything readable at all?

    res.readableRows = any;
    if (rmain) res.mainReadableRows = Object.entries(rmain).reduce((s, [t, v]) => s + (v.rows?.size ?? 0), 0);
  } else if (r.outcome === 'healthy') {
    if (integ.ok === false) res.problems.push('healthy but integ failed before');
  } else {
    res.problems.push(`outcome ${r.outcome}: ${text.slice(0, 300)}`);
  }
  res.text = text.length > 1500 ? text.slice(0, 1500) : text;
  appendFileSync(out, JSON.stringify(res) + '\n');
```
