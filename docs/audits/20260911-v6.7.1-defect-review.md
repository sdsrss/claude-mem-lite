## P2 — CONFIRMED — `fileShapeScore` scores leading-dot dotfiles 0, i.e. BELOW the version numbers it exists to demote

**Where:** `lib/file-edge-match.mjs:118-119`

    const dot = name.lastIndexOf('.');
    if (dot <= 0 || dot === name.length - 1) return 0;

`dot <= 0` is meant to reject "no extension". It also rejects every dotfile whose only dot is the
leading one: `.env`, `.gitignore`, `.npmrc`, `.eslintrc`, `.nvmrc`, `.babelrc`, `.dockerignore`.
Those return 0 — the bottom tier — while `v4.0.1` scores 1 (`ext.length <= 5`). The two later
terms that would have rescued them (`/^[A-Za-z]/.test(ext)` -> `env` is letter-initial; the
separator term) are never reached.

**Reachability is not theoretical — `extractFiles` emits these tokens.** Verified against the
shipped `scripts/prompt-search-utils.mjs:250`:

    prompt: "why does src/.env break after v1.2.3 v1.2.4 v1.2.5 v1.2.6 v1.2.7 v1.2.8"
      extractFiles     -> ["src/.env","v1.2.3","v1.2.4","v1.2.5","v1.2.6","v1.2.7","v1.2.8"]
      ranked[0..6]     -> ["v1.2.3","v1.2.4","v1.2.5","v1.2.6","v1.2.7","v1.2.8"]   <- src/.env evicted
      old text[0..3]   -> ["src/.env","v1.2.3","v1.2.4"]                            <- src/.env probed

    prompt: "check .github/.gitignore and 1.0.1 2.0.2 3.0.3 4.0.4 5.0.5 6.0.6"
      ranked[0..6]     -> ["1.0.1","2.0.2","3.0.3","4.0.4","5.0.5","6.0.6"]         <- evicted
      old text[0..3]   -> [".github/.gitignore","1.0.1","2.0.2"]                    <- probed

This is a **recall regression against the code the round replaced**, in the one direction the round
was written to fix. It also falsifies the safety property the docblock rests on
(`lib/file-edge-match.mjs:147-148`): *"SORT, not filter, and that is the safety property: a wrong
score costs a position, never a candidate."* Downstream of a `.slice(0, FILE_PROBE_CAP)` a
position **is** a candidate — that is the entire premise of the round.

Six higher-scoring tokens are needed for outright eviction, which is why I grade it P2 rather than
P1; the mis-ordering (dotfile below version number) is unconditional.

**Fix shape:** a token whose only dot is at index 0 is a dotfile, not an extensionless token —
score the remainder as the extension. `const dot = name.lastIndexOf('.'); if (dot < 0 || dot === name.length - 1) return 0;`
plus a separate guard for `name === '.'`-style inputs. Worth a case in `tests/file-edge-rank.test.mjs`
asserting `rankFileCandidates(['v4.0.1','src/.env'])[0] === 'src/.env'`.

## P2 — CONFIRMED — the dedup is Unicode case-folding while the SQL it models is ASCII-only, so it drops a candidate that probes different rows

**Where:** `lib/file-edge-match.mjs:159` (`const key = s.toLowerCase();`) and the justification at
`:148-150` ("Dedup is case-insensitive because all four arms of fileMatchClause are (NOCASE / LIKE),
so two spellings of one path probe identical rows").

SQLite's `NOCASE` (and `LIKE`) fold **ASCII A-Z only**; JS `String.prototype.toLowerCase()` folds
the whole Unicode case table. The two do not agree:

    rankFileCandidates(['Ä.mjs','ä.mjs'])  ->  ["Ä.mjs"]          // second candidate dropped

    sqlite> select f from t where f = 'Ä.mjs' COLLATE NOCASE;  -> Ä.mjs
    sqlite> select f from t where f = 'ä.mjs' COLLATE NOCASE;  -> ä.mjs   // distinct rows

So `ä.mjs` is removed on the theory that `Ä.mjs` already probes its rows, and it does not. That is
a **drop**, the one thing `rankFileCandidates` contractually never does
(`tests/file-edge-rank.test.mjs:13` names the describe block "never drops"). The ASCII case the
test asserts (`Utils.mjs` / `utils.mjs`, `:62-66`) is the half that is true.

**Not reachable through today's only caller**: `extractFiles`' character class is `[\w./-]`, and
`\w` without the `u` flag is ASCII, so no non-ASCII filename survives extraction. But
`rankFileCandidates` is an **exported** function in `lib/`, documented generically as "for the
callers that can only afford to probe the first few", and the module's own header is about a
predicate two consumers must agree on byte-for-byte. Graded P2 because the shipped comment states
an equivalence with the SQL that does not hold.

**Fix shape:** fold with the same alphabet the SQL uses —
`s.replace(/[A-Z]/g, (c) => c.toLowerCase())` — and say so in the comment.

## P3 findings

**P3-1 — CONFIRMED — a trailing separator earns the "has a separator" bonus.**
`lib/file-edge-match.mjs:130`: `if (name !== String(token ?? '')) score += 2;`. `basenameAnySep`
strips trailing separators (`lib/file-edge-match.mjs:75`), so `'foo.mjs/'` -> `'foo.mjs'`, the
strings differ, and a token with **no** internal separator collects the separator bonus:

    rankFileCandidates(['bare.mjs','foo.mjs/'])  ->  ["foo.mjs/","bare.mjs"]   // 5 vs 3

Unreachable from `extractFiles` (its regex must end in `\.\w{1,10}`, so no match can end in a
separator). Latent contract bug in an exported helper. Test with `token.includes('/') || token.includes('\\')`
instead, or compare against the separator-stripped token.
