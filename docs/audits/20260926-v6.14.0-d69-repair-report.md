## P2-2 — the probe filter deleted real work where "mutation" is product vocabulary
Repro reproduced first (RED): 5 correct-usage shapes tagged `probe`, the reviewer's GraphQL sed -i fix window lost all 3 entries.
Fix (lib/episode-input-filter.mjs):
- The weak rule no longer takes a test run as confirmation of the word. It needs a probe MECHANISM (a checksum, a backup copy or a restore). The heredoc-script clause likewise needs in-place/checksum/restore, not a test run.
- Unrestored-write rule: a call whose `bashWrites` hit a file under the project dir is dropped only when a restore follows (same call or within PROBE_SPAN_MAX). `filterSummaryInput(episode, { projectDir })`; hook.mjs passes `inferProjectDir()`. A write outside the project protects nothing. With no projectDir every write is protected, the conservative default.
- Restore recognition had to widen, or the new rule would have kept 43 real probes. It now covers a cp/mv whose SOURCE token carries a backup mark (`.bak/.orig/.keep/.mut*/BAK/ORIG/backup`, quoted scratch paths included), plus `printf '%s' "$ORIG" > f`. Backup copies are recognised the same way on the destination side. A line-start `mutated…` output line was added as a probe-specific marker.
- The ruler (benchmark/key-events-input-replay.mjs) passes the project dir too (`--project-dir`, default: the most common main-thread cwd).
Correct-usage population (tests): `npx vitest run src/graphql/mutations/createUser.test.ts`, `npm test -- --grep "mutation resolvers"`, `npx jest src/store/mutations.spec.js`, a Redux `-t "mutate cart"`, `pytest tests/test_mutations.py`, an Apollo "optimistic mutation": none is tagged. The GraphQL sed -i fix window keeps 3/3. This repo's probe shapes (E#818 split probe, E#646 one-call probe, heredoc mutation script, the restore via `…backup…`, a `node -e` mutation printing `mutated…`) still drop.
