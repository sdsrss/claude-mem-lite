## DEFECTS

### P2-1  hook-update.mjs:46 — the updater now imports a symbol the previous release's lib lacks, and the swap renames it 79 files earlier
hook-update.mjs used to import `acquireLock` (present in every release); 1c12bf7f changes it to
`takeLock`, which exists only from this commit. The swap renames files in SOURCE_FILES order:
hook-update.mjs is index 17, install.mjs 28, lib/proc-lock.mjs 96 (of 161). A swap killed between 17
and 96 (Ctrl-C on `self-update` during the rename loop, a host kill of the launch.mjs sync) leaves a
tree whose hook-update.mjs cannot load, so recoverInterruptedSwaps and syncDataDirFromCache are
unreachable from INSTALL_DIR, which is the recovery that window exists for. CLAUDE.md invariant:
"A recovery path must not import the thing it recovers". install.mjs has the same shape since
6d5cac5d (`lockDirBlocked`), and 1c12bf7f adds `takeLock` to that import too.
Mitigation: in plugin mode scripts/launch.mjs imports the plugin cache's own (consistent)
hook-update.mjs and still heals; what is lost is hook-launcher's backup healer
(trySyncDataDirFromCache, scripts/hook-launcher.mjs:511, which imports INSTALL_DIR/hook-update.mjs and
swallows the failure). For a direct install, install.mjs (repair/cleanup/install) was already
unloadable in that window from 6d5cac5d. The window is the rename loop only (milliseconds).
Repro (v6.25.2 tree, then the files before lib/proc-lock.mjs in the new manifest's order overlaid):
```
== d113c245: overlaid 96 files
hook-update.mjs loads
install.mjs FAILS: SyntaxError The requested module './lib/proc-lock.mjs' does not provide an export named 'lockDirBlocked'
== 1c12bf7f: overlaid 96 files
hook-update.mjs FAILS: SyntaxError The requested module './lib/proc-lock.mjs' does not provide an export named 'takeLock'
install.mjs FAILS: SyntaxError The requested module './lib/proc-lock.mjs' does not provide an export named 'lockDirBlocked'
```
and in the d113c245 mixed tree `import('./hook-update.mjs')` gives
`syncDataDirFromCache: function recoverInterruptedSwaps: function`. `cli.mjs repair` in both mixed
trees prints "this file is damaged or truncated: …/install.mjs" (the real cause is an older sibling
lib file). The launcher heals only ERR_MODULE_NOT_FOUND (hook-launcher.mjs:229), and a missing named
export is a SyntaxError.
Fix options: import takeLock dynamically / feature-detect it (`mod.takeLock ?? ((p) => ({release: mod.acquireLock(p) || undefined}))`)
in hook-update.mjs and install.mjs, or move lib/proc-lock.mjs ahead of its importers in SOURCE_FILES.

### P3-3  install.mjs:3763 — self-update's lock precheck blocks a check that takes no lock (plugin mode)
In plugin mode checkForUpdate never installs (`canInstall = !pluginMode && …`, hook-update.mjs
checkForUpdate), yet the precheck stops before the check and exits 1:
```
[blocked, CLAUDE_PLUGIN_ROOT set] ⚠ Not checked: install.lock cannot be taken — su-blocked/data/runtime cannot be written (EACCES). Fix: … exit=1
[free,    CLAUDE_PLUGIN_ROOT set] Checking for updates... ⚠ Not checked: could not reach GitHub Releases (network, proxy or DNS). Nothing was installed. exit=0
```
A plugin-mode user with a sudo-owned runtime dir can no longer learn whether an update exists from
self-update, and its exit changes 0 → 1. Direct installs that are already up to date get the same
"Not checked". The precheck could apply only when `!isPluginMode()`, or run after the check and
before the install.
