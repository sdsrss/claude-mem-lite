### F3 — P3 — introduced by e77aba2d — the meta guard is a no-op; skill bodies after the turn's text split real turns, and "one before it does not" cannot fail
- File: benchmark/summary-events-ab.mjs:179-181 `if (e.isMeta && last === null) continue;` and its comment.
- Mechanism: with `last === null`, stop() records nothing and drop() resets already-null values, so the line changes no outcome; the real rule is "any meta record ends a turn with pending text". The comment's premise "a meta record inside a turn (a skill's body, a caveat) comes before the turn's text" is false on real transcripts: a Skill call after text is followed by its body as a meta record.
- Evidence: mutation B9 (delete the line) SURVIVED (`26 passed (26)`), and the corpus runs with and without the line are identical at event and output level. Event level vs the host: 10 Stops the host never fired at mid-turn meta records (skill bodies 8, "[Image: original …]" 1, "Your response above was stopped by a safety classifier" 1); old ruler 0 at those. Output impact on this corpus: 0 (each is followed by the turn's own stop_hook_summary before any compaction, interrupt or API error; checked all 10).
