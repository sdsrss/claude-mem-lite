  - **写事务里一次普通读抛出 SQLITE_CORRUPT 之后，同一事务里后面的每一次写和 COMMIT 都失败（SQLITE_CORRUPT）。**

    - 之后的读不受影响（`count(*)` = 1195）。

  - **`PRAGMA quick_check` / `integrity_check` 在同一个写事务里报出损坏（"Tree 74 page 505 cell 10: Rowid 11 out of order"）之后，后面的写和 COMMIT 都成功**：它们把损坏写成报告行，不抛错。

  - β 写前的扫描只要碰到损坏的基础表，重建就跑不了。冒烟里 β 中止了 72 个臂，其中 49 个是写前扫描抛错；这 72 个臂上 OLD 都至少重建成功了一项。
  - **任何"一个事务包住全部重建"的设计都满足不了 D#768 条件 (4)**：某张 FTS 表的重建读到损坏，同一事务里其余的表也重建不了。所以必须一张表一个事务。
