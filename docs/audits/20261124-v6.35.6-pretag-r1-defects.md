## Verdict

No P0 or P1. Two P2 on the summary side, one of them a regression against v6.35.5 on a real report shape
(4 of 156 遗留 parts in the R4 corpus). The CLI guard does what the contract says on every path I ran; its gaps are
constructed shapes and fail open to v6.35.5 behaviour. The new header alternation is linear: 23.9 ms worst case at
1,000,000 characters.

## Findings

### F1 — P2 — real — a 遗留 part opened with a label stores only the label, and it replaces the model's Remaining
- Shapes (both are header forms the contract lists):
  - (a) `### 遗留（需要你决定）`, a blank line, then a bold lead line `**评审的 MEDIUM（F1）已复现，属实。**`, then the items.
    `notDone` = `（需要你决定）`.
  - (b) `**遗留：需要你决定**`, a blank line, then a table. `notDone` = `需要你决定`.
- Mechanism. This is inherited code, reached now by the new keys. v6.35.5 gives the same output for `### Not done（…）`
  followed by a bold lead.
  - (a): `lib/summary-extractor.mjs:101` returns the parenthetical as `tail` with `block: true`, and `:237` pushes it into
    the buffer. Then `:248` (`BOLD_LINE.test(line) && buffers[current].length > 0`) closes the block on the lead line,
    because the label already counts as content.
  - (b): `:100` returns `block: false` when the colon has text after it. The paragraph-break rule at `:268-273` then
    ends the part at the blank line, before the table.
- Why it is a regression and not just a gap. In `lib/fast-summary.mjs`, a non-empty Not done sets `hasReport`
  (`:304`). That stores the report's `notDone` with `left='report'` (`:373-376`), and `mergeModelSummary` keeps a
  `report` remaining (`:584-587`). On v6.35.5 these replies extracted nothing, so the model summary's
  `remaining_items` was stored. On the candidate a contentless label replaces it.
- Corpus (R4 frozen, finals with 汇报 parts): 4 of 156 遗留 parts — `-home-ai-dev-code-graph-mcp/c6435c08…` (14/14 part
  lines lost), `-home-ai-dev-daagu/09f7f439…` (18/18), and `-home-ai-dev-claudemd/41d25db2…` twice (6/6 and 5/5, tables).
  The lost content is the decision list, which is what R4 found users pasting back.
- Repro (library level, both trees, synthetic text with the real shapes):
  ```
  cd ~/.cache/tmp/rv-6.35.6-defects && for t in base head; do env -u ANTHROPIC_API_KEY -u OPENROUTER_API_KEY \
    HOME=$PWD/sbx-suite/home node scripts/stub-regression.mjs $PWD/$t; done
  base: paren-heading+bold-lead | extract.notDone = ""  | stored remaining = "MODEL-REMAINING: decide F1 / push / release"
  head: paren-heading+bold-lead | extract.notDone = "（需要你决定）" | stored remaining = "（需要你决定）"
  head: colon-inline+table      | extract.notDone = "需要你决定"     | stored remaining = "需要你决定"
  ```
- The new tests miss both shapes. `**遗留（需要你决定）**` and `**遗留：需要你决定的事**` there are followed directly by bullets,
  with no blank line and no bold lead (`tests/summary-extractor.test.mjs:337-346`).

### F2 — P2 — constructed here, plausible for users without the claudemd report format — a bare "Changes" heading now locks Remaining to ''
- `HEAD_RE` (`lib/summary-extractor.mjs:41-44`) matches the new names on any line. It does not need a `## 汇报` / `## Report`
  heading, although the README now says "the Changes / Open items parts of a `## Report`".
- `## Changes`, `**Changes**`, `**Changes:**` and `Changes: …` are common headings in generic end-of-task summaries.
  In those summaries a missing Open items section does not mean nothing is left. Through F1's mechanism they now set
  `completed` to the list and `remaining_items` to `''` with `left='report'`, so the model summary's completed and
  remaining are discarded. Example: `### Changes` followed by `### Next steps` stores `remaining=""`.
- Text after the list is also misfiled. `**Still to do:** wire the CLI flag` after a `**Changes:**` list lands in
  `completed`, because that line does not end in `**`, so it is not a `BOLD_LINE`. A plan that ends a turn
  (`## Changes\n1. …\n\nShall I proceed?`) becomes a Done.
- Repro (`scripts/changes-lock.mjs`): base stores `MODEL-DONE` / `MODEL-REMAINING…` for all 3 shapes. Head stores
  `- Moved the parser… / ""`, `- Moved the parser **Still to do:** wire the CLI flag / ""` and `1. Split the parser 2. Add a cache / ""`.
- Population: on this machine 0 of 1,473 live finals hit this. All 292 changed extractions are full 汇报 reports with
  a 验证 part. Other users' report styles cannot be measured here. This is a default-behaviour change of the published
  package for that population.

### F3 — P3 — real — a bold sub-heading inside a part ends the part
- The same `:248` rule (a bold line closes a block once it has content) cuts 变更 and 遗留 parts at sub-heads such as
  `**需要你决定**`, `**需要你授权的**`, `**发版。**` and `**审阅**`.
- R4 corpus:
  - 遗留: 9 of 156 parts lose lines, 83 of 1,419 lines in all. 4 of the 9 are F1; the other 5 lose the block after a
    sub-head.
  - 变更: 11 of 147 parts lose lines, 139 of 1,510.
- Through F1's lock, the partial report Not done also replaces the model's Remaining. In the 汇报 format the part headers
  already bound each part, so this "unrelated bold title" rule does not fit it.

### F4 — P3 — constructed — `Changeſ:` / `Open itemſ:` throws
- With `/iu`, U+017F `ſ` case-folds to `s`, so `HEAD_RE` matches. `EN_KEY[m[3].toLowerCase()…]` (`:67`) then returns
  `undefined`, and `buffers[undefined].push` throws at `:237`. v6.35.5 returns empty fields for the same input: none of
  its names contain `s`.
  ```
  head: "Changeſ: fixed X\nOpen items: Y" -> THROWS TypeError: Cannot read properties of undefined (reading 'push')
  ```
- The Stop hook catches it (`hook.mjs:1443-1455`), so that turn loses its report and falls back to the tail floor.
  `benchmark/summary-events-ab.mjs` does not catch it.

### F5 — P3 — constructed, not observed — an old-format Done / Not done block is re-routed by a bullet that starts with a part name
- `**Done**\n- fixed the cap\n- Verification: npm test 47/47\n- also renamed the flag`: v6.35.5 gives
  done = all 3 bullets. Head gives done = `- fixed the cap`; the rest goes to the dropped `checks` buffer.
- `**Not done**\n- tag not pushed\n- Changes: none…\n- docs not updated`: head moves the last 2 bullets into done (wrong field).
- Not observed: across 1,473 live finals, v6.35.5 extracted a Done from only 2 and a Not done from 44, and none of
  those changed. That population is small. The pre-existing summary-extractor tests (65) all pass on head.
- Repro: `scripts/old-pop.mjs`.

### F6 — P3 — constructed — `restore` refuses when the only project-less rows are ones it would skip
- `mem-cli.mjs:2495-2496` checks `rows.every(r => !r || typeof r !== 'object' || r.project)`. The loop (`:2520-2539`)
  skips malformed objects, arrays and tombstoned rows (`compressed_into` other than −2) without ever reading a project,
  but the check still refuses (rc=1) when such a row has no project. It also refuses `"project": ""`.
- No partial write: the check runs before the loop. A mixed file (one row with a project, one without) gives rc=1 and
  writes 0 rows. `--dry-run` is refused too.
- `export` always writes `project`, so a normal round trip never reaches this.

### F7 — P3 — constructed — where the guard refuses wrongly or misses (both fail open to v6.35.5 except the first)
| Case | Result on head |
|---|---|
| `CLAUDE_CONFIG_DIR=$HOME` (absolute), write from `~/projects/app` | **refused** with "is Claude Code's own per-project state" — a real project wrongly refused |
| Logical PWD through a symlink to the config home (`~/claude-link/projects/P/memory`) | written under `-home-u-proj--memory` (misfile) |
| PWD unset and `~/.claude` a symlink | written under `-x--memory` (ran it: `process.cwd()` is the real path); the same dir with the logical PWD set is refused, and so is PWD unset without a symlink |
| Case-different spelling (`.Claude`), POSIX | written (case-sensitive compare); only matters on case-insensitive macOS volumes |
| `CLAUDE_CONFIG_DIR=cfg` (relative) | guard checks `~/.claude/projects`; `<cwd>/cfg/projects`, which Claude Code would use, is written; doctor already names a relative value |
| Windows (`path.win32` simulation of `:145-148`) | `C:\…`, `C:/…` and case variants refused; MSYS form `/c/Users/…` not refused (only if node receives PWD in that form — NOT CHECKED) |

Correct on head: trailing slash, `..` staying inside, the `projects/` dir itself, an empty `CLAUDE_CONFIG_DIR`, an
absolute `CLAUDE_CONFIG_DIR` with or without a trailing slash, `projects-old/` (allowed), and the config home itself
(allowed). PWD and the real cwd cannot disagree with the project name: the guard and `inferProject()` both read
`CLAUDE_PROJECT_DIR || PWD || cwd`. PWD=memdir with the real cwd in a project → refused; PWD=project with the real cwd
in memdir → written under the project; `CLAUDE_PROJECT_DIR`=project with PWD=memdir → written under the project.
`..` leaving the tree stores project `..--proj`; that naming comes from `inferProject()` and is the same on v6.35.5.

## Questions answered

- **Report shapes.**
  - R4 corpus (891 finals, 160 with 汇报 parts): 0 replies where a 验证-part line reaches done or notDone;
    0 replies with an empty done or notDone where the part exists.
  - Content losses: F1 and F3.
  - Live set (1,473 finals): 0 changes to a non-empty v6.35.5 Done. 29 changes to a non-empty v6.35.5 Not done:
    - 23 keep every old line and add the 遗留 part;
    - 4 move `剩余工作…` / `剩下的…` lines that sit inside a 变更 part into done (those lines described finished work);
    - 2 drop lines that sit inside a 验证 part — in one of them v6.35.5 had leaked `→ 通过` lines into Not done.
  - Prose-only 变更 / 遗留 / 验证 lines without a separator are not read as headers (test `tests/summary-extractor.test.mjs:374`, and 0 such hits
    in the corpus).
  - Part-name variants (`验证结果：`, `遗留项…`): 9 lines in 1,473 finals, 0 leaks.
- **Linear time.** Medians of 3, two ABBA passes (`scripts/timing.mjs`, `timing2.mjs`). Doubling n roughly doubles
  the time for every input: whitespace runs after `##` / `**` / `Open` / `Not` / `变更`, NBSP and ideographic space,
  repeated `/ Open` near-misses, 遗留/变更 repeated, unclosed `（` runs, `\r` runs, unpaired `**`, and many header lines.
  - Worst at 200k characters: head 8.1 ms vs base 1.5 ms (header-heavy multi-line input).
  - Worst at 1M characters: head 23.9 ms vs base 4.0 ms (`**Open  items-ish` lines, which now reach `enHeader`).
  - Linear, with a constant about 6× larger.
- **Write paths.** Guarded and refused from a memdir, with rc=1, nothing written and `--project` named: `save`,
  `defer add`, `activity save`, `import-jsonl`, and `restore` of a project-less row. Nothing is missed:
  - `compress`, `maintain` and `optimize` default to all projects or a named one;
  - `update`, `delete` and `defer drop` take ids;
  - `activity promote` copies `ev.project`;
  - `verify-apply` refuses rows outside the project, and its replacement rows take `p.before.project`
    (`lib/verify-apply-core.mjs:202,338`);
  - no shipped code spawns these writes.
  - `search` still writes its `search_runs` telemetry under the cwd project. That is a read command, unchanged and
    outside the contract.
- **Read paths.** 16 read commands run from a memdir on equal copies of one DB (recent, search, recall, get, timeline,
  browse, context, stats, defer list, activity recent/search, citation-stats, export, fts-check,
  verify-apply --print-project, memdir-audit): same exit code on both trees. Outputs differ only in timestamps and
  data-dir paths.
- **restore.** It cannot write some rows and then refuse: the check runs before the loop. It can refuse when no row
  needed the directory (F6).
- **Upgrade from v6.35.5.** F1 and F2 change stored Remaining / Done for existing users. A `cd ~/.claude/projects/… &&
  cli.mjs save` chain now stops at exit 1, which is intended. No schema or stored-format change.
