### F1 — P2, close to P1. Regression against v6.30.13. The shape is plausible but was not seen in real data
CHANGELOG.md:20 says: "Text that 6.30.13 erased together with such a label's value stays erased." This is false.
Mechanism, in secret-scrub.mjs:1612-1633 (scrubEscapedLiterals, maskEscapes, valueTokens):
- The protection for a rewritten literal compares whole value tokens. Each token is read with escapes masked to spaces.
- An escape that decodes to a VALUE_TOKEN_RE character splits a token in the escaped body but not in the re-encoded
  literal: `\/` (PHP `json_encode` writes it by default) and `\u002B` (`+`, which .NET System.Text.Json escapes by
  default). The merged token is then "not in the body", so it is kept.
- A credential value shorter than the 6-character floor (`root`, `admin`) is not erased when the literal is read as
  text. Its whole `LABEL=value` token is replaced by `***`, so the label disappears. The outer pattern pass then no
  longer runs the label's value on over the next lines, which is what erased them on v6.30.13.
- The rewrite happens only when some other credential in the same string is erased.

Repro: `node scripts/slashleak2.mjs $PWD/base $PWD/cand` (base/cand, K = value kept):
```
-/K  PHP {"content": .env}, password "root", Discord URL next
-/-  plain JSON {"content": .env}, password "root", Discord URL next
-/K  .NET {"content": env}, password "root", base64 with + next
-/K  ... "admin" and "ab" the same; "" (empty value): -/- on all three encodings
base PHP-encoded .env, root password (252 chars): live MCP - live Bash - import MCP - import Bash - prompt - imported prompt -
cand PHP-encoded .env, root password (252 chars): live MCP - live Bash - import MCP K import Bash K prompt K imported prompt K
```
The text is `APP_ENV=local\nMYSQL_ROOT_PASSWORD=root\nDISCORD_WEBHOOK_URL=https:\/\/discord.com\/api\/webhooks\/<id>\/<68-char token>\nMAIL_PASSWORD=<16>\nLOG_LEVEL=info\n`
in `{"content":"…"}`, written the way PHP does. 41787adc stores the Discord webhook token through import-jsonl (MCP
result and Bash output) and the prompt hook; v6.30.13 erases it on every path. In raw text (not in a JSON string) both
versions store such a token, because no pattern covers it. v6.30.13 erased it only through the run-on.
