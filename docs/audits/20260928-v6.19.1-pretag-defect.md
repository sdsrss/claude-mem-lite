## F1 · P3 · 回归 — Bash 描述的尾窗在空白折叠后露出无标签的凭据值
**位置**：utils.mjs:354-363（`oneSpace` 作用在尾窗上），配合 `dropCutTokenAtStart`（utils.mjs:307-312）。

**机制**：尾窗是 `str.slice(-4096)`。窗边落在“标签+分隔符”内部（如 `pass|word: <v>`）或正好落在分隔符后的空白上时，`dropCutTokenAtStart` 只丢掉被切断的标签碎片，值 `<v>` 以无标签的形式留在窗首。所有依赖标签的 pattern（`password:`、`Authorization: Bearer`、`--token`、`api_key =` 等）因此都认不出它。
旧代码的尾部只做 `\n → 空格`，窗首永远落不进最后 49 个字符。新代码用 `oneSpace` 把空白折叠成一个空格，只要值之后约 4000 个字符几乎全是空白，窗首就会进入可见的尾部。

**复现**：`node rev-defect/probes/p6-tailedge.mjs`
```
"Authorization: Bearer "  new: curl -v x → x x … …sEcReTvAlUe1234567890 3 passed
                          old: curl -v x → x x … …                                         3 passed
"password: " / "--token " / "api_key = " 同形
```
整串 `scrubSecrets(s)` 能擦掉该值（whole-scrub has value: false），所以泄露只发生在尾窗这条路径上。
`p6b-tailedge-inlabel.mjs`：窗边在标签 `db password: ` 的 14 个位置中，新代码泄露 9 个，旧代码 0 个。

**触发条件**：输出长度 > 8192；凭据标签恰好跨在“末尾往前 4096”处；值之后的约 4000 个字符几乎全是空白。触发难度与 round-3 P3-6 同级，属构造型。
**建议**：尾窗多取一段前导上下文（例如 `slice(-window-256)`）一起 scrub，再丢掉前导部分；或者尾窗不做空白折叠。

## F2 · P3 · 非回归（a5af889 的修复不完整）— 截断私钥只在“裸行、LF/CRLF 换行”形态下被擦除
**位置**：secret-scrub.mjs:212-215（截断头 pattern），216-221（尾部 pattern；正则在 219 行）。

**复现**：`node rev-defect/probes/p1-shapes.mjs`。以下形态新旧两版都原样存储：

另有两个缺口：

## F3 · P3 · 回归（新 pattern）— 两个新 PEM pattern 会擦掉单词行组成的散文
**位置**：secret-scrub.mjs:213（截断头），218-220（尾部）。

**复现**（p1-shapes.mjs）：
- `The header line is -----BEGIN RSA PRIVATE KEY-----\nThen\ncomes\nthe\nbody.` → `The header line is ***PEM_KEY***\nbody.`（`Then comes the` 被擦）；
- `Checklist -----BEGIN OPENSSH PRIVATE KEY-----\n\nStep1\nStep2\n\nDone with it` → `Step1 Step2` 被擦；
- `done\nOK\n<body>\n-----END RSA PRIVATE KEY-----` → `done`、`OK` 也被吞进 `***PEM_KEY***`；
- `count\n42\n7\n<body>\n-----END…` → `count 42 7` 全被吞。

原因：两个 pattern 的“行”都是 `[A-Za-z0-9+/=]+`，任何单个英文单词或数字都能匹配。尾部 pattern 会连带吞掉 END 之上所有连续的单词行。
提交信息称“Live DB 11,996 fields: 0 differ”，说明现有语料里没有这类形态；上述输入是 `echo OK; tail key.pem`、`wc -l; tail key.pem` 这类真实命令组合，损失量小。
**建议**：body 行要求长度下限（例如 ≥16 且不含空格），或者要求至少一行达到接近 64 的长度。
