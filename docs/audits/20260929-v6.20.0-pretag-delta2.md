## P1

### P1-1 A root that becomes an npm package after the file exists keeps CLAUDE.local.md, npm ships it, and the steering loads twice
- Code: lib/local-steering.mjs:299 `if (npmPublishable(root)) return { action: 'refused', reason: 'npm-publishable' }`
  refuses to WRITE but leaves a block it created earlier on disk; adopt-cli.mjs:287-289 then returns `inject`,
  and hook.mjs:2933-2936 injects the same block on top of the file that is still loaded.
- Claims contradicted: README.md:170 "(a publishable npm package root never gets it, see above)";
  CHANGELOG Packaging "The plugin does not write the file into a publishable npm package root";
  README.zh-CN.md:157 "可发布的 npm 包根目录不会写入这个文件".
- Common flow: `git init` → open Claude Code (file created) → `npm init -y` (no "private") → `npm publish`.
- Repro (verified):
  ```
  mkdir -p $H/p && cd $H/p && git init -q && echo x>README.md && git add -A && git -c user.email=t@t -c user.name=t commit -qm i
  node -e "$A"           # {"ok":true,"action":"local","written":"created"}
  npm init -y >/dev/null
  node -e "$A"           # {"ok":true,"action":"inject","reason":"local-npm-publishable"}
  ls CLAUDE.local.md     # still there
  npm pack --dry-run --json | grep CLAUDE.local.md   # "path": "CLAUDE.local.md"
  ```
  Hook e2e (session-start twice, same repo): second session output had the file present AND
  `## claude-mem-lite — persistent memory` in additionalContext; npm pack files = `CLAUDE.local.md, README.md, package.json`.
- Same shape for `symlink` refusal when the link target carries a block, and for the
  CLAUDE_MEM_NO_TEMPLATE_REFRESH=1 path (adopt-cli.mjs:282-285 returns before writeLocalSteering, so npm/symlink are never checked).
- Suggested fix: on a `npm-publishable` (and `symlink`) refusal, remove a block this plugin created
  (state file present, regular file) via removeLocalSteering, or run the npm check in the frozen path too.

### P2-1 npmPublishable's `files` matcher misses globs npm expands to the root file; a root .npmignore entry is trusted even when `files` includes the file
- Code: lib/local-steering.mjs:117-148 (`couldMatch` accepts only '', '.', '*', '**', /CLAUDE/i, `*.md`, `**/*`;
  .npmignore regex `^\s*\/?CLAUDE\.local\.md\s*$` returns false before considering `files`).
- npm semantics: root .npmignore does not override `files` (verified below).
- Matrix, npmPublishable vs `npm pack --dry-run` (npm 11.19.0), 23 variants — WRITES-AND-SHIPS rows:
  ```
  files **/*.md                     npmPublishable=false  npm-pack=SHIPS
  files *.*                         npmPublishable=false  npm-pack=SHIPS
  files /     | files /*            npmPublishable=false  npm-pack=SHIPS
  files *.local.md | C* | [A-Z]*    npmPublishable=false  npm-pack=SHIPS
  files {lib,*.md}                  npmPublishable=false  npm-pack=SHIPS
  files *.md + .npmignore names it  npmPublishable=false  npm-pack=SHIPS
  ```
  (private:true also SHIPS under `npm pack`, but `npm publish` refuses it, so that row matches the "npm publish" wording.)
- Claims contradicted: CHANGELOG "no `files` list or `.npmignore` that leaves it out" / README.md:170 same wording.
  The `.npmignore` row is the one a user reaches by following the notice at hook.mjs:2679 ("npm pack … do not read .git/info/exclude").
- Fix direction: treat any `files` entry containing a glob metachar (`*?[{`) or equal to `/`, `/*` as could-match; ignore root .npmignore when `files` is an array.

### P2-2 `adopt --disable` at the repository root does not turn the guidance off for sessions started in a subdirectory
- Code: adopt-cli.mjs:279 `if (isAutoAdoptDisabledFor(root)) return { ok: true, action: 'inject', reason: 'root-disabled' }`;
  hook.mjs:2933-2936 injects the steering and fires offerAdoptOnce for `inject`.
- Repro (hook e2e): root session → `adopt --disable` at root (removes local block, writes sentinel) → session-start in `packages/web`:
  ```

  systemMessage: claude-mem-lite: memory guidance for this project is injected at session start, … Run /adopt (or `claude-mem-lite adopt`) to put it in CLAUDE.md instead …
  root session after --disable: steering injected = false
  ```

- Claims contradicted: commands/adopt.md:55-57 "permanently stops auto-adopt for this project (also for sessions started in
  its subdirectories)"; hook.mjs:2680 / 2660 "`adopt --disable` turns the guidance off for this project";

- The test pins the contradicted behaviour: tests/local-steering.test.mjs:297 expects `action` 'inject'.
- Fix: return `{ action: 'disabled', reason: 'root-disabled' }` (no injection, no /adopt offer), or reword the four docs.

### P2-3 $HOME reached through a symlink: a git work tree at $HOME is not recognised, ~/CLAUDE.local.md is written
- Code: lib/local-steering.mjs:105 `d === resolve(homedir())` compares git's realpath top-level with the unresolved HOME.
- Repro: HOME=<link> → <real>, `git init` in <real> (dotfiles-at-$HOME pattern), session in `$HOME/code/scratch` (not its own repo):
  ```
  isSharedAncestor(real home): false
  session in $HOME/code/scratch: {"ok":true,"action":"local","written":"created"} | wrote ~/CLAUDE.local.md: true
  ```
  Claude Code loads ~/CLAUDE.local.md as an ancestor of every project below $HOME — the case the module header and
  README ("in a repository rooted at `$HOME` … nothing is written") exclude. Test "the filesystem root and $HOME are never a
  steering root" uses a non-symlinked HOME. Pre-existing at 80335a4 (unreleased, so it ships in 6.20.0).
  Affects any HOME with a symlinked component (e.g. /home → /var/home layouts). Fix: compare `realpathSync` of both.

### P2-5 `unadopt` / `adopt` / `adopt --disable` expose the user's own notes in a plugin-created CLAUDE.local.md to `git status`
