## 2. 架构与关键流（本轮核对后的要点，不重复 `docs/ARCHITECTURE.md`）

三个 face（hooks / MCP / CLI）共享 `lib/` 88 个模块，0 静态 / 0 惰性循环，`lib → engine` 12 条边为有意设计。本轮核对到的、文档未写明的运行时事实：

1. **"session" 的实际单位是 turn，不是 CC 会话。** Claude Code 的 `Stop` 在每轮回复结束触发；`handleStop`（`hook.mjs:1524-1527`）每次 `unlinkSync(sessionFile())`，下一个钩子的 `getSessionId()`（`hook-shared.mjs:361-366`）发现文件缺失即 `createSessionId()`。本机真实库只读统计：79 条 prompt 分属 20 个 CC 会话，却产生 **70 个** mem 内部 session id（单个 CC 会话 10 条 prompt = 10 个 id）；`sdk_sessions` 92 行、`session_summaries` 69 行、`session_handoffs` 4 行全为 `exit`、`clear` 为 **0**。这一事实是 P1-1 的根，也解释了为何 `sdk_sessions` 数远大于会话数。
2. **写路径与读路径对 `project` 参数走同一条模糊解析**（`project-utils.mjs:100-160`，四步：精确后缀 → 精确名 → 前缀子串 → 整词），读侧模糊是设计，写侧模糊会把新项目吸进旧项目（P2-3）；`schema.mjs:1066-1128` 的一次性 `normalize-project-names` 清理用的是**更宽**的 token 子串（P1-2）。
3. **`optimized_at` 是三条维护路径共用的"已处理"标记**（re-enrich 写、normalize 写、cluster-merge/wide 池读），语义混用导致行被永久踢出富化池（P2-2）。
4. **自更新与安装是两套写法**：`hook-update.installExtractedRelease` 走 staging + journal + `swap-in-progress` 屏障 + smoke + 回滚；`install.mjs install`/`repair` 走就地 `copyFileSync`（P2-12），且无条件把安装器自己版本的 `launch.mjs` 覆盖进每个插件缓存版本目录（P2-11）。
