## Report

**Verdict: do not tag feba57c2 as it stands.** One P1 regression: the new per-string scrub stores a credential that v6.30.12's import erased, in a config shape people really write. Also one P2 false number in the CHANGELOG and five P3 items. The 12-shape-group claim, the D#654, D#661 and D#669 claims and the import-time claim all hold. The 100,000-part fuzz claim does not.

The repo was not touched (`git status` clean). Trees, probes and outputs under `/home/ai/.cache/tmp/rv-6313-defects/`, in `base/`, `cand/`, `cand-mut/`, `probe/` and `out/`. ### Findings

**F1 — P1, regression. An empty credential key swallows the next line's label, so that line's secret is stored.**
- Where: `lib/import-jsonl.mjs:98` and `:110` (each string is now scrubbed as raw text). The root cause is older and sits in `secret-scrub.mjs` label patterns (`:81`, `:122`, `:126`, `:131`, `:146`). Their `\s*` after `=` or `:` crosses a line break, so an empty `password:` or `token:` takes the next line's first token as its value. When that token is itself a label such as `JWT_SECRET:` or `api_key =`, the label is replaced by `***` and its value is left with no label in front of it.
- Why v6.30.12 was safe: it scrubbed the JSON text, where the break is an escaped `\n`. The indentation's space stopped the value at 2 characters, the next label survived, and its own rule erased the value.
- Repro: `probe/empty-label-show.mjs`, output for a docker-compose Write (value masked here):
  ```
  v6.30.12: ..."      POSTGRES_PASSWORD:\n      JWT_SECRET: ***      POSTGRES_DB: app\n"}
  v6.30.13: ..."      POSTGRES_PASSWORD:\n      *** <VALUE>\n      POSTGRES_DB: app\n"}
  ```
- Reach: `probe/empty-label.mjs` runs `importJsonl` on both trees: erased → STORED for three shapes (indented compose env; indented INI `password =` then `api_key = v`; YAML `token:` then `client_secret: v`), each through Write, Edit and an MCP array result. A Bash or Read string result was already stored by v6.30.12 too, so the fix belongs in the scrubber. The same mechanism also drops the next line's non-secret label (`POSTGRES_DB:`).
- Fuzz (`probe/fuzz.mjs <seed> 25000`, with the OpenSSH keys present): seeds 11–14 gave 26, 31, 21 and 36 regressions, 114 in 100,000 parts, all this one mechanism. With empty-label lines removed (`probe/fuzz-noempty.mjs`, seeds 21–22): 0 in 50,000. No key-window regression.
- Frequency here: 0 of 139,099 importable real parts outside this repo.

**F2 — P3 (constructed), regression. Deep nesting aborts the whole transcript.** `lib/import-jsonl.mjs:113`: `JSON.stringify` with a replacer recurses; the plain one in v6.30.12 did not fail. On Node 26.8.1 it throws `RangeError: Maximum call stack size exceeded` from depth 5,647 (object input) and 2,701 (array result); v6.30.12 does not throw up to depth 2,000,000 (`probe/depth.mjs`). The throw is inside the transaction: one ~6 KB line makes the whole file import 0 prompts / 0 observations; v6.30.12 imports 2 and 2 (`probe/depth-e2e.mjs`). The CLI reports "import failed" and moves on.

**F3 — P2. False number in shipped prose.** The CHANGELOG line "none of 163,475 tool inputs and results holds such a marker, and 72 are stored differently" (and commit 53659d1f) counts `api-request-blob` events, which `importJsonl` never reads (`:494`, counted as skipped). Re-measured (`probe/popdiff.mjs`): assistant 69,550 parts / 61 changed; user 69,549 / 0; api-request-blob 25,503 / 11; total 72 changed. So import-jsonl stores ~139,100 of those parts and 61 change, all tool_use inputs. "0 markers" holds.

**F4 — P3. Test gap: the END-first rule for JSON parts is untested.** Removing the whole-part `endFirst ? ''` return (`:115`, mutant M7) leaves all 23 import-related test files green (1,140 tests). On a two-block MCP result (key tail in one block, END line in the next) that mutant stores 421 key-body windows; both releases store 0 (`probe/endfirst-json.mjs`).

**F5 — P3 (constructed), wording.** The marker rule never looks at object keys. A BEGIN plus body line held in a key is stored by both releases, and an END in a key does not empty the part (`probe/odd.mjs`). The doc comment at `:88–90` and the CHANGELOG's "keeps only the text before its first … marker" are false for keys.

**F6 — P3. Text loss the CHANGELOG does not describe.** In the 61 changed real parts the erased text is, by masked shape, not a live credential: 42 `session_id` values in Bash commands that echo hook JSON; 7 shell spans between two quotes after `*_API_KEY=`; 5 `${{ secrets.NPM_TOKEN }}` references; 1 grep regex; a few fixture tokens (`probe/classify.mjs`). v6.30.12 already erased the same text from the title (`probe/title-vs-body.mjs`), so the body now matches the title. About 16 parts now keep a `\n` or `\` that v6.30.12 swallowed.

**F7 — P3. Cost.** Building the tool parts on real transcripts costs 1.20–1.23x per project. Whole import on the two largest non-repo transcripts: 553–558 vs 588–608 ms and 447–450 vs 478–484 ms (1.06–1.10x). Crafted parts of many small strings: 10.6–14.4x, still linear (`probe/cost.mjs`). Re-importing 134 real transcripts adds 0 rows in either release; both store the same row set; 18 narratives differ.
