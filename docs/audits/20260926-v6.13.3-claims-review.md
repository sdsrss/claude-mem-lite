### C17. "A SIGINT that lands before vitest has loaded the reporter takes node's default action, so no exit hook runs and the stamp survives." -> TRUE-BUT-MISLEADING
probe-sigint.mjs: fixture identical to setupVitestFixture (copies scripts from the 2de4849 tree), green run stamps, then spawn `vitest run` with GS_SLOW and SIGINT after a fixed delay; records exit code / signal / stamp. Two grids:
```
delay 100,100,100,140,150,160,170 -> exitCode null, signal SIGINT, stampSurvives true   (node default action)
delay 180,190,200,210             -> exitCode 130,  signal null,   stampSurvives true   (vitest HANDLED the SIGINT; stamp still survives)
delay 220..1000, marker x3        -> exitCode 130,  signal null,   stampSurvives false
```
At 100 ms (the reading the commit cites) the mechanism is exactly as stated: killed by signal, no 'exit' event. But there is a second, later window (~180-210 ms on this machine, load 1.0) in which vitest has already installed its own SIGINT handling and exits 130 through process exit, yet the reporter's `process.once('exit')` hook is not registered yet, so the stamp still survives. "Before the reporter is loaded" therefore does NOT imply "default action"; the accurate statement is "before the reporter's onInit registers its exit hook, whether the signal takes the default action or vitest's own handler". The fix (wait for a marker written from inside the test body) covers both windows, so the test change is sound; only the explanation is narrower than the phenomenon.
