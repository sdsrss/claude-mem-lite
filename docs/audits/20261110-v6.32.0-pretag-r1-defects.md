## Findings

### F1 — P2 — regression: a FIFO above the repository hangs the SessionStart hook; the session loses all of its SessionStart context
- Where: `adopt-cli.mjs:631` (`blockIn(d)` → `claudemd.mjs:276-277` `existsSync` + `readFileSync`),
  `adopt-cli.mjs:634` (`readBlockAt(<d>/CLAUDE.local.md)`), and on the non-git path
  `adopt-cli.mjs:569` (`readFileSync(<cwd>/.git)`). The new walk opens a file in every directory
  above the top-level (outside git: above the session) with a blocking read. Claude Code skips such a
  file itself (bundle: `[CLAUDE.md] skipping …: not a regular file or exceeds 4194304 byte limit`).
  v6.31.0 never read above the top-level and did not walk at all outside git.
- Reach: needs a FIFO (or another file whose open blocks) named CLAUDE.md / CLAUDE.local.md in an
  ancestor. Nothing creates one by accident, but any other local user can put one in a world-writable
  ancestor (`/tmp/CLAUDE.local.md`), and then every plugin session in a project under /tmp hangs.
  hook.mjs:345-346 traps SIGTERM, and the trap cannot run while the main thread is blocked, so a
  plain SIGTERM does not stop the process.
- Repro 1 (offline sync, 10 s cap): `bash probes/s05-fifo.sh`
  ```
  [base] git repo below a FIFO CLAUDE.local.md: rc=0 50ms {"ok":true,"action":"local","written":"created",…
  [base] non-git dir below a FIFO CLAUDE.md:        rc=0 36ms {"ok":true,"action":"inject",…
  [cand] git repo below a FIFO CLAUDE.local.md: rc=124 10007ms
  [cand] non-git dir below a FIFO CLAUDE.md:        rc=124 10006ms
  ```
- Repro 2 (the real hook entry, `scripts/hook-launcher.mjs hook.mjs session-start`, `timeout 15`): `bash probes/s05-fifo-hook.sh`
  ```
  [base] rc=0 136ms stdout_bytes=2578 has_steering=1
  [cand] rc=124 142951ms stdout_bytes=0 has_steering=0
  ```
  The cand process ignored `timeout`'s SIGTERM at 15 s, sat in `wait_for_partner` (/proc wchan), and
  ended only when I sent SIGKILL by PID at about 143 s.
- Repro 3 (real Claude Code 2.1.322, `--plugin-dir` cand): `probes/real-runs.sh 4`. Transcript
  attachments: `hook_success SessionStart:startup` (setup.sh, 109 ms) and
  `hook_cancelled SessionStart:startup durationMs 15506` (session-start). The steering text was in 0
  places in the transcript, `claude -p` took 21 s, and no plugin process was left running afterwards.
- Fix direction: `lstat`/`fstat` first and read only regular files (as the host does), and cap the
  size the same way.

### F2 — P2 — regression: under CLAUDE_MEM_NO_TEMPLATE_REFRESH=1, a block above deletes the user's edited local block
- Where: `adopt-cli.mjs:428-430` with `frozen ||` at `:631` and `:639`. Under the freeze, every
  block above counts as current, whatever its version, and the root's copy is removed and forgotten.
  v6.31.0 kept a frozen local block as it was (`lib/local-steering.mjs:777`
  `if (present && frozen) return { action: 'unchanged' … }`). The freeze is the documented way to keep
  edits inside the markers (CHANGELOG.md:2068, v6.21.0 entry: "keep notes outside the markers or set
  `CLAUDE_MEM_NO_TEMPLATE_REFRESH=1`"). The edit cannot be recovered. If the block above later goes,
  the copy that comes back is the shipped template, not the user's text. The CHANGELOG says the
  plugin takes out "an untracked copy it wrote before".
- Shape: the freeze is set, the local block was edited, and any directory above carries a block (a
  parent `adopt`, a 6.19-era auto-adopted `~/dev/CLAUDE.md`, or a worktree's main checkout).
- Repro: `bash probes/f2-freeze-edited-block.sh`
  ```
  [base] edited line before=1 | session: {"ok":true,"action":"local","written":"unchanged",… | edited line after: 1
  [cand2] edited line before=1 | session: {"ok":true,"action":"already-adopted","reason":"above-root",… | edited line after: file gone
  ```
  `probes/s02-file-safety.sh` cases (a) and (a2) show the same with a current block and with an older
  block above.
- Severity: P2, not P0. The text lost is the user's, but it sits in a file the plugin created, and
  three conditions have to hold together.

### F3 — P3 — regression: zero steering in a worktree subdirectory when git refuses the repository
- Where: `adopt-cli.mjs:468` → `steeringAbove(cwd)` → `worktreeMainCheckout(cwd)` (`:569`), which
  reads only `<cwd>/.git`. Claude Code finds the worktree by walking up for `.git` (bundle `XJt`/`yr`
  from the launch directory) and skips the main checkout's CLAUDE.md. Run 2 confirmed that skip for a
  real `--worktree` session.
- Shape: a worktree nested in its main checkout (the `claude --worktree` layout), the main
  checkout's CLAUDE.md carries the current block, git refuses the repository (dubious ownership, for
  example a mounted repository in a container), and the session starts in a subdirectory of the
  worktree. The plugin takes the non-git path and counts a CLAUDE.md the host does not load.
- Repro: `bash probes/s08-dubious-worktree.sh`. A git shim answers as git does for a repository
  owned by another user (`fatal: detected dubious ownership`, exit 128).
  ```
  [base] session in t1/src, git refuses: {"ok":true,"action":"inject",…
  [cand2] session in t1/src, git refuses: {"ok":true,"action":"already-adopted","reason":"ancestor-claude-md",…
  [cand2] session at t1 root, git refuses: {"ok":true,"action":"inject",…   (correct at the worktree root)
  ```

### F4 — P3 — regression: overlapping first sessions leave a `--worktree` session with no steering
- Where: `adopt-cli.mjs:428-431`. The host loads instruction files before the hook runs. A worktree
  session that launched before the main checkout's first session created `R/CLAUDE.local.md` loaded no
  block. Its hook then sees that file as current and neither writes nor injects. v6.31.0 created the
  worktree's own copy and injected it.
- Repro (sequential stand-in for the race; I did not measure the window): `bash probes/s07-race-and-doc.sh`
  ```
  [base] files loaded by t1 at launch=0 | main hook: …"created"… | t1 hook: …"local","written":"created"…
  [cand2] files loaded by t1 at launch=0 | main hook: …"created"… | t1 hook: …"already-adopted","reason":"above-root"…
  ```

### F5 — P3 — new in range: `adopt --status` promises one copy where the next session leaves two
- Where: `adopt-cli.mjs:786-801`. Status judges only the first file `readLocalSteering` returns (the
  rules file comes first). The session removes with `keepTracked`, so a tracked CLAUDE.local.md that
  also carries the block stays and keeps loading.
- Repro: `bash probes/s04-status.sh` case (a). It is constructed: the rules file and a tracked
  CLAUDE.local.md both carry the block, and a current block sits above.
  ```
  (a) status:   local:      — none: …/A/CLAUDE.md carries the block (the local copy in …/R/.claude/rules/claude-mem-lite.md is removed at the next session start)
      sync:   {"ok":true,"action":"already-adopted","reason":"above-root",…}
      after:  rules= local-has-block=1      ← A/CLAUDE.md and the tracked CLAUDE.local.md: loaded twice
  ```
- Related, case (b): status reads the freeze from the shell it runs in. With the freeze set only
  where sessions run (for example a settings `env` block), status reports "✓ <copy> … out-of-date
  copy above", while the next session removes the copy.

- The host loads no CLAUDE.md under this variable (bundle: the loader returns early on

- Repro: `bash probes/s06-disable-mds.sh`

  [cand2] git repo below adopted dir: {"ok":true,"action":"already-adopted","reason":"above-root",…

  Outside git, v6.31.0 injected in every session and the candidate injects in none. In git,

- The same class, not run: `--setting-sources` without project/local (D#783), and claudeMdExcludes

### F7 — P3 — regression: the above-root path never writes or refreshes the data-dir detail doc
- Where: `adopt-cli.mjs:428-432` returns before `ensureSteeringDetailDoc()` (`:433`). In a worktree
  that relies on the main checkout's CLAUDE.local.md, whose block points at
  `~/<data dir>/plugin_claude_mem_lite.md`, worktree sessions no longer refresh that file. With
  `claude --worktree` the hook's CLAUDE_PROJECT_DIR is the worktree (run 2), so a workflow that uses
  only `--worktree` never runs a session at the main checkout.
- Repro: `bash probes/s07-race-and-doc.sh`. After deleting the data-dir doc and running one worktree
  session: base `present`, cand2 `MISSING`. Any session elsewhere that takes the local or inject path
  restores it.

### F8 — P3 — new trigger: a user's own CLAUDE.local.md becomes visible to git at session start
- Where: `adopt-cli.mjs:429` → `lib/local-steering.mjs:1075`. When the plugin put its block into a
  CLAUDE.local.md the user already had (`createdFile:false`), removing the block also drops the
  plugin's exclude entry. This is the existing "back to how git saw it" rule; the change is that it
  now fires at SessionStart with no user action.
- Repro: `bash probes/s02-file-safety.sh` case (b). base: `git status` clean. cand:
  `?? CLAUDE.local.md`, a file holding the user's notes, which the next `git add -A` would commit.

## Checked, no defect found
- **Q1, symlinked launch directory** (`real-runs.sh 1`). With the launch through
  `L/link → real/A/R`, Claude Code loaded `real/A/R/CLAUDE.md` and `real/A/CLAUDE.md`, not
  `L/CLAUDE.md`. The hook's CLAUDE_PROJECT_DIR and stdin `cwd` were the physical path. The host and
  the plugin walk the same ancestors.
- **`claude --worktree`** (`real-runs.sh 2`). CLAUDE_PROJECT_DIR and stdin `cwd` were
  `R/.claude/worktrees/t1`. The host loaded `R/CLAUDE.local.md` and `A/CLAUDE.md` and skipped
  `R/CLAUDE.md`. This matches the candidate's rule.
- **Submodule** (`real-runs.sh 3`). A session in `S/sub` loaded `S/CLAUDE.md`, `S/CLAUDE.local.md`
  and `P/CLAUDE.md`, so cand's above-root reliance in a submodule (s03 M5) is right.
- **JSONC settings** (`real-runs.sh 3`). The host did not honour claudeMdExcludes from a project
  settings file with a comment and a trailing comma (`P/CLAUDE.md` loaded). The plugin's strict
  `JSON.parse` agrees.
- **Layouts** (`probes/s03-layouts.sh`), each matching the host's loader (bundle `dr`, `XJt`, `JJt`):
  - nested worktree with the main checkout's local copy: above-root;
  - main checkout with CLAUDE.md only: local copy written;
  - bare repository with a nested worktree: local copy written;
  - submodule: above-root;
  - sibling worktree: local copy written.
- **Q2, file safety** (`probes/s02-file-safety.sh`):
  - a tracked CLAUDE.local.md is kept;
  - a symlinked one is kept, and its target still has the block;
  - user text beside the block is kept.
  - The new code writes nothing outside the top-level beyond what v6.31.0 already wrote (info/exclude
    and the state file in the git dir).
- **Q5, odd inputs** (`probes/s09-odd-inputs.sh`). None of these made sync or `--status` throw:
  - an unreadable CLAUDE.md above;
  - a directory named CLAUDE.local.md above;
  - a directory named `.claude/settings.json`;
  - a `.git` file holding NUL and high bytes;
  - a `.git` file pointing at junk.
- **Q5, cost** (`probes/s05-cost.sh`, ms per call, 20 calls, ABBA order):

  | Shape | base | cand |

  | ordinary repo, depth 9 | 7.28, 7.01 | 6.71, 7.49 |

  The last row is about +130 ms: `settings.json` is now parsed again by `claudeMdExcludesSet`. That
  is constructed and far under the 15 s limit.
- **Q6, HARD_ERROR_RE** (`probes/q6-replay.mjs`, read-only over
  `/home/ai/.claude/projects/*/*.jsonl`): 189 transcripts, 40,634 Bash results (645 of them error
  strings).
  - The old and new regex differ on 7 outputs. All 7 are prose after a blank line
    (`"\n\nAt the start of …"`), which the old prefix wrongly counted as a frame.
  - The isHardError verdict changed on 0 outputs.
  - Synthetic shapes (`probes/q6-shapes.mjs`): Node 4-space, Java tab, CRLF+spaces, CRLF+tab, mixed
    tab/space, .NET, Rust backtrace, and a blank line before an indented frame all match in both.
    Only NBSP, form-feed or VT indentation, `\n\r`, and an unindented `at` after a blank line differ.
    None of these is a runtime's frame shape.
- **Q3**: I found no state where the copy is written while the host loads the current block from
