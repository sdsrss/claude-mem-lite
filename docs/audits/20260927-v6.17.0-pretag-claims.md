## MISLEADING

**M1 — CHANGELOG.md:13, README.md:84 & 250-251, README.zh-CN.md:63 & 211-212, commit 34a65cd**
"the summary is the one written at Stop from the assistant's own final report" / "written at
every Stop from the assistant's own final report (no model call)" / "…is unchanged". The Stop
extract (`hook.mjs` writeFastSummaryBaseline → `extractStructuredSummary`,
`lib/summary-extractor.mjs:57-102`) only reads a report that has **Done / Not done / Failed /
Uncertain headers**, or the 中文 equivalents. The v6.15.0 notes said so (CHANGELOG.md:105,
"when its headings are markdown (`## Done`…)"). The code comment says those headers are there
because "CLAUDE.md §10 mandates Done/Not done/Failed/Uncertain markers", and that is the
maintainer's personal spec. A user whose assistant does not write those headers gets
`Completed` from observation titles or nothing (the `titles` tag), and never gets `Next:`. For
that user the opt-in model summary was the only prose summary. This is one machine's habit
presented as general behaviour.

**M2 — CHANGELOG.md:34-35** "in the rare session the model did run, it could add `Lessons:` /
`Decisions:` lines, and those now appear only when opted in." This understates what goes away.
`lib/fast-summary.mjs:356-441`: the model worker also writes `request` and `next_steps`
(rendered `Next:` by `hook-context.mjs:944`, and `Next steps:` in the /clear handoff at
`hook-handoff.mjs:1070`). No Stop-side writer produces `next_steps`. Where the report had no
Done section, the worker also wrote `completed` (it overrides unless `prov.done === 'report'`).
The live row #495 shows exactly this. "Rare" is one machine's reading: the release session
itself was one of those sessions (see F2).

**M3 — README.md:250-251, README.md:1067, README.zh-CN.md:211 ("几乎从不调用模型")** "almost never
called the model". This rests only on the maintainer's DB: 24/24 in one window, and D#95's
"4 of 157 hook sessions held an observation", which is consistent with the D#95 ledger entry.
Two things undercut it: the same day's data at tag time (2/26, F2), and D#95's own ledger
detail ("observation ids 256-281 that day: 19 of 26 gone", so 7 of 26 survived). How many
observations survive episode classification depends on the user's work mix and the LLM's
classifications. The README is what npm users read (the tarball ships both READMEs and no
CHANGELOG, confirmed by `npm pack --dry-run`), and it gives them no stamp or population.

**M4 — CHANGELOG.md:36-37** "The `<session-summary>` tag … now names where its text came from
(`report`, `titles` or `haiku`)". `summarySourceLabel` (`lib/fast-summary.mjs:175`) labels only
the **Done** provenance. The same block also prints `Remaining:` (whose provenance is the `left`
tag, e.g. `donetitles leftreport` is a valid state per `parseSummaryNotes`) and `Next steps:`
(model-only). So a block labelled `titles` can carry report text, and when opted in, a block
labelled `report` can carry model-written next steps. Accurate wording would be "names who wrote
its Done text". The docstring gets this right; the release note does not.

**M5 — CHANGELOG.md:49** "the cached 'vX available' flag was never cleared". It was cleared at
the next successful network check. `hook-update.mjs:133-140` writes `updateAvailable:false`
when the latest release is not ahead. Commit 6494d48 says it correctly ("until the 24h throttle
expired"). The flag persisted past 24 h only when fetches failed. The fix itself is TRUE:
reverting each site separately reds its own test (banner 2 red, throttled check 1 red, re-run
by me).

**M6 — CHANGELOG.md:20 heading "Lesson ids no longer fill your replies", README.md:246-247
("which filled replies with lesson-id lists")**. The baseline is 98 of 1,890 text-only replies
(5.2%) with a dismissal. The effect after the release has **not been measured**: the baseline
doc itself says "Readout owed after the release carrying 396ae10". The shipped code comment
(`lib/citation-tracker.mjs:106-108`) says agents "still write the second form unprompted". What
changed is the request, and the note states an outcome. Lower severity than M1–M3.
