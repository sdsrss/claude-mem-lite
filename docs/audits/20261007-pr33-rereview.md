## New findings

### F1 (should-fix; we fix after merge): an IP-literal https gateway behind an HTTPS_PROXY fails on every call, leaks the tunnel socket, and doctor shows green

- Site: `lib/proxy-fetch.mjs:239`, `createConnection: () => tls.connect({ socket, servername: t.hostname })`.
- Node rejects an IP address as a TLS servername with `ERR_INVALID_ARG_VALUE` ("Setting the TLS ServerName to an IP address is not permitted"). For IPv6, `t.hostname` keeps its brackets, and the identity check fails with `ERR_TLS_CERT_ALTNAME_INVALID … Host: [::1].`.
- Reachability: `main` only ever tunnelled to fixed hostnames (api.anthropic.com, openrouter.ai, github). This PR lets `ANTHROPIC_BASE_URL` be `https://10.x.x.x:8443`-shaped. With `HTTPS_PROXY` set, `httpConnectProxyFor` tunnels it unless `NO_PROXY` lists the exact IP, and the `NO_PROXY` matcher has no CIDR support.
- Repro: `node scratchpad/pr33/ipdiag.mjs <worktree>` runs a local https gateway (cert SAN: localhost, 127.0.0.1, ::1) and a local CONNECT proxy:
  ```
  tunnel 127.0.0.1: error ERR_INVALID_ARG_VALUE … Received '127.0.0.1'   | direct fetch 127.0.0.1: status 200
  tunnel [::1]: error ERR_TLS_CERT_ALTNAME_INVALID … Host: [::1].         | direct fetch [::1]: status 200
  tunnel localhost: status 200                                             | direct fetch localhost: status 200
  ```
- Product effect, probe `ip-proxy` (`ANTHROPIC_BASE_URL=https://127.0.0.1:PORT` with `HTTPS_PROXY`): doctor says `ok`, "LLM provider: api key set, 127.0.0.1 reachable (via proxy http://127.0.0.1:45651)". The gateway log shows only the CONNECT and no request, and the call falls back to the CLI. This is the same false-green class the PR set out to remove.
- Socket leak: the CONNECT socket is never TLS-wrapped, and `finish(reject)` does not destroy it. With the gateway in a separate process (`hang-srv.mjs` + `hang-client.mjs <worktree> 127.0.0.1`), the result was "call returned after 41ms … process exit after **120041ms**". That is Node's default TLS handshake timeout on the server side. The control (`… localhost`) exits after 114 ms. In the long-lived MCP server, each such call holds a socket until the server's timeout.
- Proposed patch (also at `scratchpad/pr33/proposed-patch-proxy-ip-sni.diff`; not committed):
