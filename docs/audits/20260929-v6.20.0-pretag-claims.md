## Verdicts per claim

### Claim 1 — in git: CLAUDE.local.md at repo root, listed in .git/info/exclude, `git status` never shows it, never committed
Verdict: TRUE as literally stated (T1, T13), with gaps:
- Already-ignored file (T15): nothing is added to .git/info/exclude (`ensureExcluded` returns 'already',
  lib/local-steering.mjs:118), yet the notice (hook.mjs:2675) says "It is listed in the repository's
  .git/info/exclude". P3.
- `git status --ignored` shows `!! CLAUDE.local.md` (T1); `git add -f` would commit it. "never" holds for
  default commands only. P3.
- A user's pre-existing untracked CLAUDE.local.md is silently excluded too (T12): their own text disappears from
  `git status`/`git add -A`. Not disclosed. P3.
- NOT "kept out of what you ship": npm pack ignores .git/info/exclude -> CLAUDE.local.md (with an absolute path
  to the data dir, i.e. the username) goes into the tarball of any package without `files`/.npmignore
  (pkg test). Same for docker build contexts/archives (not tested). See P1-5.

### Claim 2 — outside git, repo rooted at $HOME, or tracked CLAUDE.local.md: nothing written, guidance injected
Verdict: TRUE (T3, T4, T5; code lib/local-steering.mjs:90-97, 151-153; also `/` and exclude-write failure).
"Nothing" = nothing in the project; the detail doc and markers go to the data dir (stated in README).

### Claim 3 — "What you need to do: nothing"; existing CLAUDE.md block synced; unadopt -> local; adopt -> CLAUDE.md + removes local
- Sync of existing block: TRUE (adopt-cli.mjs:276-289; T11).
- "What you need to do: nothing" + headline "auto-adopt no longer writes your project's CLAUDE.md"
  (CHANGELOG.md:7,19) and README "without touching anything git tracks" (README.md:170) / "never writes anything
  git tracks" (README.md:589): FALSE for every project carrying a <=6.19.4 block — i.e. every project an
  existing user opened, since 6.19.4 auto-adopted all of them. The template changed in 9aca6cc, so the FIRST
  6.20.0 session rewrites CLAUDE.md and two .claude/ files (T11). P1-1.
- unadopt -> next session writes CLAUDE.local.md: TRUE (T7, r11).
- adopt moves block to CLAUDE.md and removes the local copy + exclude lines: TRUE (T8), but a later session
  launched from a subdirectory writes the local copy again next to the CLAUDE.md block (T14). P2-3.

### Claim 4 — adopt --disable / MEM_NO_AUTO_ADOPT / unadopt [--all]
- `adopt --disable` "removes the local block": TRUE (r15 first step).
- `adopt --disable` "turns the guidance off for one project" (CHANGELOG.md:24, README.md:172):
  MISLEADING/FALSE in two shapes:
  (a) project with a CLAUDE.md block (all upgraded projects): block is kept and still loads (T9;
      adopt-cli.mjs:313-316 comment "Does NOT remove a CLAUDE.md block"). P2-1.
  (b) the opt-out sentinel is keyed by the launch cwd (memdirPath(cwd)), the file by the repo top-level:
      disable at root, then any session from a subdirectory re-creates root CLAUDE.local.md, which root
      sessions then load (r15). P1-4.
- `MEM_NO_AUTO_ADOPT=1` "turns auto-adopt off everywhere": literally TRUE, but listed under "How to turn it off"
  it is MISLEADING: existing CLAUDE.local.md files stay and keep loading, now unsynced (T10;
  lib/quiet-scope.mjs comment "MEM_NO_AUTO_ADOPT only stops new writes"). README.md:1024 says "stops the
  per-SessionStart steering ... no injected steering, and no sync" and omits it. P2-2.
- `unadopt [--all]` removes the local block and its exclude entry: TRUE at the moment it runs (T7; --all run
  removed r10's block + exclude lines). But see P1-2: the next SessionStart puts both back.

### Claim 5 — one-time notices; MEM_NO_ADOPT_HINT=1 silences both
Verdict: TRUE (T1, T3 second session silent; r10 first session with MEM_NO_ADOPT_HINT=1 had no systemMessage;
hook.mjs:2648, 2669). Markers are per inferProject() name, so each subdirectory launch of one repo gets its own
notice (T13, r15) — P3. The local notice's undo advice is the P1-2 problem. README.md:1025 (MEM_NO_ADOPT_HINT
row) lists only the /adopt offer and the Invited-memory hint, not the CLAUDE.local.md notice — P3.

### Claim 6 — subagents see CLAUDE.local.md; injected guidance never reaches subagents
Verdict: TRUE per evidence I did not reproduce: Claude Code docs (code.claude.com/docs/en/memory: "Local
instructions ./CLAUDE.local.md ... CLAUDE.md and CLAUDE.local.md files in the directory hierarchy above the
working directory are loaded at launch") and audit §8.5 (12/12 vs 0/12). Exception the texts omit: in the
session that CREATES the file, the host has already loaded instructions, so subagents in that first session do
not see it (80335a4's own message: "0/4 subagents saw steering in S1"). "subagents included"
(CHANGELOG.md:12-13, README.md:170) — P3.

### Claim 7 — supersedes retires obs and events; CLI `save --supersedes 12,E#34`
Verdict: TRUE (CLI supersede test above; tool-schemas.mjs:317-378 accepts numbers and "E#n"; events filtered by

## Findings by severity

### P1 (false statement about what gets written to users' files or how to undo it)
P1-1  Upgrade headline "auto-adopt no longer writes your project's CLAUDE.md" (CHANGELOG.md:7), "What you need to
      do: nothing" (:19), README.md:170 "without touching anything git tracks", README.md:589 "never writes
      anything git tracks" (+ zh twins). Every project auto-adopted by <=6.19.4 carries the block; 9aca6cc changed
      the template, so the first 6.20.0 session rewrites 3 tracked files (T11: M CLAUDE.md,
      M .claude/plugin_claude_mem_lite.md, M .claude/.plugin_claude_mem_lite_state.json, 21+/8-). The body
      bullet ("keeps it, synced as before") contradicts the headline. Fix: say that projects already carrying the
      block get it refreshed in CLAUDE.md on the first 6.20.0 session (commit or run unadopt), or skip the refresh.
P1-2  `unadopt` presented as removal/turn-off: CHANGELOG.md:24-26 lists "`unadopt [--all]` removes the local block
      and its exclude entry" under "How to turn it off"; the one-time notice (hook.mjs:2675-2676) says
      "`claude-mem-lite unadopt` removes it". Next SessionStart silently re-creates the file and exclude lines
      (T7; no notice, marker already set). commands/unadopt.md already says "this does not stop auto-adopt";
      README.md:551 "(runtime marker stays to honor the explicit removal)" is false — the .auto-adopt- marker
      gates nothing (hasAutoAdoptMarker has no production caller; pre-existing line, zh README:459 same).
P1-3  README.md:595-596 "A block you remove by hand is not written back" (zh same): hand-deleted CLAUDE.local.md is
      re-created (r10); a hand-removed CLAUDE.md block is replaced by a CLAUDE.local.md (r11).
P1-4  `adopt --disable` "turns the guidance off for one project and removes the local block": the sentinel is per
      launch cwd, the file per repo; disable at root, then a session from a subdirectory re-creates root
      CLAUDE.local.md, which root sessions load (r15).
P1-5  (borderline: undisclosed consequence rather than a literally false sentence) "What you need to do: nothing"
      / "kept out of commits": the file is invisible to git but not to npm — `npm pack --dry-run` includes
      "2.0kB CLAUDE.local.md" in a package without `files` (pkg test); its text carries the absolute data-dir path
      (username). Because git status is clean, nothing warns the user.

### P2 (false or overstated claim users or the model will act on)
P2-1  `adopt --disable` "turns the guidance off" (CHANGELOG.md:24, README.md:172) — a CLAUDE.md block (all upgraded
      projects) stays and keeps loading (T9).
P2-2  `MEM_NO_AUTO_ADOPT=1` under "How to turn it off" (CHANGELOG.md:25) and README.md:1024 row — existing
      CLAUDE.local.md files stay loaded and stop being synced (T10).
P2-3  Subdirectory launch of a repo whose root carries the CLAUDE.md block writes root CLAUDE.local.md as well
      (T14): both blocks load (host loads ancestor CLAUDE.md and CLAUDE.local.md at launch); a later root session
      deletes the local copy, a subdir session re-writes it. Contradicts README.md:172 "gets no local or injected
      copy on top of it" and the `adopt` "removes the local copy" claim. (hasBlock checks cwd/CLAUDE.md,
      adopt-cli.mjs:261; the local file goes to the git top-level.)
P2-4  LLM-facing steering (adopt-content.mjs:54 block row; detail doc adopt-content.mjs:104 "#NN 是 agent 主动保存
      的笔记，更可靠") and CHANGELOG.md:40 "Automatic session summaries (E# ids)": #NN rows are NOT only saved notes.
      Background summaries of type `change` persist as observations (#NN) (hook-llm.mjs persistHaikuSummary
      fallthrough ~547-560), and the foreground rule-based pre-save of every significant episode is an
      observation (#NN) until/unless the LLM re-types it into an event (hook-llm.mjs saveEpisodeImmediate ~751-757).
      E# rows can also be manual (`activity save`).
P2-5  LLM-visible /adopt and /unadopt command text not updated on the branch (`git diff main..80335a4 -- commands`
      is empty): commands/adopt.md description "Runs automatically on SessionStart; use this to force it now" and
      body "This normally runs automatically on every SessionStart" — false now (auto path writes CLAUDE.local.md
      or injects; /adopt writes a normally-committed CLAUDE.md). commands/unadopt.md never mentions
      CLAUDE.local.md, and its "Aftermath ... returns to verbose mode" is false (isAdoptedHere stays true via
      isSteeringInjectedHere unless disabled, lib/quiet-scope.mjs).
