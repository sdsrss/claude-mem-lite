### A20260906-R8-P1-1 — 五处人工修复指引打印的是一条实测空转的命令

- **位置+证据**：`lib/binding-probe.mjs:16` 定义 `NATIVE_BINDING_REBUILD_CMD =
  'npm rebuild better-sqlite3 --dangerously-allow-all-scripts'`，其上注释写

  "**THE npm-REBUILD PATH ABOVE CANNOT HEAL v13 AT ALL**"。两段互相矛盾，后者是对的。
  该常量作为**用户可见的手动修复指引**出现在：`install.mjs:624`（硬编码字面量，**没有引用常量**）、

- **沙箱复现**（npm 12.0.2，`mktemp -d`，两种 prebuild 状态各一次）：

  npx -y npm@12 rebuild better-sqlite3 --dangerously-allow-all-scripts

- **复发认定**：`CHANGELOG.md:6496` 记着同一缺陷类的上一次——旧指引 `--build-from-source`
  "on npm ≥ 12 hits the same script block and exits 0 without compiling"，当时改成了现在这条。
  那次修复对 better-sqlite3 **12** 是对的，v4.0.0 换依赖后失效。**修复没错，是依赖变了没人回头看。**
- **最小修复**：人工指引改为打印两条（先 npm rebuild，失败则 source build），或直接改为指向
  `claude-mem-lite rebuild-binding`（它跑的就是完整三步链）。同时把 `install.mjs:624` 的硬编码
  字面量换成常量引用，并修正 16 行那句已经不成立的注释。
- **验收标准**：一个守卫断言"任何用户可见的 binding 修复指引都不得只包含 `npm rebuild` 那条"；
  变异验证 = 把任一指引改回单条 npm rebuild，用例必须变红。

### A20260906-R8-P2-3 — `existsSync` 看不见悬空符号链接，于是重装修不好被它挡住的 CLI 链接

- **位置+证据**：`install.mjs:665` `if (existsSync(cliLink)) unlinkSync(cliLink);` 紧接 `666`
  `symlinkSync(cliSource, cliLink)`；`672`/`673` 是 `/usr/local/bin` 的同一形状。
  `install.mjs:1548`（`uninstall` 删 CLI 链接）同样用 `existsSync`。
  同一文件 **434 行**的 `isDevInstall()` 用的是正确写法
  `existsSync(serverPath) && lstatSync(serverPath).isSymbolicLink()`——**不是不知道，是漏了**。
- **沙箱复现**：`ln -s <不存在的目标> link` 后，`existsSync(link) === false`，
  `lstatSync(link).isSymbolicLink() === true`。
- **影响**：`INSTALL_DIR = DATA_DIR = ~/.claude-mem-lite`。当该目录被 `uninstall --purge` 或手工
  删除后，`~/.local/bin/claude-mem-lite` 成为悬空链接。此后：① `uninstall` 的 1548 行看不见它，
  留下一个坏命令在 PATH 上；② 更糟的是 665 行——重装时 `existsSync` 为 false 于是不 unlink，
  `symlinkSync` 抛 `EEXIST`，落进 catch 去试 `/usr/local/bin`（通常不可写）再失败，最终只打印
  "CLI symlink failed — run manually"。**文档指引的修复手段（重新 install）修不好这个状态。**
- **最小修复**：把 `existsSync(p)` 换成"存在或为链接"的判定
  （`try { lstatSync(p); unlinkSync(p); } catch {}`）。517/526/533/540 四处 dev-install 链接是同一形状，
  一并改。
- **验收标准**：用例先造悬空链接再调创建路径，断言链接被换成有效链接；变异验证 = 改回
  `existsSync` 时用例变红。
- **改动风险**：低。**前置依赖**：无。

### 11.4 方法论

**两轮评审都找到了实施方看不到的东西，而且都是"守卫看起来在守、实际上守不住"这一类。**
共同机制：写守卫的人按**自己刚写的那种写法**去构造反例，于是只覆盖了自己想得到的回退形状。
评审按**改回原样**去构造，那才是真实的回归形状。下次自己写结构守卫时，反例应当取自
`git show <改动前的 sha>` 的原文，而不是手打一个"差不多"的版本。
