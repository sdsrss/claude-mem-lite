## P3-1: Key Context booking still fails when a tag's attribute tail spans lines; the "idempotent" comment is false

`hook-context.mjs:713-717` (the comment says "Idempotent with the block-level pass") and
`format-utils.mjs:115-116` (`CONTEXT_DELIMITER_RE` … `(?:\s[^>]*)?>`).

The attribute tail `\s[^>]*` matches newlines. The block-level pass at `hook-context.mjs:929`
runs over the whole joined body, so an opening tag name followed by a space, with no `>` on
its own line, matches forward to the next `>` anywhere later in the body, including a `>`
inside another row. The per-row `bookedLine` defang sees only its own line, so it finds no
match. The two results differ and `idsShownWhole` rejects both rows.

Repro (a scratch script that calls `buildSessionContextLines` and `idsShownWhole` directly,
with `HOME` and `CLAUDE_PROJECT_DIR` pointed at an unadopted temp dir; the script has been
deleted). It uses three bugfix rows at importance 2:

- A: title `Handle the <system-reminder block in hooks`
- B: lesson `map a -> b before c`
- C: a plain row

```
span    quiet= false rendered= [ 1, 2, 3 ] booked= [ 3 ]
- [bugfix] Handle the system-reminder block in hooks (#1) — strip it before the cap
- [bugfix] Arrow mapping order (#2) — map a - b before c        <- B's '>' was deleted
| #1 | 14:53 | 🔴 | Handle the <system-reminder block in hooks |   <- Recent row keeps a live '<system-reminder '
control rendered= [ 1, 2, 3 ] booked= [ 1, 2, 3 ]              (same rows with the tag removed)
```

Failure scenario: rows A and B are both rendered and both missing from the Key Context
marker. They are re-injected at prompt time and get no citation credit at Stop, which is the
exact symptom D#115 P3-1 set out to fix. B carries no tag at all, so the damage reaches an
innocent neighbour. `->`, `=>`, `>=` and `Array<T>` are common in lesson text.

Second input that breaks the same claim: when any row nests a forged tag deeper than 32
layers, `defangToFixpoint` falls back to `text.replace(/[<>]/g,'')` on the WHOLE body.
Every other row containing a plain `<` or `>` then fails to match its per-line copy and is
not booked.

Already in 6.17.0, not introduced by 22072c8:

- the deleted `>` in row B's display text;
- the Recent table keeping `<system-reminder block in hooks |` un-defanged. The caller
  appends `\n</claude-mem-context>`, which supplies a closing `>`, so the full injected
  block contains a match of `CONTEXT_DELIMITER_RE`.

The root cause is the same in both halves: the attribute tail crosses newlines. A candidate
fix is `(?:[ \t][^>\n]*)?>`, or defanging per row before the join. Either is a
security-surface change, so it needs its own review.

Live population: 0 of 173 rows carry any tag (per the commit), so the reach today is zero.
