## FALSE and MISLEADING, with proposed wording

FALSE
1. **P5 — what fixed the CI timing budget.** Subject of 853e28e, the isB64Code comment, and the CHANGELOG perf bullet credit the char-code rewrite. Measured under coverage: char-code rewrite alone 5.66-5.87x (41b9659: 5.42-5.84x); the stop-before-BEGIN line alone 2.07-2.18x.
   - Comment: "A BEGIN line under a key header ends the scan before it is read: the scanners visit every BEGIN on every pass of the fixed-point loop, and reading each following BEGIN line whole put the many-BEGINs linearity shape past its 10x budget under coverage on CI (the CI run on the v6.19.2 release commit). Character classes are also tested by code; that alone measured no change."
   - CHANGELOG: "The cut-off private-key scanner stops at the next BEGIN line instead of reading it; under coverage instrumentation it was over a CI timing budget. The output is unchanged."
2. **K4 — "every line of every key format is a run of 16+ base64 characters"** (6575aba body, secret-scrub.mjs comment, CHANGELOG). The last line of every PEM/OpenSSH body is a remainder of any length, encrypted PEM has `Proc-Type: 4,ENCRYPTED` and a blank line, PGP ends with `=XXXX`.
   - "Every key body holds at least one such run: a full line is 64 characters in PEM and PGP and 70 in OpenSSH, and the smallest key (Ed25519) is one full line. So a body with no such run holds no key."
   - CHANGELOG: "Every key has a line of at least 64 such characters, so a key in any line shape still goes whole."
3. **H4 — "Nothing reached stderr"** (857bc15 body, e2e test comment). Pre-fix hook printed `[ERROR] session-start: sdk_sessions invariant: ...` on stderr at every session-start and user-prompt, and `stats` counted it. -> "Claude Code showed nothing: the error went to the hook's stderr (exit 0) and to runtime/hook-errors, which only `stats` reads."
4. **R6 — "an active session row started now"** (c6b1ebb body, mem-cli.mjs comment). Restore passes `now: new Date(createdEpoch)`, so the row starts at the first restored row's created_at. -> "an active session row dated to the first restored row".

MISLEADING
5. **K13 — "keeps what is between them" / "has words in it" / the Known limit.** Text between markers with no space or tab also still goes (compact JSON `{"begin":"<BEGIN>","end":"<END>"}`, `("<BEGIN>","<END>")`, `awk '/<BEGIN>/,/<END>/'`). -> "A block now stays when the text between its markers has a space or tab between two other characters and no run of 16 base64 characters. Release commit bullet: "... with no key line and a space between them keep the text."
