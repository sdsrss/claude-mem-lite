Mechanism (npm's own source):

- `@npmcli/arborist/lib/shrinkwrap.js:131-152` (`assertNoNewer`) trusts the hidden lockfile when no package *directory* is newer than it.
- Lockfile entries carry no `gypfile`, so `arborist/rebuild.js:273` (`gypfile !== false && … isNodeGypPackage`) synthesizes `node-gyp rebuild`. Its `clean` step deletes `build/`.
- When the hidden lockfile is stale or missing, npm reads the real `package.json`, which has `"gypfile": false`, and nothing runs.

Real shape: **both directions are real.**

- **Claim holds (real shape, re-measured):** `$W/plugin-shape` is the plugin-cache shape (`npm install --omit=dev` with the lockfile, as in setup.sh). I ran `build-release` there, then truncated the compiled addon (loading it now SIGBUSes). `npm rebuild … --dangerously-allow-all-scripts` left it. A compile recreates `build/`, so the hidden lockfile goes stale.
- **Claim fails:** when a later `npm install` refreshes the hidden lockfile after the compile, and the addon dies afterwards. I constructed this by writing the file directly.
- **Effect:** benign. The new repair runs before any npm step either way, and the error runs in the "npm rebuild sometimes heals" direction.
- **v6.35.4:** npm behaves the same. Under 13.0.3 the shape does not shadow anything, because the prebuild loads first.

## Informational

**I1 · the mechanism behind two "measured and unexplained" items in findings.md:120-126 (outside the range).**

findings.md lists two unexplained observations:
- the install-scripts report "flips … when `prebuilds/` alone is deleted";
- "`npm rebuild` compiles nothing even in the state where npm says the script exists".

Both follow from C1's mechanism. npm synthesizes `node-gyp rebuild` from the node's package data, which comes from a lockfile entry (no `gypfile`) only while `node_modules/.package-lock.json` is newer than every package directory. Deleting `prebuilds/`, or creating `build/`, changes the package directory's mtime. npm then reads the real `package.json`, whose `"gypfile": false` suppresses the script. V5, V6 and V7 in C1 isolate this.

Corollary: the shipped comments saying `npm rebuild` "has nothing to run" on 13 (lib/binding-probe.mjs:24-28, scripts/setup.sh:335-336) are state-dependent in the same way.
