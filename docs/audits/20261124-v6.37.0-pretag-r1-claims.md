## Findings

### F1 (P2): "newest first" holds only inside the observations table. Event-table lessons still come after observation lessons, and on Read they are dropped.

Quotes:
- `CHANGELOG.md:5` "PreToolUse recall shows the newest lesson for a file first"
- `CHANGELOG.md:10-11` "When several lessons match the file being read or edited, PreToolUse recall now shows the newest first. Until now it ranked them by citation history first…"
- `README.md:244`, `:248`, `:1314` ("the newest lesson comes first")
- `README.zh-CN.md:206`, `:208`, `:968`
- `scripts/pre-tool-recall.js:275` "the lessons matching one file come newest first"

What is true: the change reorders only the `observations` SELECT. Event rows come from a second SELECT (`:884-905`, already `created_at_epoch DESC`, never cite-ranked). The merge is `[...rows(obs), ...eventRows]` sliced to `mergeCap` (`:919-935`). So every observation lesson outranks every event lesson regardless of write time, and on Read (cap 1) a newer event lesson is never shown while any observation lesson matches. The "until now ranked by citation history" half is also false for event rows: they never were.

Evidence (candidate hook, sandbox DB: two observation lessons written 50 and 40 days ago, one event lesson written 1 minute ago, same file):
```
--- Read
  #2 [bugfix] OBS lesson written 40 days ago
--- Edit
  #2 [bugfix] OBS lesson written 40 days ago
  #1 [bugfix] OBS lesson written 50 days ago
  E#1 [lesson] EVENT lesson written 1 minute ago
```
Size of the population:
- Live store, read-only, read 2026-11-24 before 22:02Z, 60-day window, importance ≥ 2, live rows: **663** observation lessons with file edges vs **3,444** events with a body and `file_paths`.
- Metrics 2026-11-05..11-24: 3,166 `pretool_recall` firings, of which **943 of 3,450 injected rows (27.3%) were event rows**, 842 firings were events-only, and 47 mixed both.

The headline describes the observations arm, not "the lessons" the block shows. The `E#` rows render under the same `[mem] Lessons for <file>:` header.

### F2 (P2): the shipped detail doc still says citing raises a lesson in PreToolUse recall

Quote, `adopt-content.mjs:95` (written into every adopted project's `.claude/plugin_claude_mem_lite.md`; this repo's copy is `.claude/plugin_claude_mem_lite.md:25`):
> 系统按会话追踪引用：被引用的 lesson 在召回排序里上浮，被注入却未引用的下沉（有界的排序乘数）

In English: the system tracks citations per session; cited lessons float up in the recall ranking and lessons injected but not cited sink (a bounded ranking multiplier).

It sits under `## 被动 recall`, whose lead line (`:85`) scopes the section to the PreToolUse hook. Since D#949 the cite factor in that face's ORDER BY is a same-millisecond tiebreak (`scripts/pre-tool-recall.js:797-801`): a cited lesson no longer rises, and an uncited one no longer sinks, in the recall this section describes. The sentence stays true for UPS and search. The release did not touch this text, and this is LLM-visible steering metadata.
